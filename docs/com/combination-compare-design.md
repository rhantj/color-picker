# 조합 비교 화면 — 방향 결정

- 날짜: 2026-09-06
- 상태: **방향만 정함. 구현 안 함.**
- 관련: `docs/session-resume/2026-09-01-session-summary.md` 의 "새 방향 후보"

## 무엇을 만들려는 것인가

두 조합을 나란히 놓고 **면적 비율을 바꿔 가며** 비교한다. 이 사이트의 논지가 "같은 두 헥스도
비율이 바뀌면 다른 색이 된다" 이므로, 비교는 정지된 두 스와치를 옆에 두는 것으로는 부족하다 —
**비율을 움직일 수 있어야 비교가 성립한다.**

## 결정 — 슬라이드로 비교한다

정적 나란히 놓기가 아니라 **슬라이더로 면적을 움직이며 비교**한다.

이미 있는 것을 그대로 쓴다. `public/ui.js` 의 `ratioControl` 이 그 슬라이더이고, 홈의 결과 카드와
저장 화면이 둘 다 쓰고 있다. `{ node, set }` 을 돌려주고 `onInput`(끌 때)·`onCommit`(손 뗄 때)을
나눠 받으므로, 비교 화면은 **하나의 슬라이더가 두 조합의 `swatchView` 를 함께 갱신**하게 붙이면 된다.

```
[슬라이더 하나] ──onInput──> 조합 A swatchView.set(next)
                └──────────> 조합 B swatchView.set(next)
```

같은 비율에서 두 조합이 어떻게 달라지는지가 이 화면의 답이다. 조합마다 슬라이더를 따로 두면
비율이 어긋난 채 비교하게 되어 무엇 때문에 달라 보이는지 알 수 없다.

## 결정하지 않은 것

- **어느 화면에 두는가** — `/saved` 안인지 새 경로(`/compare`)인지.
- **무엇을 비교 대상으로 고르는가** — 저장한 조합끼리인지, 검색 결과끼리인지, 섞을 수 있는지.
- **세 개 이상 비교** — 지금 코퍼스가 2색 조합만 담으므로(S1-G1 이 강제) 화면도 둘로 시작하는
  것이 자연스럽지만, 확장 여지는 열어 둔다.
- **저장 여부** — 비교 상태를 저장할지, 휘발로 둘지.

## 버린 대안

**정적 나란히 놓기.** 두 조합을 기본 비율로 옆에 두기만 하면 지금 `/saved` 목록에서 위아래로
보는 것과 다를 바가 없다. 비율이 색을 바꾼다는 이 사이트의 주장을 화면이 만질 수 있게 만드는
자리가 하나 더 생기는 것이 이 기능의 값이다.

**조합마다 슬라이더 하나씩.** 자유도는 높지만 비교의 기준선이 사라진다. 필요해지면 "각자 조정"
토글을 나중에 얹는 편이 낫다 — 기본은 하나로 묶는 것.
