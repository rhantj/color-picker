# 검색 3단계 — 하이브리드 (BM25 + 임베딩 결합) 설계

- 날짜: 2026-09-13
- 상태: 구현됨 (26단계, 2026-09-13). 구현 중 실측으로 바뀐 값은 본문에 `[실측]` 으로 표시
- 근거 문서: `docs/com/rag-is-simpler-than-you-think.md` 의 3단계. 그 문서가 "실측이 요구할 때 올린다"
  고 했고, 아래 실측이 요구했다.

## 무엇이 안 되나

코퍼스 어휘와 겹치지 않는 질의 18건을 지금의 1·2단계에 넣었다 `[실측]`.

| 결과 | 수 | 쉽게 말하면 |
|---|---|---|
| 정답 | 7 | 이미 잘 잡는다 |
| **거짓 확신** | **9** | 1단계가 "색"·"브랜드"·"같아요" 같은 흔한 어절 하나로 확신해 엉뚱한 답을 내고 LLM 을 안 부른다 |
| 저신뢰 → 2단계 실패 | 2 | 재작성어가 코퍼스 어휘와 안 맞았다 |

틀린 11건 중 9건은 "3단계가 없어서" 가 아니라 **1단계가 틀린 답을 확신해서**다. 그래서 이 단계는
3단계를 붙이는 것과 거짓 확신을 거두는 것을 **함께** 한다(대표 결정).

## 임베딩 실측 (`bge-m3`, Ollama `/api/embed`)

| 무엇 | 결과 `[실측]` |
|---|---|
| 순위 품질 | 23건(실측 18 + `S1-G2` 5) 에서 임베딩만으로 top1 **17**, top3 19, 팔레트↔진단 라우팅 22 |
| 색인 문장 | 팔레트는 **요약(이름·요약·인상·태그)** 이 전체 색인 문장보다 낫다 — top1 17 vs 13. 진단은 네 변형이 모두 7/10 로 같아 **증상·별칭·처방**을 쓴다 |
| 지연 | 따뜻한 상태 **45ms 안팎**, 간헐적 **2.2초** 튐. GPU 8GB 에 exaone 5.2GB + bge-m3 0.7GB 가 같이 올라가 있고(7.1GB 사용) 서로 밀어내지는 않는다 |
| 코퍼스 벡터화 | 34건 따뜻할 때 0.5초, 처음 적재 때 7초 |
| 못 고치는 것 | 진단 3건은 어휘 부재다 — "죽어 보여요" 는 별칭에 없고, "색이 서로 싸워요" 는 `dx-mismatch` 도 맞는 답이다 |

생성 모델(exaone·qwen-coder)은 이 Ollama 가 임베딩을 안 내준다. `bge-m3` 는 대표 허락 아래 내려받았다(약 1.2GB).

## 버린 대안

| 대안 | 왜 버렸나 |
|---|---|
| B. 문서 순서 그대로(1→2→3), 거짓 확신은 BM25 규칙만 강화 | 규칙이 휴리스틱이라 또 뚫린다. 느린 LLM(수 초)이 빠른 임베딩(수십 ms)보다 먼저 돈다 |
| C. 임베딩으로 BM25 대체 | 색 이름·헥스 같은 정확 매칭을 잃는다. 문서 취지("전문 검색이 과소평가")와 반대 |
| exaone 으로 LLM 재순위(내려받기 없음) | 질의당 3~8초, 답이 매번 달라 결정적 게이트를 못 만든다 |
| 코퍼스 벡터 캐시(`var/`) | 따뜻할 때 0.5초라 YAGNI. 필요가 생기면 그때 |

## 데이터 흐름

**바뀌기 전**: 질의 → BM25 → 어절 하나라도 통째로 겹치면 확신(1단계) → 아니면 LLM 재작성(2단계).

**바뀐 뒤**: 서버가 뜰 때 코퍼스 34건을 벡터화해 메모리에 둔다(비동기, 준비 전엔 지금처럼 동작).
질의마다 BM25 와 **질의 벡터↔34건 코사인**을 둘 다 본다.

| 단계 | 언제 | 무엇 | 쉽게 말하면 |
|---|---|---|---|
| 1 | BM25 확신 **그리고** 그 문서가 임베딩 상위 K 안 | 지금과 같음 | 두 방법이 같은 답이면 믿는다 |
| **3** | BM25 저신뢰이거나 임베딩과 어긋남 | 34건을 BM25 순위 + 코사인 순위로 결합 재순위(RRF). 1위 코사인이 문턱 이상이면 확신 | 흔한 어절 하나로 우기던 것을 임베딩이 거른다. LLM 안 부름 |
| 2 | 3단계도 저신뢰 | LLM 재작성 → 재작성어로 **다시 3단계** | 가장 느린 것을 마지막에 |

- 실행 순서는 1→3→2. 사다리 번호는 문서의 비용 사다리 그대로 두고, 응답의 `stage` 는 **가장 높이 쓴 칸**이다.
- 라우팅(팔레트/진단)은 결합 1위가 속한 코퍼스.
- 문턱(코사인 최소값 `COS_MIN` · 동의 범위 `AGREE_TOP`)은 상수로 두되 **값은 게이트 실측으로 정하고 `[실측]` 태그를 붙인다.**
  관측: 정답 1위 0.44~0.74, 오답 1위 0.38~0.53.
- 1단계 경로의 임베딩은 **짧은 예산(0.7초)** 으로 부르고, 넘기면 BM25 답을 그대로 쓴다. `S3-G8` 의 "확신 검색은 1초 미만" 안에 들어야 하므로 1초보다 짧다(처음 1.5초로 적었다가 G4 가 잡았다).
- 동의 범위는 **1위끼리 같아야** 한다(`AGREE_TOP = 1`). 상위 3 으로 두면 거짓 확신 3건이 남는다 `[실측]`.
- 2단계 뒤의 재검색은 BM25 에 `원 질의 + 재작성어`, 임베딩은 이미 구한 원 질의 벡터를 쓴다(다시 안 부른다).

## 파일

| 파일 | 무엇 |
|---|---|
| `src/embed.js` (새) | `/api/embed` 호출 · 코퍼스 벡터 준비 `prepare()` · 질의 벡터 · 코사인. 상태(`unknown`/`ready`/`unavailable`)와 모델명. `OLLAMA_EMBED_MODEL`(기본 `bge-m3`) · `EMBED_TIMEOUT_MS` |
| `src/hybrid.js` (새) | 결합 재순위(RRF) · 확신 판정 · 라우팅. **순수 함수** — Ollama 없이 검증 |
| `src/pipeline.js` | 1→3→2 흐름. 응답에 `hybrid: {model, cosine, elapsedMs} \| null` |
| `src/palettes.js` · `src/diagnostics.js` | 임베딩용 문장 함수 추가. BM25 색인 문장은 그대로 |
| `server.js` | 기동 시 `prepare()`(워밍업 자리, 기다리지 않음) · `/api/status` 에 `embed` 상태 · `maxStage` 3 · `hybridError` 는 루프백 밖에서 원문 숨김 |
| `public/app.js` · `public/history.js` | 3단계 문구·배지 · 사다리 3칸 · 시간 줄에 임베딩 ms · **LLM 횟수는 재작성 기록으로 센다** |

## 오류 처리

던지지 않는다. 모델 없음 · Ollama 죽음 · 타임아웃 · 준비 중은 전부 "3단계 건너뜀" 이고 결과는 지금의
1·2단계와 같다. `hybridError` 를 응답에 남기되 `rewriteError` 와 같은 경계를 적용한다.

## 게이트 (26단계, 검사기가 구현보다 먼저)

| 게이트 | 쉽게 말하면 |
|---|---|
| G1 | 실측 질의 23건 픽스처. 정답 수가 7 보다 늘고 **거짓 확신 9건이 1단계에 안 남는다.** 어휘 부재 3건은 "못 잡는 게 맞다" 로 표시. 양성 대조: 두 방법이 같은 답이면 1단계 그대로. 실제 `bge-m3` 필요(`S3-G3` 와 같은 전제) |
| G2 | `S1-G2` 다섯 건이 여전히 1단계·같은 답 |
| G3 | 임베딩이 없으면(모델 없음 · 죽은 호스트) 1·2단계가 그대로 돈다 · 상태가 `unavailable` 로 정직 |
| G4 | 느린 가짜 임베딩(3초)에서도 확신 검색이 1초 안에 답한다 |
| G5 | `hybrid.js` 결합·문턱을 스텁 벡터로 결정적 검증(감시 값 사본) |
| G6 | 루프백 밖에서 `hybridError` 원문이 안 샌다 |
| G7 | 화면 — 3단계 배지 · 사다리 · LLM 횟수가 재작성 기록 기준 (정적 검사) |
| 회귀 | S1 · S2 · S3 · S4 · S7 전체 |

## 되돌리는 법

`pipeline.js` 에서 3단계 분기를 빼고 `embed.js`·`hybrid.js` 를 지우면 이전 흐름이다. `bge-m3` 는
`ollama rm bge-m3` 로 지운다. 코퍼스 데이터와 BM25 색인은 건드리지 않는다.
