# 2026-09-01 — 4단계: 상태 저장 + 진단 코퍼스 확장

[3단계 문서](2026-09-01-stage3-intent-routing.md) 다음. 초안의 네 화면이 다 찼다.

## 1. 진단 코퍼스 10건 → 18건

### 왜

3단계 끝에 "답답해" 가 진단표에 없는 증상이라 가장 가까운 "요란하다" 로 갔다. 코퍼스를 늘릴지
"해당 없음" 을 만들지 정해야 했고, 늘리기로 했다.

### 조건 — 처방을 지어내지 않는다

새 8건은 전부 color-design 스킬 **본문에 실제로 적힌 문장**에서 왔고, 각 항목에 `source` 를 박았다.
`defaultRatio` 때와 같은 함정이다 — 지어낸 조언은 틀려도 티가 안 난다.

| 새 항목 | source |
|---|---|
| 답답하다 / 갑갑하다 | 팔레트 해설 ⑬ "수축하는 성질 … 답답함으로 넘어간다" |
| 글씨가 안 읽힌다 | 매체별 적용 "가독성은 명도가 좌우한다" |
| 강조가 안 보인다 | 규칙 "나머지를 탁하게 눌러야 하나가 산다" |
| 색들이 서로 안 어울린다 | 1절 "두 축을 따로 찍는다" |
| 복사했는데 느낌이 안 난다 | 마지막 절 "면적과 순서는 복사되지 않는다" |
| 어느 색부터 정할지 모르겠다 | 0절 "색상부터 고르지 않는다" |
| 차분하게 만들고 싶다 | 1절 유사색대비 / 톤인톤 |
| 강렬하게 만들고 싶다 | 1절 보색대비 / 규칙 1 |

### 늘리자 라우팅 결함이 드러났다

8건을 넣었는데도 4개 질의가 팔레트로 샜다. 원인이 전부 같았다 —

| 질의 | 팔레트 근거 | 진단 근거 |
|---|---|---|
| 글씨가 잘 안 읽혀요 | `잘` 1개 | `글씨가 안` 2개 |
| 색들이 서로 안 어울려요 | `안` 1개 | `서로 색들이 안` 3개 |
| 레퍼런스 헥스를 복사했는데 느낌이 안 나요 | `느낌이` 1개 | 5개 |
| 차분하게 만들고 싶어요 | `만들고` 1개 | `차분하게 만들고` 2개 |

**"팔레트를 먼저 보고, 걸리기만 하면 이긴다" 는 규칙이 너무 거칠었다.** 둘 다 걸리면 어절 전체로
겹친 항이 **더 많은 쪽**을 택하고, 동점이면 팔레트로 바꿨다(동점 규칙은 "탁하지 않은 따뜻한 색"
같은 탐색 질의를 진단으로 보내지 않기 위해서다). 한 글자 부사·부정어(`잘`·`안`·`못` …)도
기능어에 추가했다.

13개 질의 전부 올바르게 갈린다.

## 2. 4단계 — 쓰기가 처음 들어왔다

지금까지 읽기 전용이었으므로 규칙을 먼저 정하고 시작했다.

| 규칙 | 왜 |
|---|---|
| **클라이언트가 보낸 색을 믿지 않는다** | 저장 요청은 `paletteId`·메모·원 질의만 받고 색·헥스·유형·비율은 서버가 코퍼스에서 찾는다. 화면이 보낸 색을 저장하면 저장소가 코퍼스와 어긋나기 시작한다 |
| 원자적 쓰기 | 임시 파일 + rename. 중간에 죽어도 반쪽 파일이 안 남는다 |
| 직렬화 | 프로미스 체인 하나로 묶어 동시 쓰기가 서로를 덮지 않게 |
| 상한 | 대화 50 · 턴 100 · 저장 200 · 질의 500자 · 메모 200자 |

**대화 기록은 화면이 명시적으로 POST 한다.** 검색(GET)이 부수효과로 쓰면 게이트 실행과 새로고침까지
내역에 쌓인다.

| 파일 | 무엇 |
|---|---|
| `src/store.js` | JSON 파일 두 개. 원자적 쓰기·직렬화·상한·검증 |
| `server.js` | POST 처리, 본문 8KB 상한, CSRF 가드, `/history`·`/saved` 경로 |
| `public/ui.js` | 세 화면 공용 렌더 조각 |
| `public/history.{html,js}` | 대화 내역 |
| `public/saved.{html,js}` | 추천 받은 조합 |

저장 위치는 `var/` 이고 `TONEFIRST_DATA_DIR` 로 갈아끼울 수 있다 — 검사가 사용자 데이터를
오염시키지 않게 하기 위한 것이다.

## 지금 상태

게이트 **28개 전부 통과** (S1 4 + S2 7 + S3 10 + S4 7).

브라우저 실측: 팔레트 검색 → 저장 → 진단 검색이 한 대화로 이어지고, 저장 카드가 70/30 비율을
그대로 들고 있으며(293.5px : 125.8px), 세 화면 모두 가로 넘침·콘솔 오류 없음.

## 보안 리뷰 (격리 복사본)

Critical 0 / High 0 / Medium 2 / Low 3 + 게이트 공백 4개. 전부 반영:

| 지적 | 조치 |
|---|---|
| **[Medium] CSRF 방어 전무.** `content-type` 검사조차 없어, 사용자가 이 서버를 띄운 채 아무 페이지나 열면 그 페이지가 `text/plain` simple request 로 기록을 오염시키거나 저장을 지울 수 있다 | `application/json` 을 요구(프리플라이트를 유발해 교차 출처가 닿지 못함) + `Sec-Fetch-Site` 가 있으면 same-origin/none 만. **S4-G7 신설** |
| [Medium] 진단 별칭 2건 중복(`눈아프다`, `따로논다`) — 어느 진단이 나올지 BM25 세부 점수에 좌우됨 | 더 맞는 쪽 하나에만 남김. **S4-G6 이 유일성을 검사** |
| [Low] `readJson` 이 손상 파일을 조용히 빈 배열로 대체 → 다음 쓰기가 원본을 덮어써 **로그 없이 소실** | 옆으로 치우고(`.corrupt-<시각>`) stderr 에 남긴 뒤 빈 상태로 시작 |
| [Low] `clip()` 이 UTF-16 단위라 이모지를 반으로 쪼갬 | 코드포인트 단위로 자름 |
| [Low/추정] `readBody` 가 `close` 미처리 — 조기 종료 시 프로미스가 영구 pending | `close` 에서 reject |
| 게이트 공백 (상한·메모·프로토타입 오염·별칭·CSRF) | **S4-G6·S4-G7 신설** |

리뷰가 확인해 준 것: 경로 조립 인젝션 없음, 프로토타입 오염 벡터 없음, XSS 없음(세 화면 전부
`textContent`), 정적 서빙 회귀 없음, 8KB 상한이 실제로 걸림, 쓰기 직렬화가 무한 성장·교착 없음.

### 게이트 실효성 (뮤테이션)

| 망가뜨린 것 | 잡은 게이트 |
|---|---|
| CSRF 검사 제거 | `S4-G7_FAIL text/plain POST 가 200 / 막힌 요청이 기록에 남았다` |
| 손상 파일을 조용히 버림 | `S4-G6_FAIL 깨진 파일을 옆으로 치우지 않았다` |
| `clip` 을 코드유닛 단위로 되돌림 | `S4-G6_FAIL 이모지가 온전히 저장되지 않았다: "\ud83c"` |
| 클라이언트 색을 그대로 저장 | `S4-G4_FAIL 헥스가 클라이언트 값으로 저장됐다` |
| `renameSync` 제거 | `S4-G2_FAIL 재시작 후 대화가 0개` |
| 입력 검증 제거 | `S4-G5_FAIL stage 가 99 로 저장됐다` |

## 함정 기록

- **코퍼스를 늘리자 S3-G7 이 깨졌다.** 그 게이트가 LLM 경로를 검사하려고 쓰던 질의("답답해")가
  이제 1단계에서 잡혀, LLM 이 아예 안 돌았다. 질의를 바꾸고, **앞으로 같은 일이 생기면
  "이 질의가 이제 1단계에서 잡힌다" 고 명시적으로 실패**하도록 메시지를 넣었다.
  코퍼스가 좋아질수록 LLM 경로 게이트는 검사 대상을 잃는다 — 늘릴 때마다 확인한다.
- **python 패치가 파일을 0바이트로 만들었다.** `io.open(p, "w")` 가 파일을 비운 직후
  인코딩 오류로 죽어서 빈 파일이 남았다(`scripts/check-stage4.mjs`).
  **한글·이스케이프가 섞인 큰 패치는 python 치환 대신 파일을 통째로 다시 쓴다.**
- `LIMITS.saved`(200)는 **도달 불가**다. 같은 조합을 중복 저장하지 않으므로 최대치가 코퍼스
  크기(16)다. 검사할 수 없어 게이트를 만들지 않았고 `GATES.md` 에 한계로 적었다.
