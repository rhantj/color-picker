# 2026-09-07 — 어두운 모드 토글 (15단계 후속)

앞 세션([2026-09-07-value-direction.md](2026-09-07-value-direction.md))이 엔진에 어두운 모드를
넣어 두고 **"화면·API 에 아직 안 나간다"** 로 끝냈다. 설계까지 합의했고 코드는 한 줄도 안 썼다.
이 세션이 그 설계를 그대로 구현했다.

## 바뀌기 전에는 무엇이 있었나

`src/expand.js` 의 `expandAll(seed, catalog, {mode:"dark"})` 가 어두운 팔레트를 만들 수 있었지만
**아무도 그 인자를 안 넘겼다.** `/api/expand` 는 밝은 모드만 내려보냈고 화면은 그것만 그렸다.
사용자가 "네온 사인 빛의 어두운 사이버펑크" 를 물으면 검색은 정확히 pair-06 을 찾는데
파생 여덟 장 중 일곱의 바탕이 `l=0.93` 이었다 — **"어두운" 이 산출물에 없었다.**

## 왜 이 설계인가 — 결정 다섯

| 물음 | 고른 것 | 왜 |
|---|---|---|
| 누가 모드를 정하나 | **사용자 토글** | 앞 세션에서 사용자가 골랐다 |
| 토글 범위 | **펼침 영역마다 하나** | 상태가 그 영역 클로저 안에만 있어 공유 상태가 안 생기고, 카드마다 다른 모드로 나란히 비교된다 |
| 모드를 서버에 보내나 | **안 보낸다. 두 모드를 한 번에 받는다** | `/api/expand` 는 `q` 로 LLM 을 불러 여덟 중 다섯을 고른다. 토글마다 재요청하면 **같은 질의인데 보이는 다섯이 바뀐다.** 게다가 매번 ~500ms |
| 저장에 넣나 | **안 넣는다** | 13단계가 "파생 팔레트 저장" 을 이미 미뤘고 `normalizeRatio` 가 2색 전제다 |
| `localStorage` 로 기억하나 | **안 쓴다** | 이 저장소에 전례 0건. 상태는 전부 서버 `var/` 에 있다 |

**세 번째가 이 작업의 중심이다.** 나머지 넷은 그것에서 따라 나온다.

### `structureColors` 를 왜 뺐나 — 게이트가 시켰다

처음엔 색 고르기가 `structureCard` 안에 있었고 검사가 전부 정적이었다. **`dark` 와 `light` 를
뒤바꾼 뮤테이션이 게이트 아홉을 전부 통과했다** — 토글이 정반대로 도는 결함인데 아무도 안 울었다.
카드 조립은 `el()` 이 `document` 를 써서 의존성 0 인 이 저장소에서는 정적으로밖에 못 본다.
**색 고르기만 순수 함수로 빼면 게이트가 그냥 불러서 대조한다.** 지금 S15-G13 이 다섯 경우를 직접 부른다.

앞 세션이 "어두운 모드가 이 기준을 넘길지는 재 보기 전에는 모른다. 실패하면 사람에게 묻는다" 를

## 격리 리뷰 두 건 — Critical 0 · High 1 · Medium 3 · Low 1

`~/.claude/scripts/review-fanout.sh` 로 같은 SHA(`08c47c57ed73`)에 고정된 worktree 둘을 만들고
`typescript-reviewer` 와 `code-reviewer` 를 각각 그 안에서 돌렸다. **다섯 지적을 전부 닫았다.**

## 깬 것을 하나 고쳤다 — S14-G9

카탈로그 캐시를 넣자 **다른 단계의 게이트가 실패했다.** `S14-G9` 가 조립부를
`const structureCatalog = loadStructures().map(` 라는 **호출 형태**로 찾고 있었는데,
`fullCatalog.map(` 으로 바꾸니 앵커가 안 맞았다. 투영 내용은 그대로였다.

앵커를 `[^;=]{0,60}\.map\(` 으로 넓혔다. **`server.js` 를 게이트에 맞춰 되돌리지 않았다** —
그러려면 기동 시 파일을 두 번 읽어야 하고, 그건 정규식을 만족시키려고 제품을 나쁘게 만드는 것이다.
넓힌 뒤 `detail` 을 빼는 뮤테이션으로 게이트가 여전히 무는 것을 확인했다.

## 열려 있는 것

- **저장에는 여전히 안 들어간다.** 조합을 저장하면 모드는 기억되지 않는다. 13단계가 미룬
  "파생 팔레트 저장" 과 같은 자리이고, `normalizeRatio` 가 2색 전제라 그것부터 풀어야 한다.
- **새로고침하면 밝은 모드로 돌아온다.** `localStorage` 를 안 쓰기로 한 결과다. 사용자가 매번
  누르는 것이 불편하다고 하면 그때 저장 계층을 정한다 — 지금 임의로 들이지 않는다.
- **`aerial`(공기원근)의 거울이 의미상 맞는지는 여전히 확인 안 됐다.** 이제 화면에 그려 볼 수는
  있다. 어두운 씬에서 먼 쪽이 어두운 것이 맞는지 `light.md` 가 말하지 않는다. 실제로 눈으로 보고
  판단할 자리가 생겼다는 것이 이번 변경의 부수 효과다.
- **S15-G13·G14·G15 는 절반 이상이 정적 검사다.** `api()` 대신 `XMLHttpRequest` 로 다시 부르거나,
  다른 경로로 카탈로그 파일을 읽는 구현은 못 잡는다. `GATES.md` '알려진 한계' 에 적었다.
- **파생색끼리의 대비를 보는 게이트는 여전히 없다** (앞 세션에서 이어지는 항목). 밝은 모드 243건 ·
  어두운 모드 169건이 바탕 대비 3:1 미만이다. `S15-G12` 는 스와치 **글자색** 대비를 보는 다른 것이다.

## 함정 기록

- **스크린샷은 여전히 흰 화면으로 나온다.** 앞 세션 기록 그대로다. 게다가 브라우저 창이 숨겨져
  있으면 `requestAnimationFrame` 을 기다리는 스크립트가 45초 뒤 타임아웃한다. **레이아웃·색 증거는
  `getComputedStyle` · `getBoundingClientRect` 로 남긴다.**
- **`server.js` 를 고치면 `preview_start` 를 재시작해야 한다.** `public/` 은 정적 서빙이라 바로
  반영되지만 서버 코드는 아니다. 한동안 옛 응답을 보며 디버깅했다.
- **`review-fanout.sh` 의 라운드 캐시는 세션을 넘어 산다.** `--round 1` 로 열었더니 어제 SHA 를
  집으며 거부했다. 라운드 번호를 단계 번호(16)에 맞춰 올렸다.
- **Windows 에서 Python 으로 게이트 러너를 짜면 출력이 cp949 로 죽는다.** 실패 게이트를 찍는
  순간 `UnicodeEncodeError` 가 나서 **어느 게이트가 실패했는지가 안 보인다.**
  `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` 를 먼저 부른다.
- **bash 히어독 안에 백틱·따옴표가 섞인 Python 을 넣으면 파서가 깨진다.** 스크립트는
  스크래치패드에 파일로 쓰고 `python <파일>` 로 부르는 편이 확실하다.
