# 2026-09-01 — 3단계: 의도 분기 + 질의 재작성

[Ollama 수명주기 문서](2026-09-01-ollama-lifecycle.md) 다음. 3단계의 나머지 절반이다.

## 바뀌기 전에는 무엇이 있었나

1단계에서 재작성을 **미리 재봤을 때 결과가 나빴다.** "대시보드가 탁해 보여요" 가 그럴듯한 검색어로
바뀌어 **틀린 팔레트를 자신 있게** 받았다. 저신뢰 판정이 오히려 정직했다.

원인은 재작성이 아니라 질문의 종류였다. "탁해 보인다" 는 어떤 색을 쓸지 묻는 질문이 아니라
**이미 만든 것의 원인**을 묻는 질문이다. 그런데 코퍼스에는 팔레트밖에 없었다.

## 그래서 무엇을 바꿨나

### 진단 코퍼스를 새로 만들었다

`data/diagnostics.json` — color-design 진단표 10건(증상 → 의심할 축 → 처방). 팔레트와 **색인을
분리**했다. 섞으면 "탁해 보여요" 가 팔레트 설명문의 조각과 경쟁해 둘 다 흐려진다.

각 항목에 `aliases`(같은 증상의 표면형: 탁해·탁하다·탁함·칙칙…)를 넣은 것이 핵심이다. 한국어
활용형이 제각각이라 표제어만 넣으면 어절 전체 매칭이 안 걸리고, 그러면 저신뢰로 떨어져 LLM 을
부르게 된다. 말투를 넣어 두면 **1단계에서 끝난다.**

### 단계 승급을 문서대로 구현했다

```
질의 → 팔레트 BM25 → 걸리면 끝 (LLM 안 부름)
     → 진단 BM25   → 걸리면 끝 (LLM 안 부름)
     → LLM 한 번   → 의도 분기 ┬ 팔레트 → 재검색
                              ├ 진단   → 진단표
                              └ 기타   → 못 잡음
```

의도 분류와 재작성을 **한 번의 호출**로 받는다. 따로 부르면 호출이 두 배가 되고 모델 적재를 두 번
겪는다. 라우팅 순서는 팔레트 먼저인데, "탁하지 않은 따뜻한 색" 처럼 증상 어휘가 섞인 **탐색** 질의가
있기 때문이다.

| 파일 | 무엇 |
|---|---|
| `data/diagnostics.json` | 진단 코퍼스 10건 |
| `src/diagnostics.js` | 진단 검색기 (BM25 재사용, 색인 분리) |
| `src/rewrite.js` | LLM 한 번 호출 → 의도 + 검색어. 워밍업 |
| `src/pipeline.js` | 단계 승급 오케스트레이션 |
| `src/vocabulary.js` | 붙여 쓴 재작성어를 코퍼스 어휘로 되돌림 |
| `src/stopwords.js` | 신뢰 판정에서 제외할 기능어 |
| `src/bm25.js` | `whole` 판정을 질의·문서 양쪽 + 기능어 여부로 |
| `server.js` | 파이프라인 연결, 응답에 route·rewrite·diagnostics |
| `public/*` | 진단 카드, 재작성 칩, 사다리 |

## 도중에 나온 결함 넷

### ① 내 테스트 도구가 한글을 깨뜨렸다

Git Bash 에서 `curl --data-urlencode` 로 한글 인자를 넘기면 셸이 인코딩을 망친다. 응답의 `query`
필드가 `"���� ���ε�..."` 로 왔고, 모델은 그 깨진 문자열을 받아 병원 앱 질의에 "여름네일색조합" 을
냈다. **서버 버그로 오인할 뻔했다.**

> **한글이 든 HTTP 검증은 셸/curl 로 하지 않는다. Node 에서 `encodeURIComponent` 로 보낸다.**

### ② `wholeMatches` 가 문서 쪽만 봤다

질의 `화면이` 의 2-gram 조각 `면이` 가, 문서에 어절 전체로 있던 `면이`("채도가 가장 높은 면이
하나뿐") 와 맞아 엉뚱한 진단이 고신뢰로 잡혔다. **질의와 문서 양쪽에서** 어절 전체여야 하도록 고쳤다.

### ③ 정도부사가 근거로 취급됐다

"색이 너무 요란해요" 가 `너무` 하나로 팔레트에 라우팅됐다(pair-10 의 "너무 차갑고" 와 겹침).
기능어 스톱리스트를 만들되 **점수가 아니라 신뢰 판정에만** 적용했다 — 순위 로직을 건드리면 기존
게이트가 함께 흔들린다. 목록은 짧게 유지하고 도메인 낱말은 넣지 않는다.

### ④ 모델을 믿지 않는 자리 두 곳

프롬프트에 "띄어쓰기를 붙이지 마라" 를 적었지만 지킬 것이라 가정하지 않았다. 실측에서 `톤비대칭` 으로
붙여 내면 **순위는 살아남는데 신뢰 판정이 죽는다**(whole 3 → 0) — 정답을 찾고도 "못 잡았다" 고 말하게
된다. `src/vocabulary.js` 가 코퍼스 어휘로 되돌린다: `톤비대칭 → ["톤","비대칭"]`, whole 0 → 2.

`{"intent":"other","terms":["Consider trying a quick recipe..."]}` 처럼 **의도는 맞고 검색어만
쓰레기**인 응답도 있었다. 처음엔 통째로 버렸는데, 지금은 의도만 건져도 라우팅에 쓴다.

## 지금 상태 (실측)

| 질의 | 단계 | 경로 | LLM |
|---|---|---|---|
| 병원 앱인데 차갑지 않게 | 1 | 팔레트 | 안 부름 |
| 느와르 포스터 만들건데 고급스러운 빨강 | 1 | 팔레트 | 안 부름 |
| 대시보드가 탁해 보여요 | 1 | 진단 | 안 부름 |
| 색이 너무 요란해요 | 1 | 진단 | 안 부름 |
| 화면이 유치해 보여요 | 1 | 진단 | 안 부름 |
| 만든 화면이 자꾸 답답해 보이는데 왜 그럴까요 | 2 | 진단 | 부름 |

**대부분이 1단계에서 끝난다.** 문서가 말한 "60% 는 전문 검색 + 재작성에서 종료" 와 같은 방향이다.

게이트 **21개 전부 통과** (S1 4 + S2 7 + S3 10).

## 코드 리뷰 (격리 복사본)

Critical 0 / **High 1** / Medium 3 / Low 2. 여섯 건 다 반영:

| 지적 | 조치 |
|---|---|
| **[High] `warmUp` 이 정의·import 만 되고 호출부가 없다** — 설계 의도가 통째로 무력 | 호출부 추가. **S3-G10 신설** — 서버 표준출력에서 워밍업 로그를 확인한다. 호출부를 지우면 FAIL 확인 |
| 파이프라인이 팔레트의 약한 증거는 담고 진단의 약한 증거만 버린다 | 둘 다 담는다. 무엇을 보여줄지는 route 로 화면이 판단 |
| `rewriteError` 가 `LOOPBACK_ONLY` 가드를 안 거쳐 내부 호스트·스폰 실패 상세가 샌다 | `/api/status` 와 같은 경계 적용 |
| S3-G7 이 LLM 이 실제로 돌았는지 확인하지 않아, Ollama 가 죽어도 통과한다 | `rewrite` 존재와 `stage === 2` 를 사전 조건으로 요구 |
| 어휘집에 유형 라벨("A형")에서 나온 로마자·숫자 1글자가 섞인다 | 한 글자는 한글만 받는다 (962 → 955) |
| `app.js` 주석이 "Ollama 는 아직 검색에 쓰이지 않는다" 로 낡음 | 갱신 |

리뷰가 확인해 준 것: 재작성 칩 XSS 없음(전부 `textContent`), prototype pollution 없음, 타임아웃·중단
누수 없음, `stopwords` 가 점수에 관여하지 않음이 코드와 일치, `vocabulary` 의 잘못된 분해 사례 없음,
S2-G2 갱신이 커버리지를 잃지 않음.

## 정정 기록 — 51초는 틀린 수치였다

작업 중 "모델 적재 51초를 워밍업으로 없앴다" 고 보고했는데 **두 군데가 틀렸다.**

1. **그 시점에 워밍업은 돌지 않았다.** 치환이 조용히 실패해 `import` 만 남아 있었다. 그때 관측한
   384ms 는 앞선 게이트 실행으로 모델이 메모리에 남아 있었기 때문이다.
2. **51초는 상시 값이 아니다.** 모델을 막 내려받은 직후 디스크에서 처음 읽을 때의 1회성 값이다.

모델을 내렸다 올리며 다시 잰 값:

| 조건 | 첫 저신뢰 질의 |
|---|---|
| 워밍업 끔 | **3944ms** (재작성 3932ms) |
| 워밍업 켬 | **556ms** (재작성 534ms, 워밍업 자체는 배경에서 3275ms) |

워밍업은 효과가 있다(약 7배). 다만 51초가 아니라 **3.9초 → 0.56초**다.
