## D1 — 탐지 결과를 상태에만 적고 사유에는 안 적었다

`src/ollama.js` 의 `refresh()` 는 Ollama 가 살아 있는지 확인만 하는 함수다(프로세스를 띄우지
않는다 — 요청 경로에서 부를 수 있어야 해서). 이 함수가 탐지 결과를 이렇게 다뤘다.

| 탐지 결과 | 이전 상태 | 전에 한 것 | 문제 |
|---|---|---|---|
| 실패 | `ready` | `unavailable` + "응답이 끊겼다" | 맞다 |
| 실패 | `unknown` (서버 직후) | **아무것도 안 함** | 상태도 사유도 처음 그대로 → "아직 확인하지 않았다" 가 확인한 뒤에 남는다 |
| 성공 | 아무거나 | 상태만 `ready` | 사유가 안 바뀌어 **`ready` 인데 "아직 확인하지 않았다"** 가 `/api/status` 에 나간다 |

두 번째·세 번째 줄이 결함이다. 고친 것은 한 자리다 — **탐지 결과를 상태와 사유 양쪽에 적는다.**

| 탐지 결과 | 이전 상태 | 지금 |
|---|---|---|
| 실패 | `unknown` | `unavailable` + `"127.0.0.1:11434 가 응답하지 않는다"` |
| 실패 | `unavailable` (기동 실패 등) | **그대로 둔다.** "ollama 을 찾을 수 없다" 가 "응답하지 않는다" 보다 구체적이다 |
| 성공 | `unknown`·`unavailable` | `ready` + `"127.0.0.1:11434 응답"` |
| 성공 | `ready` | **그대로 둔다.** `ensureRunning()` 이 남긴 "자동 기동함" 이 5초 뒤에 사라지면 안 된다 — 처음 구현이 이것을 놓쳤고 리뷰가 잡았다(아래) |

`starting` 상태는 여기 못 온다 — `ensureRunning()` 이 도는 동안 `refresh()` 는 맨 앞에서
그쪽 결과를 돌려주고 끝난다(단일 비행). 리뷰어가 이 경로를 따로 확인했다.

**화면에 닿는 변화** `[실측]`: Ollama 가 없을 때 상태 점이 `"로컬"` → `"로컬 · Ollama 없음"`,
툴팁이 `"아직 확인하지 않았다"` → `"127.0.0.1:1 가 응답하지 않는다"`. 원래 `unknown` 을
위한 라벨 `"로컬"` 은 이제 **첫 탐지 전에만** 보인다 — 그것이 그 라벨의 원래 뜻이다.

## D2 — 두 곳이 아니라 세 곳이었다

17-A 가 *"`structure.js`·`finish.js` 두 곳을 함께 고친다"* 고 적어 뒀다. 코드를 따라가니
**`/api/search` 도 같았다.**

```
q = "\u200B"
  → server.js: q.trim() 이 안 지움 → 빈 질의 검사 통과
  → 전문 검색: 토큰 0개 → 아무것도 못 잡음 → 저신뢰
  → 저신뢰면 rewrite() 가 모델을 부른다   ← 여기서 헛호출
```

세 곳이 같은 판단("이 질의는 비었는가")을 하므로 **한 함수**로 모았다 — `src/query.js` 의
`cleanQuery`. 유니코드 **서식 문자**(`\p{Cf}` — U+200B zero-width space, U+2060 word joiner,
U+FEFF BOM 같은, 보이지 않고 폭도 없는 글자들)를 지우고 `trim()` 한다.

**지우는 것이지 거부하는 것이 아니다.** `"가을\u200B 카페"` 는 400 이 아니라 `"가을 카페"` 로
간다. 검색 응답의 `query` 에코와 모델 프롬프트에도 정리된 문자열이 간다.

**트레이드오프 하나** — `\p{Cf}` 에는 이모지를 잇는 ZWJ(U+200D)도 든다. 가족 이모지 같은 결합
시퀀스가 낱개로 풀린다. 이 사이트의 토크나이저가 한글·영숫자 어절만 토큰으로 삼아 이모지를
원래 버리므로 결과는 안 달라진다 `[실측: tokenize.js 의 RUNS 정규식]`. 예외를 두지 않았고,
이유를 `src/query.js` 머리에 적었다.

### 검사기의 함정 하나 — Windows libuv 어서션

자식 프로세스가 결과를 찍고 `process.exit(0)` 하면 fetch 소켓이 닫히는 도중이라 Windows 에서
`Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c` 로 죽는다.
한 틱 미뤄도 같다 `[실측]`. 그래서 자식은 exit 하지 않고 `RESULT {json}` 한 줄을 찍으며,
**부모가 그 줄을 받고 자식을 죽인다.** check-stage17 이 "지연 응답이 떠 있는 채로 닫으면
Windows 에서 libuv 어서션이 뜬다" 고 적어 둔 것과 같은 부류다.
