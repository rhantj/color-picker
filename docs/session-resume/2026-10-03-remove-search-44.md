**판정표 (src/chat.js)**

```
팔레트로 읽음           → 문장 팔레트
진단으로 읽음           → Claude 가 고른 id(맨 앞) + 별칭 id → 진단표. 둘 다 없으면 되묻기

Claude 못 씀 · 추천 경로 → "못 읽었다"
```

## 왜 그렇게 했나 (버린 대안 포함)

- **진단을 의도 호출에 합쳤다.** 따로 부르면 진단 질문이 Claude 를 두 번 부른다(open-work J3). 한 호출의 칸 하나로 닫았다.
- **목록 밖 답을 못 하게 enum.** 그래도 서버가 지금 코퍼스에 있는지 한 번 더 본다(응답 사이 코퍼스가 바뀔 수 있다).
- **키 없을 때 추천은 정직하게 못 읽음.** 버린 것: BM25 를 키 없는 대비책으로 남기기(대표가 "걷어낸다" 를 골랐다 — 남기면 코드 · 게이트를 계속 지켜야 한다).
- **검색 결과 카드 · 펼치기도 걷어냈다.** 추천이 문장 팔레트가 된 뒤로 그 카드가 나올 길이 없었다(죽은 코드). `/api/expand` 엔드포인트와 그 게이트는
  남겼다 — 구조 · 재질 고르기 API 로 아직 유효하고, 화면에서 다시 쓸 수 있다.
- **옛 게이트는 은퇴, 남은 보장은 새 게이트로.** 옛 게이트를 검색 없이 돌게 고치는 것보다, 지킬 것을 새로 쓰는 편이 읽기 쉽다.

## 지금 상태

**동작하는 것** (실제 Claude, 키 없이 둘 다)
- 진단: "포스터 색이 어색하고 촌스러워" → 유치하다(llm) · "대시보드가 병원 같아요" → 차갑다/임상적이다(llm) · 키 없이 "색이 너무 탁해요" → 탁하다(alias)
- 캐릭터: "은발에 검은 갑옷 냉정한 기사" → 빨강 × 흑록(llm) · "분홍 머리 노란 드레스 마법 소녀" → 로즈핑크 × 민트그린(llm, 한 번은 null 이라 기본 쌍)
- 키 없이 추천 → "못 읽음" + 색 코드 안내 · Ollama 를 안 띄운다 · `/api/search` 404
- S44 10개 통과. 변형 19건 중 18건 잡힘(남은 하나는 등가 — 파서의 쌍 목록 검사를 빼도 서버가 한 번 더 거른다)
- 전체 게이트 308개(묶음으로 나눠 차례로): S1~S33 · S41~S44 **268/268** · S34~S36 · S39 **30/31** — S39-G6(LangSmith 부모 런, 0.5초 대기)이
  무거운 회귀 게이트와 나란히 돌 때 한 번 실패, 단독 통과 · S40 은 G1~G6 이 지운 임베딩에 묶여 실패 → 은퇴에 더한 뒤 G7 · G8 · G9 통과

**발견해서 고친 것**
- intent.js 가 불러올 때 진단 목록을 읽어, 깨진 코퍼스면 "기동 실패" 한 줄 대신 스택 트레이스로 죽었다(S44-G6 이 잡음)
- 은퇴 대상을 잘못 고른 것 하나(S12-G3 → 실제는 S12-G2). 그래서 **은퇴 장치를 끄고 그때까지의 은퇴 60개를 전부 다시 돌려** 아직 통과하는 것이 없음을 확인했다(전부 실패 = 은퇴가 맞다)
- **처음 분류 때 S40 묶음(임베딩 견고화)을 안 돌려 G1~G6 을 빠뜨렸다** — 마지막 전체 실행에서 실제 실패(지운 embed · hybrid 모듈 · 임베딩 준비 없음)를 보고 은퇴에 더했다(60 → 66)
- 템플릿 문자열이 정규식 역슬래시를 먹는 일이 또 두 번 났다 — 이번엔 편집 도구로 바로잡았다

**안 되는 것 · 모르는 것**
- Claude 가 캐릭터 배색 쌍을 가끔 null 로 낸다(기본 쌍으로 물러선다) — 빈도를 재지 않았다
- 홈에서 저장할 때 메모를 쓰는 칸이 없어졌다(검색 결과 카드에 있었다). 메모는 `/saved` 에서 쓴다
