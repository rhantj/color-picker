# 2026-09-13 — 검색 3단계 하이브리드: BM25 와 임베딩이 어긋나면 확신을 거둔다 (26단계)

## 무엇이 안 됐나

코퍼스 어휘와 겹치지 않는 질의 18건을 1·2단계에 넣었더니 **7건만 맞았다** `[실측]`.

| 결과 | 수 | 쉽게 말하면 |
|---|---|---|
| 정답 | 7 | 이미 잘 잡는다 |
| **거짓 확신** | **9** | 1단계가 "색"·"브랜드"·"같아요" 같은 흔한 어절 하나로 확신해 엉뚱한 답을 내고 LLM 을 안 부른다 |
| 저신뢰 → 2단계 실패 | 2 | 재작성어가 코퍼스 어휘와 안 맞았다 |

문서(`docs/com/rag-is-simpler-than-you-think.md`)가 *"실측이 요구할 때 올린다"* 고 했고, 이 실측이 요구했다.
다만 틀린 11건 중 9건은 "3단계가 없어서" 가 아니라 **1단계가 틀린 답을 확신해서**였다. 그래서 3단계를
붙이는 것과 거짓 확신을 거두는 것을 함께 했다(대표 결정).

## 어떻게 했나

설계와 버린 대안은 스펙에 있다 — `docs/superpowers/specs/2026-09-13-hybrid-search-design.md`.
구현 절차는 계획에 — `docs/superpowers/plans/2026-09-13-hybrid-search.md`.

**바뀌기 전**: 질의 → BM25 → 어절 하나라도 통째로 겹치면 확신(1단계) → 아니면 LLM 재작성(2단계).

**바뀐 뒤**: 서버가 뜰 때 코퍼스 34건(팔레트 16 · 진단 18)을 `bge-m3` 로 벡터화해 메모리에 둔다.
질의마다 BM25 와 코사인을 둘 다 본다.

| 단계 | 언제 | 쉽게 말하면 |
|---|---|---|
| 1 | BM25 확신 **그리고** 임베딩 1위도 같은 문서 | 두 방법이 같은 답이면 믿는다 |
| **3** | BM25 저신뢰이거나 임베딩과 어긋남 | 34건을 BM25 순위 + 코사인 순위로 결합(RRF)해 다시 고른다. 1위 코사인이 0.44 이상이면 확신. LLM 안 부름, 수십 ms |
| 2 | 3단계도 저신뢰 | LLM 재작성 → 재작성어로 다시 3단계 |

실행 순서는 1→3→2, 사다리 번호는 문서의 비용 사다리 그대로. 응답 `stage` 는 가장 높이 쓴 칸.

## 실측이 설계값을 셋 바꿨다

| 값 | 설계 | 실측 뒤 | 무엇이 잡았나 |
|---|---|---|---|
| 동의 범위 `AGREE_TOP` | 3 (임베딩 상위 3 안이면 동의) | **1** (1위끼리 같아야) | G1 — 3 이면 거짓 확신 3건이 남았다. BM25 오답이 상위 3 에 끼어 통과했다 |
| 확신 경로 예산 `FAST_BUDGET_MS` | 1500 | **700** | G4 — 1.5초는 `S3-G8` 의 "1초 미만" 과 모순. 확신 질의 왕복 1516ms |
| G2 의 재는 방법 | 스텁 Ollama | **실제 bge-m3** | 스텁의 무의미한 벡터는 절대 동의하지 않아 다섯 건 전부 3단계로 갔다 |

**"명절 저녁 식탁의 온기"** 는 제 기대값(`pair-09`)이 한쪽 해석이었다. 임베딩도 `dx-warm-up`(따뜻하게
만들고 싶다)을 1위로 본다. `alsoOk` 로 뒀다.

## 함정 기록

- **heredoc 안의 `\\n` 이 실제 개행으로 바뀐다.** `server.js` 148행이 깨져 게이트 다섯이 서버 기동 실패로
  울었다. 25단계에서 검사기 파일로 이미 한 번 겪은 것이다. 역슬래시가 들어가는 코드는 Write/Edit 도구로 쓴다.
- **스텁 벡터로는 "동의" 를 못 잰다.** 뜻 없는 벡터는 BM25 1위와 절대 같은 답을 안 낸다. 동의가 필요한
  게이트(G2)는 실제 모델로 잰다. 스텁은 "없을 때"(G3) · "느릴 때"(G4) · "경계"(G6) 에만 맞다.
- **예산 상수는 상위 게이트의 문턱보다 작아야 한다.** 1.5초 예산은 그 자체로 `S3-G8` 의 1초를 넘는다.
  G4 가 있어서 잡혔지, 없었으면 스펙 문장 그대로 들어갔다.

## 격리 리뷰 두 건

라운드 44, `review-fanout.sh` 로 작업 트리 스냅샷을 고정해 `typescript-reviewer` · `code-reviewer`.
완료 조건 7개와 본 트리 실측을 프롬프트에 직접 넣었다.

### code-reviewer — Critical 0 · P1 1 · P2 1

| 지적 | 처리 |
|---|---|
| **P1 — 보통 기동(자동 기동 켬)에서 Ollama 를 못 띄우면 임베딩 준비를 아예 안 불러 상태가 `unknown` 에 영원히 갇힌다.** 리뷰어가 없는 실행 파일로 서버를 띄워 재현했다. 게이트 하네스가 늘 `OLLAMA_AUTOSTART=0` 을 강제해 그 경로를 한 번도 안 돌렸다 | **맞다. 고쳤다.** 기동 결과와 무관하게 `prepareCorpusEmbeddings()` 를 부른다(`prepare` 가 스스로 실패를 잡는다). `S26-G3` 에 자동 기동을 켠 채 없는 실행 파일로 확인하는 검사를 더했고, 옛 코드로 되돌려 우는 것을 확인했다 `[실측]` |
| P2 — 26단계 전 대화 기록에는 `usedLlm` 이 없어 "LLM 0회" 로 조용히 틀린다 | 화면이 그 턴에 한해 `stage === 2` 로 되돌려 센다. 저장 파일은 안 건드린다. 알려진 한계에 적었다 |

**P1 이 이 리뷰의 값어치다.** 25단계에서 `refresh()` 의 "탐지했는데 unknown" 을 고쳐 놓고, 같은 모양의
구멍을 임베딩 쪽에 새로 냈다. 잡지 못한 이유가 더 중요하다 — **하네스의 기본값이 곧 사각지대다.**
`startServer` 가 `OLLAMA_AUTOSTART: "0"` 을 기본으로 깔아 두니, 보통 사용자가 밟는 경로가 게이트 어디에도
없었다. 기본값을 강제하는 하네스는 그 기본값의 반대편을 최소 한 번은 명시적으로 돌려야 한다.

확인해 준 것: 일곱 게이트를 실제 모델로 직접 재실행해 G1 12/18 일치 · 회귀 통과 · 게이트 200 실측 일치 ·
`hybrid.js` 순수 · 경계 처리 · `usedLlm` 위조 방어 · 스펙의 "구현 전" 문구는 이 저장소 관행(착수 시점 고정)과
같다고 봤으나 이번엔 "구현됨" 으로 갱신했다.

### typescript-reviewer — Critical 0 · P1 3 · P2 3

| 지적 | 처리 |
|---|---|
| P1 — 기동 실패 시 임베딩 `unknown` 갇힘 (위 code-reviewer 와 같은 지적, 실제 서버로 재현) | 위와 같이 고쳤다 |
| **P1 — 한 번 `unavailable` 이면 재시도가 없다.** Ollama 가 살아나도 재시작 전엔 3단계를 못 쓴다. 25단계 `refresh()` 정신의 절반(회복)이 빠졌다 | **맞다. 고쳤다.** `embed.refresh()`(5초 TTL 재시도)를 `/api/status` 가 부른다. 질의 중 연결 거부는 `unavailable` 로 내린다. `S26-G3` 이 스텁 404→200 회복을 본다 |
| **P1 — 재작성 의도 `other` 면 `stage: 3` 인데 `hybrid: null`.** 실제 모델로 "오늘 저녁 뭐 먹을까" 로 재현. 검사기 자신의 불변식("3단계인데 hybrid 가 null")을 픽스처에 그런 질의가 없어 못 잡았다 | **맞다. 고쳤다.** 결합이 답을 안 정했으면 `stage: 2`. `S26-G3` 이 스텁 의도 `other` 로 본다. 옛 코드로 되돌려 우는 것 확인 `[실측]` |
| P2 — `rw.error` 경로에서 `rerank` 를 같은 입력으로 두 번 | 첫 결과를 재사용 |
| P2 — RRF 가 BM25 오답에 점수 — 이미 정직하게 기록됨 | 조치 불필요 (E1) |
| P2 — `PREPARE` 예산이 질의 예산의 4배로 암묵 결합 | 상수로 빼고 주석에 적었다 |

**둘째·셋째가 이 리뷰의 값어치다.** 둘 다 "게이트가 안 잡는 경로" 였다 — 회복은 재는 게이트가 없었고,
`other` 는 픽스처에 색과 무관한 질의가 없었다. 리뷰어가 **실제 서버를 띄워** 찾았다. 게이트가 통과한다는
것은 게이트가 재는 것만 맞다는 뜻이다.

확인해 준 것: `AGREE_TOP=1` 로 `S3-G7`·`S3-G8` 질의가 여전히 1단계 · 검사기 포트·종료·타임아웃 이상 없음 ·
일곱 게이트와 회귀를 실제 모델로 재실행해 작성자 실측과 일치.
