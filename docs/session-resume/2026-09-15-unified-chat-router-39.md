# 39단계 — 탭 통합 · 결정적 라우터 · 되묻기

## 무엇을 했나

**한 줄로:** 탭 세 개(색감 추천 · 캐릭터 색감 · 코드 및 색상)를 지우고 채팅창 하나로 합쳤다. 사용자가 아무 말이나
치면 그 말이 색 얘기인지·캐릭터 얘기인지·증상 얘기인지를 **모델(LLM) 없이 어휘표만 보고 결정적으로 판정**하고,
애매하면 화면에 선택 칩을 띄워 되묻는다. 그리고 각 대화 턴이 LangSmith(관측 서비스)에 기록되게 배선했다.

- **`src/route.js` (신규)** — 판정기. "부위 낱말이 있으면 character, 증상 별칭이 걸리면 diagnosis, 입력 전체가
  색이면 color, 그 외엔 palette" 라는 표 하나로 판정한다. 모델을 안 부르므로 같은 입력엔 항상 같은 답이 나온다
  (게이트로 대조 가능한 이유).
- **`src/chat.js` (신규)** — `POST /api/chat` 하나가 상태 기계를 돈다. 판정이 겹치거나(예: character 이면서
  diagnosis) 불명확하면 "되묻는(ask)" 턴을 만들어 선택 칩을 응답에 담고, 사용자가 칩을 고르거나 문장을 더 치면
  그 답으로 실제 경로(palette/character/diagnosis/color)를 계산해 "답한(answer)" 턴으로 기록한다.
- **`src/trace.js` (신규)** — 각 턴을 `chat.turn`(부모) 아래 `route`/`search`/`color`/`character`/`ask` 같은
  자식으로 나눠 로컬 `traces.jsonl` 에 쌓고, LangSmith API 키가 있으면 같은 내용을 REST 로도 보낸다. 전송은
  "응답을 기다리지 않는" 방식이라 LangSmith 가 느리거나 죽어 있어도 사용자 응답은 안 막힌다.
- **`src/store.js`** — 대화 한 건이 가질 수 있는 턴 수를 10으로 제한하고(`LIMITS.turnsPerConversation`), 턴마다
  `kind`(ask/answer)와 되묻는 중이면 `pending`(무엇을 물었는지)을 함께 저장하도록 넓혔다.
- **`server.js`** — `/api/chat` 라우트를 추가하고, 검색·색·캐릭터 세 처리기를 "계산만 하는 함수"
  (`computeSearch`/`computeColor`/`computeCharacter`)로 분리해 기존 GET 엔드포인트와 새 채팅 라우트가 같은
  계산을 공유하게 했다. 라우터가 물고 있는 코퍼스도 27단계의 "코퍼스 파일이 바뀌면 재적재" 규칙을 그대로 따르게
  캐시를 버전 기준으로 다시 만들게 했다.
- **`public/*` (app.js·app.css·index.html·history.js·ui.js)** — 탭 UI를 통째로 없애고 채팅창 하나
  (`<ol class="chat">`)로 바꿨다. 되묻기 응답은 선택 칩으로, 답한 응답은 기존 결과 카드(구조 카드·짝 카드·부위별
  색 카드 등)를 그대로 재사용해 그린다. 내역(history)에서 "다시 묻기"로 들어오면 그 질문에 새로 답한다.
- **`.env` / `.env.example` / `.claude/launch.json`** — LangSmith 키는 옵트인(`.env` 에 넣으면 켜짐, 없으면
  꺼진 채로 조용히 동작)이라 예시 파일에 항목만 추가했고, 기동 설정이 `.env` 를 읽도록 `--env-file-if-exists`
  플래그를 반영했다.
- **`GATES.md` / `README.md` / `scripts/check-stage39.mjs` (신규) 및 `check-stage{2,31,34,35,36}.mjs`** —
  새 게이트 10개(S39-G1~G10)를 만들고, 탭이 있던 시절의 옛 화면 구조(`id="results-featured"`, 탭 목록 등)를
  단정하던 회귀 게이트 다섯 개를 "채팅 목록(`<ol class="chat">`)이 있는가" 같은 구조 단정으로 바꿔 통과하게 했다.
  게이트 총수는 248 → 258.

## 왜 그렇게 했나

**설계 단계에서 버린 대안** (스펙 문서 "버린 대안" 절 그대로 요지만):

| 버린 안 | 왜 버렸나 |
|---|---|
| 판정 순서를 고정하고 겹치면 규칙표로 하나 고름 | 예외가 계속 늘어난다. 되묻기가 그 자리를 대신한다 |
| 판정 자체를 LLM 에 맡김 | 헥스 하나 넣어도 모델을 부르고 답이 매번 달라 결정적 게이트를 못 만든다 |
| 애매하면 결과를 둘 다 보여줌 | 화면이 길어지고 "어느 게 답인가" 를 사용자가 또 골라야 한다 |
| LangGraph 로 상태 기계 구현 | "의존성 0개" 전제와 충돌. 대화 저장소가 이미 있는데 체크포인터를 새로 들이는 것 |
| 탭을 접힌 필터로 남기거나 `/캐릭터` 같은 입력 접두어 | 탭 UI 유지 비용이 들거나 사용자가 접두어를 외워야 한다 |
| 되묻기 상한 30회 | 대화가 10턴이라 한 번도 안 걸린다. 같은 입력에 두 번 되물으면 "못 알아듣는다" 로 읽힌다 |
| 로컬 화면에 트레이스 표시 | 보는 곳은 LangSmith 로 정했다. 로컬 파일(`traces.jsonl`)은 게이트가 대조할 기록용일 뿐 |
| FastAPI(Python)로 라우터 작성 | 라우터는 어휘표 대조 100줄 수준이라 프로세스 경계를 넘길 크기가 아니다. 검사기 248개가 전부 Node |

**구현 중 실제로 내린 판단(장부의 Ruling 그대로, 조건 요약):**

- **1글자 부위 낱말 오탐** — "검"이 "검정" 안에서 걸려 "검정 안경"이 캐릭터로 잘못 갔다. 처음엔 "부위 표면형은
  2글자 이상만" 으로 고쳤더니 "눈"·"옷" 같은 진짜 1글자 부위가 다 죽어 되묻기·2역할 감지가 회귀했다. 최종 규칙:
  **어절 전체가 그 글자이거나, 어절이 그 글자로 시작하고 바로 뒤가 조사(이·은·을·도·에·과·와·만·색·이랑)일 때만**
  매칭한다. "검정"의 "정"은 조사가 아니므로 안 걸린다.
- **"부위 둘이면 강함" 판정을 표면형이 아니라 역할(role) 기준으로 셈** — 안 그러면 "포인트 강조" 같은 동의어
  중복이 표면형 두 개로 잘못 세어져 강한 신호가 됐다.
- **"눈 상의"(부위 낱말만 있는 입력)는 unclear가 맞다** — 컨트롤러가 처음엔 캐릭터로 가야 한다고 봤지만, 스펙
  1절 "부위 낱말만 있으면 unclear" 규정이 옳다고 판단해 구현자 판단을 받아들였다.
- **오류 경계 정리** — 입력 검증 오류만 400(타입 있는 `ChatInputError`)이고 나머지는 500으로 안전하게 실패한다.
- **"답한 질의"는 실제로 답한 문장** — 되돌리기 칩을 눌렀을 때 기록에 남는 검색어(query)를 "[캐릭터]" 같은
  placeholder가 아니라 실제 합쳐진 문장/직전 원문으로 남긴다. "다시 검색"이 엉뚱한 것을 찾는 사고를 막는다.
- **선택(choice)에 pending이 없으면 400** — "되물은 질문이 없다"로 명확히 거부한다.
- **처리기가 던지면 트레이스 스팬도 오류로 닫는다(try/finally)** — 관측 기록이 성공으로 잘못 남는 것을 막는다.
- **트레이스 요약을 모든 경로에 싣는다** — 라우터의 후보(routes)·신호(signals)를 답한 응답과 route 자식
  런 양쪽에 항상 담는다(원래는 일부 경로만).
- **마지막(10번째) 턴에서는 되묻지 않는다** — 9턴이 찬 대화에서 되묻기가 걸리면 그 칩은 다음 요청에서
  10턴 롤오버에 먼저 걸려 새 대화(=pending 없음)로 열려 "되물은 질문이 없다"는 400을 돌려주는 막다른
  길이 됐다. 그래서 마지막 턴에서는 불명확해도 묻지 않고 첫 후보/추천으로 바로 답한다.
- **옛(해소된) 칩은 화면에서 비활성화한다** — 문장으로 답하면 서버는 pending을 지우는데 화면 칩은 그대로
  눌러졌다. `send()` 맨 앞에서 목록에 남은 칩을 전부 비활성화한다.
- **내역 "다시 묻기"는 `fresh:true`로 보낸다** — 그래야 서버가 그 대화에 남아 있는 pending을 버리고 새
  질문으로 라우팅한다. 안 그러면 옛 질문 답으로 취급돼 문장이 이어 붙었다.
- **게이트용 라우터는 운영 라우터와 반드시 같은 입력을 받는다** — 검사기의 `loadRouter()`가 `creatures`
  목록을 안 넘겨 종족 낱말 신호가 한 번도 검사되지 않고 있었다. `server.js`와 똑같이 넘기도록 고쳤다.
- **라우터는 요청마다 코퍼스 버전을 확인한다** — 기동 때 한 번만 코퍼스를 잡아 두면 27단계의 "코퍼스가
  바뀌면 다시 읽는다" 핫리로드가 `/api/chat`에서만 죽는다. `pipeline.corpusStatus().version`이 바뀔 때만
  라우터를 다시 만들도록 캐시를 고쳤다.
- **음수(negative) 대조 표의 기준선을 실측으로 확정** — 입력표가 늘어난 뒤(16→21→22건) `NEGATIVE_MIN`
  (캐릭터가 아닌 행이 최소 몇 건 있어야 하는가)을 매번 다시 계산해 규칙이 여전히 성립하는지 확인했다.
- **Task 7 리뷰의 "6개 파일 오염" 은 오탐이었다** — 리뷰어가 워크트리 브랜치의 조상이 아닌 잘못된 기준
  커밋으로 리뷰 패키지를 만들어 생긴 착시. `git show --stat`으로 실제로는 3개 파일(`.env.example`·
  `.gitignore`·`README.md`)만 바뀐 것을 확인해 무혐의 처리했다. 이후 리뷰 패키지는 merge-base로 만든다.
- **S39-G10(회귀 전부 통과) 규정을 실측으로 좁혔다** — "1~38단계 검사기 전부"가 아니라 실제로 39단계가
  건드린 화면 구조 때문에 깨질 수 있는 다섯 스크립트(S4·S22·S34·S35·S36)로 시작했고, 최종 리뷰에서 이번
  변경이 직접 고친 S2·S31이 회귀 목록에서 빠진 것을 지적받아 추가했다.

## 알려진 한계

- **LangSmith 실제 전송은 미실측** `[판단]` — API 키가 없어 REST 호출은 가짜 서버로 형식만 확인했다.
  진짜 LangSmith 대시보드에 `chat.turn` 런이 실제로 뜨는지는 아직 아무도 안 봤다.
- **스펙 4절과 다른 점** — 자식 런에 `llm.structure`·`llm.finish`가 없다(대신 `color`·`character` 자식이
  있다). 그리고 LLM을 부르는 자식 런에 "프롬프트" 내용을 안 싣는다 — 처리기 응답에 프롬프트 자체가 없어서다.
  모델명·결과만 보낸다. 프롬프트가 꼭 필요하면 `rewrite.js`·`describe.js`에 훅을 넣는 별도 작업이 필요하다.
- **1글자 부위 낱말 뒤 구두점 경계** — "눈,"처럼 조사 목록에 없는 형태(활용·구두점)는 안 걸린다. "눈처럼" 도
  마찬가지. 조사 목록에 더 채우면 되지만 이번 웨이브에서는 안 건드렸다.
- **스펙 1절 "부위 둘이면 강함" 이 실제로는 발화하지 않는 경로가 있다** — "눈 상의"처럼 색 낱말 없이 부위만
  두 개면 partsOnly 판정이 먼저 걸려 unclear로 간다("부위 둘이면 강함" 규칙에 못 이른다). 코드가 아니라
  **스펙 문구가 부정확** — 이번 웨이브에서 문구 정정은 하지 않았다.
- **약한 부위 신호 + 진단이 겹치면 항상 ambiguous** — "눈에 띄는 색인데 탁해" 처럼 진단 별칭이 걸리면 약한
  부위 신호 하나로도 character×diagnosis 겹침이 된다(강등 규칙이 `routes.length===1`일 때만 동작).
- **10턴 롤오버에 화면 표시가 없다** — 서버는 10턴을 채운 대화를 읽기 전용으로 두고 새 입력은 새 대화로
  보내지만, 화면은 아무 배너도 안 띄운다(스펙 5절 기대와 다름).
- **블록별(카드별) 다크 모드 토글이 전역과 어긋날 수 있다** — 23단계의 의도된 동작 그대로 유지했다.
- **`NEGATIVE_MIN`이 딱 경계값에 걸려 있다** — 음수 대조 표의 최소 요구치가 정확히 11/22로, 입력이 하나만
  더 줄면 규칙이 깨질 수 있는 여유 없는 상태다.
- **자동화 도구의 Enter 키가 폼을 제출하지 않았다** — 버튼 클릭·`requestSubmit()`으로는 됐다. 하네스 문제로
  보고 넘겼지만 사람이 실제 키보드로 다시 확인해야 한다.
