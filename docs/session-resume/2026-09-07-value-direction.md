# 2026-09-07 — 파생 팔레트의 명도 방향 + 스와치 넘침 (15단계)

사용자 요청은 **"네온 사인 빛의 어두운 사이버펑크 풍의 색감"** 질의에서 그 색감이 나오게 하고,
**이미션·메탈릭 같은 감촉까지 표현**하는 것이었다. 이 단계는 그 앞을 막고 있던 것 하나만 치운다 —
재질은 다음 단계(16)다.

## 무엇을 하려던 것인가

브레인스토밍으로 재질(PBR 머티리얼) 축을 설계하고
[`docs/superpowers/specs/2026-09-07-pbr-material-finish-design.md`](../superpowers/specs/2026-09-07-pbr-material-finish-design.md)
에 스펙을 고정했다. **스펙 자체검토 중에 재질보다 앞선 차단 요인이 나왔고, 그것이 이 단계다.**

## 왜 이것부터인가 — 검색은 이미 맞았다 `[실측]`

세션을 "질의에서 색감이 안 나온다" 로 시작했지만 **검색은 이미 정확했다.**

```
질의: "네온 사인 빛의 어두운 사이버펑크 풍의 색감"
→ stage 1, route "palette", confident=true   (LLM 을 아예 안 부른다)
   pair-06  자홍 #B73F74 × 진파랑 #005B8D
   matched: 네온(2.6589, whole) · 사이버펑크(2.3107, whole)   wholeMatches=2
   tags: 밤 · 네온 · 도시 · 퇴폐 · 디스토피아 · 사이버펑크 · 야경 · 클럽
```

문제는 그 뒤였다. **파생 결과의 바탕이 거의 전부 흰색이다.**

```
16쌍 × 8구조 = 128장 중 바탕 명도 l >= 0.90 인 것: 112장 (87.5%)

pair-06 — 네온·사이버펑크 태그가 붙은 바로 그 조합
  톤온톤 #e8eff3 · 보색대비 #eaeef1 · 유사색대비 #e8f3f2 · 명도스케일 #eaeef0
  강조색 #efebed · 따뜻한뉴트럴 #f2ebe8 · 공기원근 #e9edf2     ← 전부 l=0.93
  톤인톤 #a71a59 l=0.38                                    ← 여덟 중 유일하게 어둡다
```

**"어두운"이 산출물에 없었다.** 이건 결함이 아니라 전제다 — 여덟 구조는 `color-design` 의
**웹·앱 UI 색 결정** 절에서 왔고 거기서 밝은 바탕은 기본값이다. 게임 씬은 전제가 다르다.

그리고 **재질이 이것을 못 고친다.** `applyFinish` 는 역할색을 받아 가공할 뿐이고, 명도 위계까지
다시 쓰게 하면 배색 결정이 두 파일에 나뉘어 앉는다. 그래서 순서를 재질보다 앞으로 뒤집었다.

## 어떤 원리를 썼나 — 방향만 뒤집는다

`light.md` 의 **명도 그루핑** — "명부·중간톤·암부 중 **어느 덩어리가 가장 넓은 면적을
차지하는지** 파악한다." 앵커를 새로 만들지 않고 **거울로 뒤집는다.**

```
L      = { light: 0.93, upper: 0.72, mid: 0.5,  lower: 0.32, dark: 0.15 }
MIRROR = { light→dark,  upper→lower, mid→mid,   lower→upper, dark→light }
```

**반사이지 압축이 아니라 앵커 사이 간격이 그대로 보존된다.** 그래서 S11-G7(명도 단계 최소 0.15)이
어두운 모드에서도 성립한다 — S15-G3 이 따로 검사한다(실측 최소 0.169).

### 의도한 비대칭 셋

| 무엇 | 왜 |
|---|---|
| **채도 상한 `S_CAP` 은 거울을 안 탄다** | S_CAP 은 앵커가 맡는 **역할**에 맞춘 값이다. `light` 가 가장 낮은 것은 그 자리가 언제나 바탕이라 조용해야 하기 때문이고, 바탕이 어느 명도로 가든 바탕은 조용해야 한다. 거울을 태우면 어두운 바탕이 `S_CAP.dark`(0.85)를 쓰게 되어 그 이유가 통째로 사라진다 |
| **`톤인톤` 은 거울이 아니라 접기** (`min(l, 1-l)`) | 톤을 씨앗 명도의 평균에서 가져와 세 색이 같은 `l` 을 쓴다 — **명도 위계가 없다.** 그대로 반사하면 어두운 씨앗이 오히려 밝아진다(pair-06 은 l=0.38 → 0.62) |
| **씨앗 원본을 그대로 내보내는 자리는 안 뒤집는다** | `accent` 원본과 `at(accent, {h:...})` 자리. 뒤집으면 씨앗에 없는 색을 지어내게 된다 |

## 뮤테이션이 게이트를 세 번 고쳤다

게이트를 **구현보다 먼저** 썼고(RED 확인 후 구현), 그 뒤 뮤테이션 10종으로 반응을 쟀다.
**세 개가 살아남았고 셋 다 실제 결함이었다.**

| 살아남은 뮤테이션 | 드러난 것 | 조치 |
|---|---|---|
| `S_CAP[key]` → `S_CAP[anchorFor(key,mode)]` | **상한이 0.3 → 0.85 로 열리는데 게이트 여섯이 조용했다.** 위 비대칭 1번 결정에 게이트가 없었다 | **S15-G7 신설** |
| `makeStep("light")` → `makeStep("dark")` | 결과가 안 변했다 — **모듈 레벨 `step` 이 죽은 코드였다.** 모든 규칙이 인자로 받은 `step` 으로 그 이름을 가린다 | 죽은 상수 제거. 죽은 갈래는 "여기를 고치면 기본 모드가 바뀐다"고 거짓말한다 |

## 게이트 하나를 스스로 고쳤다 — 상대 조건이 틀렸다

S15-G2 를 처음엔 "어두운 모드 바탕이 **전부 엄격히** 낮아진다" 로 썼고 톤인톤 22건에서 실패했다.
구현에 맞춰 게이트를 푼 것이 아니라 **내가 쓴 조건이 보편 규칙으로 틀렸다** — 톤인톤은 명도 위계가
없어 방향을 강제하면 원전에 없는 톤을 지어내게 된다. 불변식 셋으로 다시 썼다:

1. 앵커 기반 일곱 구조는 `l <= 0.2`, 톤인톤은 `<= 0.5`
2. 밝은 모드보다 **밝아지지는** 않는다
3. 앵커 기반에서 0.2 를 넘던 것은 **전부 실제로 낮아졌다** (280장)
4. 톤인톤은 접기 정의 `min(l, 1-l)` 와 **정확히** 일치한다 (40장)

③이 없으면 "아무것도 안 하는" 구현이 ①②를 통과한다. ④가 없으면 톤인톤에 대해 ①이 공허하다 —
접기는 정의상 0.5 를 넘을 수 없으므로 아무 구현이나 통과한다. 두 갈래 각각에 양성 대조를 걸어,
검사한 장이 0 이면 게이트가 스스로 운다.

**①의 문턱 0.2 는 리뷰가 고치게 한 값이다.** 처음엔 0.5 하나였고, 리뷰어가 `MIRROR` 를
`{light:"mid", mid:"light", ...}`(여전히 대합)로 바꿔 바탕을 "딱 중간 회색"으로 만들었는데
320장 중 319장이 통과했다. 앵커 기반 실측은 0.1510(193장)·0.1490(87장) 두 값이라 0.2 가 둘을 가른다.

## 같이 고친 것 — 파생 스와치가 카드 밖으로 넘쳤다

사용자가 스크린샷으로 알려 온 별개 결함이다. **원인은 CSS 자손 선택자 하나였다.**

```css
.card--featured .swatch            { width: 460px; flex-shrink: 0; }
.card:not(.card--featured) .swatch { height: 128px; }
```

두 규칙은 카드 **자신의** 스와치를 겨냥해 쓰였고, 그때는 카드 안에 다른 스와치가 없었다.
**13단계에서 파생 팔레트가 카드 안(`.expand__grid > .struct`)으로 들어오면서** 자손 선택자가
그 안의 스와치까지 함께 잡기 시작했다. 규칙을 고친 사람이 없는데 주변이 바뀌어 깨진 결함이다.

브라우저 실측 (1280×800, 파생 8장씩):

```
                 카드폭  스와치폭  넘침     높이
featured 안        298     460     +176px    42     ← 460px 는 위 첫 규칙의 값
normal   안        507     481      -13px   128     ← 128px 는 위 둘째 규칙의 값
```

**넘침이 8장 모두 정확히 176px 로 같았던 것이 결정적 단서였다.** 라벨 길이나 색 개수에 따라
달랐다면 min-content 문제였겠지만, 상수라는 것은 어딘가에 고정폭이 박혀 있다는 뜻이다.

고친 것은 세 줄 — 세 규칙을 전부 **직속 자식(`>`)** 으로 좁혔다(미디어쿼리 안의 것 포함).
증상 쪽(`.struct .swatch { width: auto }` 덮어쓰기)이 아니라 원인 쪽이다.

고친 뒤 실측:

```
375px   파생 16장  최대넘침 -13px  높이 56/70  가로스크롤 0
753px   파생 16장  최대넘침 -13px  높이 56/70  가로스크롤 0
1425px  파생 16장  최대넘침 -13px  높이 56/70  가로스크롤 0
카드 자신의 스와치: featured 460px · normal 128px  (규칙 그대로, 회귀 없음)
```

### 리뷰가 이 게이트를 두 번 뚫었다

CSS 수정 자체는 문제없다고 나왔고(리뷰어가 `public/ui.js` 의 카드 조립 코드를 읽어 `.swatch` 가
`article.card` 의 **첫 직속 자식**임을 확인), **지적 둘은 전부 내가 쓴 게이트에 있었다.**

| 지적 | 무엇 | 조치 |
|---|---|---|
| **HIGH-1** | 선택자 파서가 `/(^\|[};])([^{}@;]+)\{/` 라, 선택자 앞에 `}`·`;`·문자열 시작을 요구했다. `@media (...) {` 바로 다음 **첫 규칙**은 앞이 `{` 이라 목록에서 통째로 빠졌다 — 그 자리에 자손 선택자를 되돌려도 통과했다 | 정규식을 버리고 **중괄호를 걸으며 읽는 스캐너**로 바꿨다(따옴표 건너뜀). 스캐너 자체의 양성 대조를 게이트 안에 넣었다 |
| **HIGH-2** | 양성 대조가 개수만 봤다(`child.length < 2`). 버그를 만든 **바로 그 규칙 하나만** 지워도 나머지 둘이 문턱을 만족해 `S15_G9_OK` 가 나왔다(실측) | **선택자별 개수를 표로 적고 정확히 대조**한다. `.card--featured > .swatch` ×2 · `.card:not(.card--featured) > .swatch` ×1 |
| MEDIUM | `GATES.md` '알려진 한계'에 이 게이트의 실제 한계가 없다 | 잡는 것·못 잡는 것을 실측으로 적었다 |

**개수는 "무엇이 남았는가" 를 말하지 않는다** — HIGH-2 가 그 교훈이다. 양성 대조를 넣었다는
사실만으로 안심했고, 그 대조가 무엇을 배제하는지는 안 따졌다.

## 2라운드 리뷰 — 반영 검증 + 새 지적 하나

전체 diff 를 보는 두 번째 리뷰어가 **1라운드 여섯 지적이 실제로 닫혔는지**를 뮤테이션으로
하나씩 재현해 확인했다. 여섯 전부 "새 게이트가 정확히 그 뮤테이션에 반응한다" 로 확인됐고,
특히 **`complementary` 이중 반전 버그는 `S15-G1`(기준선 회귀)이 통과하고 새 `S15-G5` 만
유일하게 잡는 것**이 확인됐다 — G5 확대가 실제로 값을 한다는 증거다.

교차 검증 하나가 의도대로 도는 것도 확인됐다: `NO_MIRROR` 에 항목을 **부당하게 추가**하면
(실제로는 앵커를 타는 자리를 제외 목록에 넣기) G5 는 조용해지지만 커버리지가 720→680 으로
소리 없이 줄어드는데, **G8 의 자체 정합성 검사가 즉시 잡는다.** 뚫으려면 두 곳을 동시에
잘못 고쳐야 한다.

새 지적은 하나였다.

| 지적 | 판정 | 조치 |
|---|---|---|
| HIGH — `S15-G9` 양성 대조가 개수만 본다 | **이미 닫힘.** 이 리뷰어는 고치기 전 스냅샷(`34a0e55`)을 봤다. CSS 리뷰의 HIGH-2 와 같은 것 | 그들이 제시한 재현(`.card:not(.card--featured) > .swatch` 통째 삭제)을 돌려 지금은 잡히는 것을 확인 |
| **LOW — "앵커 기반 실측이 전부 0.1510" 이 틀렸다** | **맞음. 새 지적** | 전수 재측정 → **0.1510(193장) · 0.1490(87장)** 두 값. 두 곳 정정 |

**실측치 오기가 이 단계에서 두 번째다** (첫 번째는 0.471). 두 번 다 **표본 일부를 전체로 옮겨
적은** 같은 부류다. 게이트 정확성에는 영향이 없었지만(둘 다 0.2 아래라 판정이 안 바뀐다),
이 저장소는 `[실측]` 을 근거로 인용하는 규율을 쓰므로 틀린 값은 다음 사람을 잘못 인도한다.
**`[실측]` 을 적을 때는 전수를 돌린다** 를 주석에 규칙으로 박았다.

리뷰어가 나머지 수치를 전부 재계산해 대조했고 — 87.5%(112/128) · 0.4804(pair-09, 22건) ·
0.498 · 280/320 · 0.871 · 0.299 · 720곳/160곳 · 298px — **0.1510 하나만 어긋났다.**

**`S15-G9` 는 정적 검사다.** 의존성 0 이라 헤드리스 브라우저가 없어 실행 시점 넘침은 못 본다 —
`GATES.md` '알려진 한계'가 같은 이유로 같은 말을 이미 하고 있다. 선택자가 자손 형태로 되돌아가는
것만 본다. 뮤테이션 5종(세 규칙 각각 되돌리기 · 중간에 `.card__body` 끼우기 · 규칙 통째 삭제)에
전부 반응하는 것을 확인했다. **다르게 쓴 같은 누수는 못 잡는다.**

## 함정 기록

- **`.md` 안의 게이트 번호를 정규식으로 일괄 치환했다가 자기 결과를 다시 치환했다.**
  `S12-G1 → S12-G6` 이 만들어 놓은 문자열을 다음 회차가 다시 잡아 `S12-G61` 이 나왔다.
  번호 이동은 **한 번의 `re.sub` + 콜백**으로 해야 한다.
- **JSDoc 블록 중간에 `*/` 가 남은 채로 이어 썼다가 `SyntaxError: Unexpected token '*'`.**
  주석 블록을 늘릴 때는 닫는 줄 위치를 먼저 본다.
- **`review-fanout.sh` 의 `--round` 는 같은 SHA 를 재사용한다.** 코드를 고친 뒤 같은 라운드로
  열면 "지금 없는 코드를 리뷰한다"며 거부한다. 라운드를 올리거나 `--stale-ok` 를 준다.
- **브라우저 창이 뒤에 있으면 스크린샷이 흰 화면으로 나온다.** 페인팅이 안 되기 때문이고,
  `requestAnimationFrame` 도 안 돌아 그것을 기다리는 스크립트는 타임아웃한다.
  **레이아웃 증거는 스크린샷이 아니라 `getBoundingClientRect` 측정으로 남긴다** — 어차피
  "몇 px 넘쳤나" 는 그림보다 숫자가 정확하다.
- **다른 세션이 4173 을 점유하고 있으면 `preview_start {name}` 이 거부된다.** 추적 파일인
  `.claude/launch.json` 을 고치는 대신 `preview_start {url: "http://localhost:4173"}` 로
  붙었다 — 같은 폴더를 서빙하므로 `public/` 변경이 그대로 보인다.

## 다음에 할 일 ① — 어두운 모드 토글 (설계 합의됨, 구현 안 함)

**세션 마지막에 사용자가 "토글로 설정 가능하도록" 을 골랐고 설계까지 합의했다. 코드는 한 줄도
안 썼다.** 다음 세션은 여기서 바로 시작하면 된다.

### 결정된 것

| 물은 것 | 고른 것 | 근거 |
|---|---|---|
| 어느 모드를 쓸지 누가 정하나 | **사용자가 토글로** | 사용자 선택 |
| 토글 범위 | **펼침 영역마다 하나** | 상태가 그 영역 클로저 안에만 있어 공유 상태가 안 생긴다. 카드마다 다른 모드로 나란히 비교도 된다 |
| 모드를 서버에 보내나 | **안 보낸다. 두 모드를 한 번에 받는다** | `/api/expand` 는 `q` 로 LLM 을 불러 8개 중 5개를 고른다. 토글마다 재요청하면 **같은 질의인데 보이는 다섯이 바뀐다.** 게다가 매번 ~500ms |
| 저장에 넣나 | **안 넣는다** | 13단계가 "파생 팔레트 저장은 이 단계에 없다" 로 이미 미뤘고 `normalizeRatio` 가 2색 전제다 |
| `localStorage` 로 기억하나 | **안 쓴다** | 이 저장소에 전례 0건. 상태는 전부 서버 `var/` 에 있다. 새 저장 계층을 이 작업으로 들이지 않는다 |

### 손댈 자리

- **`server.js` `handleExpand`** — `expandAll(seed, undefined, {mode:"dark"})` 를 한 번 더 돌려
  구조마다 `colorsDark` 를 얹는다. **기존 필드는 하나도 안 바꾼다** (S13-G4·S14-G4 가 응답
  형태를 본다). `mode` 를 쿼리 파라미터로 **만들지 않는다** — 만드는 순간 토글이 LLM 재선택을
  부를 경로가 생긴다.
- **`public/app.js` `expansionSection`** — 영역 클로저에 `mode` 상태. 토글 버튼은 `note` 아래.
  누르면 **이미 받아 둔 `data` 로 `grid`·`restGrid` 만 다시 그린다.** 네트워크 0, LLM 재호출 0.
- **`public/ui.js` `structureCard(st, mode)`** — `mode === "dark" ? st.colorsDark : st.colors`.
  `colorsDark` 가 없으면 `colors` 로 물러선다.
- **`public/app.css`** — 토글 버튼. `.expand__more-toggle` 과 무게가 겹치지 않게 한다.

### 게이트 S15-G10~G12

| | 검사 |
|---|---|
| G10 | 응답이 구조마다 `colors`·`colorsDark` 를 둘 다 주고 **둘이 실제로 다르다**. `colors` 는 기존과 동일(회귀) |
| G11 | **`mode` 는 서버 파라미터가 아니다** — `?mode=dark` 를 붙여도 응답이 완전히 같다 |
| G12 | **어두운 모드 파생색에서도 스와치 글자색 대비 4.5:1** — `S13-G6` 과 같은 기준·같은 음성 대조(고정 회색 라벨 `#888888` 은 실패해야 한다) |

**G12 를 가장 먼저 돌린다.** 어두운 색이 화면에 나가는 순간 라벨이 안 읽히면 기능이 아니라
결함이고, 지금 `S13-G6` 은 밝은 모드만 본다. **어두운 모드가 이 기준을 넘길지는 재 보기 전에는
모른다** — 실패하면 그 사실을 먼저 보고하고 어떻게 할지(라벨 규칙을 고칠지, 어두운 모드를
조정할지) 사람에게 묻는다. **조용히 기준을 낮추지 않는다.**

## 열려 있는 것

- **어두운 모드가 화면·API 에 아직 안 나간다.** 엔진에만 있다. 어떻게 내보낼지는 위 '다음에 할 일 ①'
  에서 정해졌다 — 사용자 토글, 두 모드를 한 번에 전달. **구현은 안 됐다.**
- **파생색끼리의 대비를 보는 게이트가 없다.** 실측으로 바탕 대비 3:1 미만이 밝은 모드 243건 ·
  어두운 모드 169건이다. **어두운 모드가 74건 적으므로 이번 변경이 만든 문제는 아니다** —
  최저 1.00 은 톤인톤이고 그 구조는 정의상 세 색의 명도가 같다. `S13-G6` 은 스와치 **글자색**
  대비를 보는 다른 게이트다.
- **`aerial`(공기원근)의 거울이 의미상 맞는지 확인 안 됐다.** 어두운 씬에서 먼 쪽이 어두운 것이
  맞는지 `light.md` 가 말하지 않는다("멀수록 대비·채도 하락", 방향은 상대적). 기계적으로
  뒤집어 뒀고, 화면에 그려 보고 판단한다.
- **`S15-G1` 의 기준선 파일이 다시 생성되면 게이트가 무의미해진다.** 파일 안에 경고를 적었지만
  강제하는 장치는 없다. git 이력이 유일한 증거다. 리뷰가 둘 다 같은 것을 지적했고, 한쪽은
  "생성 시점의 `src/expand.js` 해시를 픽스처에 함께 적어 두면 사람이 대조할 근거가 남는다" 는
  개선안을 냈다 — **채택하지 않았다.** 해시도 함께 다시 만들면 그만이라 강제력이 늘지 않고,
  강제력이 생긴 것처럼 보이게 만드는 쪽이 더 나쁘다고 판단했다. 다시 볼 자리로 남긴다.
- **게이트 수가 한 세션에 다섯 번 바뀌었고 README 와 한 번 어긋났다**(107 인데 108 로 적음).
  `GATES.md` 의 `CHECK:` 줄 수 · README 선언값 · README 단계별 합계 셋이 일치하는지는
  지금 사람이 센다. 게이트로 만들 수 있지만 이번 단계 범위 밖이라 하지 않았다.
- **`S15-G4`(채도 상한)는 이번 뮤테이션 세트로 실패를 못 만들었다.** `S_CAP.dark` 를 1.0 으로
  올려도 최대 지각 채도가 그대로였다 — 극단 명도에서 `C=(1-|2l-1|)·s` 가 s 와 무관하게
  채도를 누르기 때문이다. 어두운 모드에 대해서는 이 게이트가 사실상 헐겁다는 뜻이고,
  실질 방어는 `S15-G7`(역할 상한)이 한다.
