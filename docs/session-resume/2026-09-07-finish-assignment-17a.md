## 바뀌기 전에는 무엇이 있었나

16단계가 재질 엔진을 만들었지만 **어느 역할에 어떤 재질인지**는 손으로 적은 표
(`DEFAULT_FINISH_BY_ROLE`)뿐이었다. 그 표는 "네온 사인 빛의 어두운 사이버펑크" 와
"가을 카페 브랜딩" 에 **똑같은 재질**을 준다 — 질의가 재질에 닿지 못한다.

16단계 스펙이 그 한계를 미리 적어 뒀다. "재질을 구조에 못 박고 LLM 미개입" 을 버린 대안으로
두면서, **버리지 않고 기본 배정 = 폴백으로 흡수**했다. 이 단계가 그 위에 LLM 을 얹는다.

## 왜 LLM 인가

"네온 사인" 의 강조가 발광이어야 하고 "가을 카페" 의 강조는 그러면 안 된다는 것은 **계산으로
안 나온다.** 색상각도 명도도 그 판단을 못 한다 — 질문의 뜻을 읽어야 한다. 이 사이트에서
LLM 이 하는 일은 이제 셋이고(질의 재작성 · 구조 선택 · 재질 배정) 셋 다 같은 성격이다.

## 어떤 원리를 썼나 — `structure.js` 를 거울로 삼는다

14단계가 이미 같은 문제를 풀었다: **로컬 LLM 에게 목록에서 고르게 하고, 실패하면 물러선다.**
새로 설계하지 않고 그 자리·그 모양을 그대로 옮겼다.

| | `structure.js` (14단계) | `finish.js` (17-A) |
|---|---|---|
| 무엇을 고르나 | 8구조 중 5개 | 역할마다 재질 하나 |
| 질의가 없으면 | 안 부른다 | 안 부른다 |
| 실패하면 | 카탈로그 앞 다섯 | `DEFAULT_FINISH_BY_ROLE` |
| 배지 | `matched === 0` 이면 `from="fallback"` | 같다 |
| 타임아웃 | `STRUCTURE_TIMEOUT_MS` | `FINISH_TIMEOUT_MS` (**같은 값을 독립적으로 적는다**) |
| 던지나 | 안 던진다 | 모델·네트워크로는 안 던진다. `roles` 가 잘못되면 던진다 |

**LLM 은 색에 닿지 않는다.** 고르는 것은 재질 id 뿐이고 헥스는 전부 `material.js` 가 씨앗 색을
받아 계산한다. `S17-G7` 이 실제로 헥스 주입을 시도해 확인한다 — 사용자가 고른 경계다.

**폴백은 16단계의 표 그대로다.** 두 벌을 두면 둘이 갈라진다. `S17-G8` 이 세 곳(엔진 폴백 ·
`material.js` · 게이트의 독립 사본)이 같은 표인지 대조한다.

## 게이트가 자기 하네스의 결함을 드러냈다

**`S17-G4` 가 처음에 통과했는데 우연이었다.**

한 게이트 안에서 가짜 Ollama 를 두 번 세웠다. 그런데 `finish.js` 와 `ollama.js` 는 둘 다
`OLLAMA_HOST` 를 **모듈 적재 시점에** 읽고 ESM 은 모듈을 캐시한다 — 두 번째 스텁은 새 포트를
받지만 모듈은 **첫 포트를 계속 문다.** HTTP 500 을 검사한다고 적어 놓고 실제로는 **연결 거부**를
재고 있었다. 폴백이라는 결과가 같아 눈으로는 안 보였다.

`S17-G5` 가 같은 이유로 실패하면서 드러났다. 스텁 하나를 세워 두고 **행동만 바꾸는**
형태(`stub.set`)로 고쳤고, **정상 응답이 `llm` 을 내는 양성 대조**를 넣어 "이 스텁으로는 늘
폴백" 을 재는 상태를 막았다.

**`S17-G7` 도 자기 검사가 항등식이었다.** `applyFinish(...)` 두 번을 같은 인자로 불러 비교했으니
늘 참이다. 지금은 게이트가 **응답에서 직접** 재질 id 를 꺼내 적용한 결과와 대조한다 — 그 사이에
응답의 다른 필드가 끼어들 자리가 없다는 뜻이다.

## 다음에 할 일 — 17-B (화면·API 연결)

`server.js` `handleExpand` 에서 `selectFinishes` 를 부르고, 화면이 역할별 재질을 보여준다.
**결정해야 할 것이 하나 있다** — 재질 수치(base·metallic·roughness·emission)를 어떻게 줄 것인가.

기존 내보내기(`/api/export`)는 **저장된 2색 조합용**이고, 파생 팔레트 저장은 13단계가 이미
미뤄 뒀다. 그래서 내보내기가 자연스러운 집이 아니다. 남는 선택지 둘:

| | 응답 크기 | 화면 |
|---|---|---|
| (a) 서버가 재질 수치까지 계산해 내려보낸다 | 3.8KB → **약 12KB** (두 모드 × 8구조 × 3~4색) | 스와치마다 수치를 붙일 수 있다 |
| (b) 서버는 배정만 주고 화면은 재질 이름만 | 3.8KB → 약 4KB | 수치를 보려면 별도 동작이 필요하다 |

**사용자에게 물어서 정한다.** 어두운 모드 토글 때와 같은 자리다 — 응답에 무엇을 실을지는
"LLM 을 다시 부르지 않는다" 같은 제약과 얽혀 있어 임의로 정하지 않는다.

그리고 17-B 는 `mode` 와 같은 함정을 다시 만나게 된다. **재질 배정을 바꾸는 조작이 생기면
`/api/expand` 를 다시 부르게 되고, 그러면 `selectStructures` 가 다시 돌아 보이는 다섯이
바뀐다.** S15-G11 이 그 파라미터의 부활을 막고 있으니 같은 규율을 따라야 한다.

## 함정 기록

- **한 게이트 안에서 모듈 적재 시점 환경변수를 두 번 바꾸려 하지 마라.** ESM 모듈 캐시 때문에
  두 번째가 안 먹고, **결과가 우연히 같으면 게이트가 통과한다.** 스텁 하나를 세우고 행동만 바꾼다.
- **"안 바뀐다" 를 항등식으로 쓰지 마라.** 같은 식 둘을 비교하면 늘 참이다. 비교 대상 하나는
  **게이트가 독립적으로 만들어야** 한다.
- **폴백 기대값을 구현에서 가져오지 마라.** 이 저장소가 같은 부류로 세 번 지적받았다
  (`fallbackSelection()` · `METAL_MIN` · 그리고 이번에 미리 막은 `DEFAULT_FINISH_BY_ROLE`).
- **결과가 같아도 사유가 다르면 결함일 수 있다.** 틀린 진단은 사용자를 엉뚱한 곳으로 보낸다.
