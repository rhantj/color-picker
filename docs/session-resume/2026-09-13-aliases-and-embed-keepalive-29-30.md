## 29단계 (E2) — 사용자 말투가 별칭에 없으면 임베딩도 못 잡는다

### 무엇이 안 됐나

26단계 실측에서 "화면이 죽어 보여요" · "숨이 막혀요 화면이" 가 `dx-noisy` 로 갔다. 진단의 별칭은 BM25 색인과
임베딩 문장(`embedText` = 증상 + 별칭 + 처방) **둘 다**에 들어가므로, 별칭이 없으면 두 경로가 함께 못 잡는다.
Ollama 없이 돌리면 "숨이 막혀요 화면이" 는 `pair-02`(팔레트)를 1단계로 **거짓 확신**하기까지 했다 `[실측]`.

### 어떻게 했나

코드는 안 바꿨다. `data/diagnostics.json` 두 진단에 실제 말투를 더했다.

| 진단 | 더한 별칭 |
|---|---|
| `dx-flat-value` (밋밋하다 / 생기 없다) | 죽어 보인다 · 죽어 보여요 · 죽었다 · 생기 없어요 |
| `dx-stifling` (답답하다 / 갑갑하다) | 숨이 막혀요 · 숨 막혀요 · 숨막혀 · 막힌다 |

토크나이저가 띄어쓰기로 어절을 나누므로 "죽어 보여요" 는 `죽어` · `보여요` 두 어절이 통째로 맞는다. 어절 매치가
2 라 BM25 가 1단계에서 확신하고, 28단계의 "안 믿는다" 문턱(1 이하)에도 안 걸린다.

## 30단계 (E3) — 임베딩 2.2초 튐은 모델이 내려간 것이다

### 원인 `[실측]`

| 측정 | 값 |
|---|---|
| 웜 임베딩 | 36~83ms |
| 콜드 재적재(모델을 내린 뒤 첫 요청) | 1834 · 1855 · 2198ms |
| `keep_alive` 없는 요청으로 올린 모델의 만료 | 5분 (Ollama 기본값) |
| `keep_alive: "30m"` 으로 올린 모델의 만료 | 30분 |

`/api/embed` 요청에 `keep_alive` 가 없었다. 5분 뒤 `bge-m3` 가 GPU 에서 내려가고 다음 질의가 재적재를 치른다.
확신 경로의 예산은 700ms 라 그 한 번이 "제때 답하지 않았다" 로 떨어져 3단계를 건너뛴다. 채팅 모델은 `rewrite.js`
워밍업이 `keep_alive: "30m"` 을 보내 같은 문제가 없었다. 조사 도중 8초(저신뢰 예산) 시간 초과도 한 번 봤다 —
채팅 모델 5.2GB 가 GPU 에 있는 채로 재적재하던 순간이다. 같은 원인이다.

### 처방

`src/embed.js` 에 `EMBED_KEEP_ALIVE = "30m"` 을 두고 모든 `/api/embed` 본문에 실었다. 영구(`-1`)로 안 둔 이유는
GPU 8GB 를 다른 일과 나눠 쓰기 때문이고, 채팅 모델과 같은 값에 맞췄다.

### 게이트 (실측)

| 게이트 | 무엇 | 구현 전 | 구현 후 |
|---|---|---|---|
| S30-G1 | 모든 임베딩 요청(배치 1 · 낱개 2)에 사본값 `keep_alive` (스텁) | `undefined` 3건 | OK |
| S30-G2 | 내린 뒤 서버 준비로 올리면 `/api/ps` 만료 ≥ 25분 (실제 Ollama) | **5분** | **30분** |
| S30-G3 | 콜드 ≥ 웜 3배 (원인의 양성 대조) · 준비 뒤 확신 질의 5건 예산 안 | 통과 (원인을 잰다) | 콜드 1834 · 웜 41 |
| S30-G4 | 26단계 회귀 7개 | 통과 | OK |

### 게이트가 두 번 헛돌았다

- **G2 가 구현 전에 통과했다.** Ollama 는 **올릴 때의** `keep_alive` 를 기억한다 `[실측]` — 조사 스크립트가 30분으로
  올려 둔 모델에 값 없는 요청을 보내도 만료가 안 짧아진다. 먼저 내리고 서버 준비가 올리게 고쳤더니 구현 전 5분,
  구현 후 30분.
- **G3 의 콜드가 51ms 였다.** `keep_alive: 0` 은 비동기라 바로 다음 요청이 옛 러너를 탄다 `[실측]`. `/api/ps` 에서
  사라질 때까지 기다린 뒤 재게 고쳤다.

27·28단계와 같은 교훈이다 — **창을 재려면 창이 실제로 열려 있어야 하고, 그것은 실측으로만 안다.**
