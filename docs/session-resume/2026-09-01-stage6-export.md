# 2026-09-01 — 6단계: 내보내기 (CSS 변수 / JSON)

[폰트 자립 문서](2026-09-01-local-fonts.md) 다음. 초안이 약속한 세 기능 중 두 번째.

## 바뀌기 전에는 무엇이 있었나

색을 찾고, 비율을 맞추고, 저장까지 할 수 있는데 **가져갈 방법이 없었다.** 저장 화면 초안에 버튼만
있고 동작하지 않았다. 도구에 출구가 없었던 셈이다.

## 형식이 이 기능의 전부다

헥스 두 개만 내보내면 이 사이트가 계속 말해온 것을 잃는다 — **면적과 서열**이다.
"같은 두 헥스도 비율이 바뀌면 다른 색" 이라고 해 놓고 비율 없이 내보내면 앞뒤가 안 맞는다.

```css
  /* 살구 × 파랑 · D형 · 보색 / 톤 비대칭
     면적 75% : 25% (직접 조정함)
     메모: 확정 버튼에만 파랑 */
  --pair-10-ground: #FDD4BD; /* 살구 · 바탕 */
  --pair-10-ground-area: 75%;
  --pair-10-accent: #006EB8; /* 파랑 · 강조 */
  --pair-10-accent-area: 25%;
```

결정 셋:

- **역할은 코퍼스의 유형이 아니라 지금 이 항목의 비율에서 계산한다.** 대등 조합(50:50)은
  `tone-1`/`tone-2`, 사용자가 60:40 으로 조정하면 그때부터 `ground`/`accent` 다 — 서열이 생겼으니까.
- **면적도 변수로 낸다.** `width: var(--pair-10-ground-area)` 로 꽂아 쓸 수 있어야 "면적이 색의 일부"
  라는 말이 코드에서도 성립한다.
- **형식은 서버가 만든다.** 화면이 문자열을 조립하면 곧 서버 형식과 갈라진다.

CSS 변수 이름은 조합 id 로 짓는다. 한글은 CSS 식별자로 쓸 수는 있지만 도구 체인마다 처리가 달라
주석에만 남긴다.

| 파일 | 무엇 |
|---|---|
| `src/export.js` | **신규.** `rolesOf` · `safeComment` · `toCss` · `toJson` · `FORMATS` |
| `server.js` | `GET /api/export?format=css\|json`, 요청 예외 격리 |
| `public/saved.{html,js}` | 버튼·결과 패널·복사·파일 저장 |
| `scripts/check-stage6.mjs` | **신규.** S6-G1~G7 |

## 게이트가 못 보는 것을 브라우저로 봤다

`S6-G3` 은 CSS 구조(중괄호·세미콜론·식별자)만 센다. 진짜 파싱되는지는 브라우저에서 확인했다 —
`new CSSStyleSheet().replaceSync()` 로 오류 없이 파싱되고, 변수 8개가 선언되고,
`--pair-10-ground` → `rgb(253,212,189)`, `--pair-10-ground-area`(75%)를 폭에 꽂으니 1080px
(1440 의 75%)로 적용됐다.

## 코드 리뷰 (격리 복사본) — **BLOCK** 판정

Critical 1 / High 1 / Medium 1. 셋 다 반영:

### [Critical] 인증 없는 GET 한 번으로 서버 프로세스가 죽었다

`FORMATS[format]` 이 일반 객체 리터럴이라 `format=__proto__` · `constructor` 같은 이름이
**프로토타입 체인에서 값을 내준다.** `!spec` 검사를 통과하고 `spec.build` 가 없어 던지는데,
Node 의 http 서버는 핸들러의 동기 예외를 `uncaughtException` 으로 올려 보내 **프로세스를 끝낸다.**

재현했다:
```
GET /api/export?format=__proto__  →  연결 끊김, 프로세스 종료
TypeError: spec.build is not a function
```
`/api/export` 는 GET 이라 CSRF 가드를 안 거친다(읽기라서 의도). 그 대가로 아무 웹페이지의
`<img src="http://127.0.0.1:4173/api/export?format=__proto__">` 한 줄로도 서버를 내릴 수 있었다.

**두 겹으로 고쳤다:**
1. `Object.hasOwn(FORMATS, format)` — 요청 문자열로 객체를 조회할 때는 **자기 속성인지** 먼저 본다.
2. **요청 처리 전체를 try/catch 로 감싸 500 으로 격리한다.** 개별 결함을 고치는 것과 별개로,
   요청 하나가 서버 전체를 내리는 구조를 남겨 두지 않는다. 비동기 핸들러의 거부도 같은 자리에서 받는다.

뮤테이션으로 두 겹이 독립임을 확인했다 — `hasOwn` 만 빼면 500(서버 생존), 격리까지 빼면 서버가 죽는다.

### [High] 메모가 CSS 주석을 조기에 닫았다

메모에 주석 닫는 기호가 들어가면 그 뒤가 CSS 선언으로 해석된다. 악의가 없어도
"이 색은 /* 살구 */ 느낌" 같은 메모 한 줄이면 내보낸 파일이 깨진다. 더 나쁜 것은 **이 출력의 용도가
다른 프로젝트의 스타일시트에 붙여넣는 것**이라, 깨진 CSS 가 다른 신뢰 경계로 그대로 옮겨 간다는 점이다.

`safeComment()` 로 주석에 들어가는 모든 자유 텍스트를 손질한다. 보이지 않는 문자를 끼워 넣는 대신
`* /` 로 **눈에 보이게** 바꾼다 — 사용자가 자기 메모가 손질됐다는 것을 알아야 한다.

### [Medium] `aria-live` 가 코드 블록 전체를 감쌌다

형식을 바꿀 때마다 스크린리더가 내보낸 CSS/JSON **전문을 처음부터 다시 읽었다.**
`aria-live` 를 제목·안내문으로 좁히고, 패널은 `aria-labelledby` 로 이름만 준다.

## 부끄러운 것 둘

- **고치려던 결함을 문서에서 저질렀다.** `safeComment` 의 JSDoc 안에 주석 닫는 기호를 그대로 적어서
  주석이 조기에 닫히고 `export.js` 가 파싱되지 않았다. 설명하려던 바로 그 함정이었다.
- **python 치환이 파일을 세 번 깨뜨렸다.** 이번엔 `"\n"` 이 실제 개행으로 들어가 문자열 리터럴이
  두 줄로 쪼개졌고(`saved.js` 통째로 죽음), 정규식 문자 클래스에 제어문자가 리터럴로 박혔다.
  `node --check` 는 둘 다 통과시켰고 **브라우저 콘솔이 잡았다.**

> **이스케이프·유니코드가 섞인 JS 패치는 python 치환으로 하지 않는다.** Node 스크립트로 조립하거나
> 파일을 통째로 다시 쓴다. 그리고 고친 뒤에는 반드시 `import()` 로 파싱을 확인한다.
