## 무엇을 했나

### 1. 끊긴 곳은 한 군데였다

메모(`note`)는 스키마(`store.js`)·표시(`saved.js`)·내보내기(`export.js` 두 형식)가 **이미 다 돼
있었고**, 홈의 저장 요청만 `note` 를 안 실었다. 그래서 항상 빈 값이었다.

```
[홈] app.js save()   -> paletteId, fromQuery, ratio 만        <- 여기만 끊김
[서버] server.js:238 -> savePalette(body, ...)                   그대로 통과
[저장] store.js      -> note: clip(input.note, 200)              준비돼 있었음
[화면] saved.js:25   -> entry.note 렌더                          준비돼 있었음
[내보내기] export.js -> CSS 주석 · JSON 필드                     준비돼 있었음
```

결과 카드에 `input` 을 달고 저장할 때 함께 보낸다. **비어 있으면 아예 안 보낸다** — 빈 값은 서버가
"지우기" 로 읽기 때문이다.

### 2. 이어붙이면서 드러난 것 셋

**재저장 유실.** `savePalette` 가 비율은 이어받는데 메모는 안 이어받았다. 입력 칸이 없을 때는
드러나지 않던 결함이다. 세션 요약의 학습 1번(`ratioAdjusted` 를 만들고 안 읽어 데이터를 잃음)과
정확히 같은 부류라 같은 묶음으로 처리했다.

**겹친 저장.** 병합 기준(`previous`)을 `serialize` 큐 **밖**에서 읽고 있었다. 겹친 요청 둘이 모두
상대의 쓰기 전 스냅샷을 보고 항목을 만들어, 나중에 쓰는 쪽이 앞의 것을 덮었다. `serialize` 가 쓰기를
순서화해도 소용없다 — **무엇을 이어받을지가 이미 낡은 값으로 정해져 있기 때문이다.**

**중복 전송.** 버튼을 다시 여는 자리가 둘(메모 입력·비율 변경)인데 한쪽에만 가드가 있었다.
`reopen` 헬퍼로 합쳤다.

### 3. safeComment 순서 결함 (별도 커밋)

별표와 빗금 사이에 제어문자가 끼면 주석 닫기 방어가 매치하지 않고 통과시키는데, **그 다음 단계가
제어문자를 지우며 주석 닫기를 다시 만들었다.** 방어가 끝난 자리에서 방어 대상이 재조립된다.

수정 전에는 `별표 + U+0001 + 빗금` 을 넣으면 손질 결과에 리터럴 주석 닫기가 그대로 남았다.
내보낸 CSS 에서 주석이 조기 종료되고 `@import` 가 살아 있는 선언으로 삽입되는 것까지 재현했다.

**지금까지 도달 불가능한 경로였다** — `note` 는 늘 비었고 나머지 필드는 코퍼스 고정값이다.
메모 입력이 그것을 처음 살렸다.

## 왜 그렇게 했나 (버린 대안)

**메모 입력 위치 — 저장 화면 편집은 버렸다.** `/api/saved/note` 엔드포인트가 새로 필요하고 게이트도
늘어난다. 홈에서 저장할 때만 쓰는 쪽이 범위가 닫힌다. 대신 **홈에서는 메모를 지울 수 없다** — 그
길은 저장 화면 편집과 함께 열린다.

**safeComment — 화이트리스트를 버렸다.** 모든 벡터에서 안전하지만 정상 별표·빗금·이모지까지 조용히
지운다. 이 파일이 스스로 세운 원칙("눈에 보이게 바꿔야 사용자가 손질됐다는 것을 안다")과 정면으로
충돌한다. 순서 교체 + 불변식 검사를 골랐다.

**중복 전송 — `if (pending) return;` 한 줄을 버렸다.** 그러면 `ratio = next` 가 안 돌아 **비율 변경
자체가 버려진다.** 고치려던 결함을 비율 쪽에 복제하는 셈이다. 값은 항상 받고 **여는 것만** 미루는
구조로 만들었다.

## 이 세션이 배운 것

### 게이트가 헛돈 이유는 판정 로직이 아니라 페이로드였다

S6-G7(메모의 CSS 주석 주입 방어)은 주석을 걷어낸 뒤 잔여물을 세고 중괄호 균형까지 보는 **튼튼한
판정 로직**을 갖고 있었다. 그런데 페이로드가 리터럴 주석 닫기 하나뿐이라, 손질 함수가 **정확히 잡는
케이스만** 시험하고 있었다. 페이로드를 다섯으로 늘리자 넷이 잡혔다.

**"51/51 통과" 가 이 결함에 대해 아무 증거가 아니었다.** 애초에 그 입력을 넣지 않았기 때문이다.
