# 2026-09-07 — 새로고침해도 어두운 모드가 남는다 (23단계 · A4)

## 무엇이 안 됐나

어두운 배경으로 배색을 보다가 **새로고침하면 매번 다시 눌러야 했다.** 검색을 다시 하거나
다른 씨앗을 보러 갔다 오면 늘 밝은 모드로 돌아왔다.

## 이건 이미 내려진 결정을 뒤집는 일이었다

`public/app.js` 에 이렇게 적혀 있었다:

> **모드 상태는 이 영역 클로저 안에만 있다.** 전역이나 `localStorage` 에 두지 않는다 —
> 카드마다 다른 모드로 나란히 비교할 수 있고, 이 저장소에 없던 저장 계층을 들이지도 않는다.

그래서 그냥 고치지 않고 **그 결정이 무엇을 지키고 있었는지**부터 봤다. 두 가지였다.

| 원래 결정이 지키던 것 | 어떻게 했나 |
|---|---|
| **카드마다 다른 모드로 나란히 비교** | **그대로 살렸다.** `mode` 는 여전히 펼침 영역 클로저 안에 있다 |
| **저장 계층을 안 들인다** | **뒤집었다.** 기본 모드 **하나**만 기억한다 |

앞의 것이 그 결정의 진짜 값이고, 뒤의 것은 값이라기보다 **아직 필요가 없어서** 안 한 것이었다.
필요가 생겼으니 뒤쪽만 뒤집는다.

```
새로 펼치는 카드   → 저장된 모드로 시작
그 뒤로            → 카드마다 따로 토글할 수 있다
마지막으로 고른 것  → 다음번 기본이 된다
```

**별도의 "이 모드를 기본으로" 버튼은 안 만들었다.** 그러면 두 번 눌러야 한다.
사용자가 어두운 모드로 바꿨다는 것이 곧 "요즘 어두운 걸 본다" 는 뜻이다.

## 이 저장소의 첫 `localStorage` 다 — 문을 좁게 열었다

한번 들이면 다음 것(비율? 재질? 마지막 질의?)도 거기 들어가기 쉬워진다. 그래서 규칙을
같이 세웠다.

| 규칙 | 왜 |
|---|---|
| 저장을 만지는 자리가 **한 곳뿐** (`modeStore`) | 흩어지면 어느 값이 어디 저장됐는지 아무도 모르게 되고, 그때는 되돌릴 수도 없다. `S23-G6` 이 화면 다섯 개를 훑어 확인한다 |
| **접근 자체를 감싼다** | 시크릿 창·사이트 데이터 차단에서 `localStorage` 는 **읽기만 해도 던진다.** 안 감싸면 **홈 화면이 통째로 안 뜬다** — 모드를 기억하자고 화면을 잃는 것은 말이 안 된다 |
| **쓰기가 막혀도 토글은 된다** | 저장은 편의이고 토글은 기능이다 |
| **저장값을 안 믿는다** | 개발자 도구로 아무 값이나 넣을 수 있고 같은 오리진의 다른 코드가 덮어쓸 수도 있다. 믿으면 `mode` 가 `"purple"` 이 되어 파생 계산이 어디서 터질지 모른다 |
| 이름을 나눈다 (`tonefirst:mode`) | 같은 오리진의 다른 것과 안 부딪치게 |

## 버튼이 거짓말할 뻔했다

전에는 늘 밝은 모드로 시작해서 버튼 글자를 **`"어두운 배경으로 보기"` 로 박아** 뒀다.
저장된 모드로 시작하게 되면 **어두운 모드에서 그것이 거짓말이 된다** — 이미 어두운데
어둡게 보자고 한다.

칠하는 일을 `applyModeButton` 한 곳으로 모았다. 만들 때와 누를 때가 같은 함수를 쓴다.

**그리고 리뷰가 더 깊은 모순을 찾았다** — `aria-pressed` 자체가 이 버튼에 안 맞았다.
아래 리뷰 절을 본다.

## 게이트 (실측)

**`S22-G6` 이 곧바로 일을 했다.** 23단계 여섯 개를 더했는데 문서가 176 에 멈춰 있는 것을
회귀 실행에서 잡았다 — 어제 만든 게이트가 하루 만에 값을 했다.

### 뮤테이션 18개 — 처음에 둘이 살아남았고 둘 다 게이트를 고쳤다

**① 기본 저장소 접근의 감싸기를 빼도 안 잡혔다.**

게이트가 늘 **가짜 저장소를 넘겨 주고 있어서** 기본 경로(`globalThis.localStorage`)를
한 번도 안 밟았다. 그런데 실제 사용자는 인자를 안 넘긴다 — **게이트가 시험하지 않는 길로만
다니는 셈**이었다.

`globalThis.localStorage` 를 던지는 getter 로 바꿔 놓고 인자 없이 부르는 검사를 더했다.

> **주입할 수 있게 만들면 기본값 경로가 시험에서 빠지기 쉽다.** 주입은 시험을 위한
> 것인데, 그것 때문에 진짜 경로를 안 보게 되면 뒤집힌 것이다.

**② 버튼에 처음 칠하는 호출을 지워도 안 잡혔다.**

정적 검사는 "처음에 칠했는가" 를 못 본다. 칠하는 일을 `applyModeButton` 으로 빼고
게이트가 **가짜 버튼에 직접 칠해 본다.** 21·22단계와 같은 처방이다 — 세 번째다.

## 격리 리뷰 두 건 — Critical 0 · High 1 · Medium 1

일반 리뷰가 **Approve** 를 냈고, 결정 뒤집기가 정직하게 기록됐는지도 따로 확인해 줬다
(*"이 저장소 자신의 기준보다 낫다"*). 다만 접근성에서 **15단계부터 있던 모순**을 찾았다.

### High — 저장 순서를 틀려도 아무 게이트가 안 잡았다

TS 리뷰가 화면의 두 줄을 맞바꿨다.

```js
mode = modeToggle(mode).next;   // 먼저 바꾸고
modes.write(mode);              // 그다음 저장       ← 이 둘을 맞바꾸면
```

**옛 모드가 저장된다.** 그런데 그 고장은 **그 자리에서 안 보인다** — 버튼도 색도 새 모드로
제대로 바뀐다. **새로고침해야 드러난다**: 어둡게 바꿔 놓고 다시 열면 밝은 모드다.
**23단계가 하려던 일이 통째로 무효인데 아무 신호가 없다.** 여섯 게이트가 전부 통과했다.

**22단계에 적어 둔 조건이 충족됐다.** 거기서 배선을 정적 검사로만 두면서
*"판단이 바뀔 조건: 이 배선이 눈에 안 보이는 것을 바꾸게 될 때"* 라고 적었다. 바로 그 경우다.

**정적 검사로 순서를 재려 하지 않았다.** 그건 표기를 지키는 것이지 동작을 지키는 것이 아니고,
이 저장소가 그것으로 세 번 뚫렸다. **틀릴 순서 자체를 없앴다** — `nextMode(store, current)`
가 뒤집기와 저장을 한 동작으로 묶고, 게이트가 그것을 직접 불러 **돌려준 값과 저장된 값이
같은지**를 본다.

> 22단계에서 이름표를 인자로 바꾼 것과 같은 처방이다. **게이트를 하나 더 만드는 것보다
> 틀릴 수 없게 만드는 것이 낫다** — 두 번째 사례다.

### Medium — `aria-pressed` 와 갈 곳 라벨은 함께 쓸 수 없다

`aria-pressed` 는 **버튼 이름이 가리키는 것이 켜져 있다**는 뜻이다. 그런데 이 버튼의
이름(=보이는 글자)은 **갈 곳**을 말한다. 어두운 모드일 때 둘을 합치면 화면을 못 보는
사람에게 이렇게 읽힌다:

```
"밝은 배경으로 보기, 버튼, 눌림"   →  밝은 배경이 켜져 있다는 뜻이 된다. 거꾸로다.
```

**눈으로 보는 사람은 이 모순을 못 만난다** — CSS 가 `aria-pressed` 를 그냥 상태 훅으로만
써서 채워진 사각형을 보이기 때문이다. 화면을 못 보는 사람에게만 거꾸로 들린다.

### 왜 이름을 고정하지 않았나

`aria-pressed` 를 살리려면 이름을 고정값(`"어두운 배경"`)으로 바꿔야 한다. 그러면
**보이는 글자와 이름이 달라진다** — 음성으로 조작하는 사람은 눈에 보이는 대로 말해서
버튼을 누르므로 그 방법이 막힌다(WCAG 2.5.3 Label in Name).

그래서 **20단계 엔진 토글과 같은 방식**으로 갔다.

```
보이는 글자:  밝은 배경으로 보기
읽어 주는 말: 지금 어두운 배경 · 밝은 배경으로 보기      ← 보이는 글자를 그대로 담는다
```

**이제 이 앱의 두 토글이 서로 같다.** 리뷰가 그 어긋남도 함께 짚었다.

### 20단계에 적어 둔 근거가 틀렸다

거기에 *"15단계 모드 토글은 `aria-pressed` 를 쓰지만 거기는 이진 상태라 맞다"* 고 적었다.
**틀렸다** — 그 버튼도 라벨이 갈 곳을 말하므로 같은 모순이 난다. 이진 상태냐 아니냐가
아니라 **이름이 무엇을 가리키느냐**가 갈림길이었다. 그 주석도 고쳤다.

### 눈으로 보는 상태 표시는 `data-mode` 로 옮겼다

`aria-pressed` 를 걷어내면 CSS 훅이 사라진다. **색만으로 상태를 알리지 않는다**는 규칙이
거기 걸려 있었으므로(채워진 사각형) `data-mode` 로 옮기고, `S23-G4` 가 **두 규칙을 따로**
본다 — 하나만 보면 테두리 색만 바뀌고 사각형이 안 채워지는 절반 고장이 통과한다.

```
어두운 모드:  data-mode="dark"  · 사각형 채워짐 · 테두리 강조색
밝은 모드:    data-mode="light" · 사각형 비어 있음
```

### 리뷰 뒤 뮤테이션 10개 전부 잡힘

접근성 6개 — `aria-pressed` 되살리기 · 읽어 주는 말이 갈 곳만 말하기 · 보이는 글자를 안 담기 ·
버튼에 안 붙이기 · `data-mode` 안 붙이기 · CSS 두 규칙 각각.

저장 순서 4개 — **옛 모드 저장(리뷰가 찾은 것)** · 저장 안 하기 · 돌려주는 값과 저장하는 값
다르게 하기 · 화면이 저장을 직접 불러 순서를 되살리기.

**게이트 자신도 두 번 틀렸다.** `nextMode` 에 가짜 저장소를 그대로 넘겨서(그 함수는
`modeStore` 가 만든 것을 받는다) 거짓 실패가 났고, 화면이 `modeToggle` 을 안 부르게 되면서
낡은 검사가 하나 남아 있었다.

### 문제없다고 확인된 것

- **저장 범위.** `localStorage`·`sessionStorage`·`indexedDB`·`document.cookie` 를 통틀어
  화면에 단 한 곳뿐이고, 저장하는 값은 두 가지짜리 열거형이다. 사용자 글이나 신원과
  무관하므로 별도 고지는 과하다고 판정했다.
- **카드별 어긋남이 실제로 산다.** `mode` 가 여전히 펼침 영역 안에 선언돼 있고,
  `redraw` 가 저장소를 다시 읽지 않고 그 변수를 그대로 쓴다.
- **결정 뒤집기가 네 곳(옛 주석·새 주석·`GATES.md`·세션 재개 문서)에 같은 내용으로 남았다.**
