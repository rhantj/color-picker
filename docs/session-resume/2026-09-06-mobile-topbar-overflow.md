# 2026-09-06 — 모바일(375px) 상단바 가로 넘침

[GitHub 공개 발행](2026-09-06-github-publish.md) 다음. 코드 변경은 `public/app.css` 한 파일, 29줄 추가뿐이다.

## 바뀌기 전에는 무엇이 있었나

상단바는 폭에 상관없이 **한 줄 고정 64px** 이었다.

```
.topbar        display:flex · justify-content:space-between · height:64px · padding:0 var(--gutter)
  .topbar__left  워드마크(톤먼저 + TONEFIRST) + 메뉴(홈 · 대화 내역 · 추천 받은 조합)
  .runtime       상태 배지 (점 + BM25 + "로컬 · Ollama 준비됨")
```

`--gutter` 는 1100px 이하에서 32px 로 줄지만, 그게 좁은 화면을 위해 준비된 유일한 장치였다.
상단바 자체에는 `@media (max-width: 620px)` 규칙이 **없었다.**

## 왜 바꾸는가

375px 에서 한 줄에 필요한 폭과 실제로 쓸 수 있는 폭이 이렇게 어긋난다.

| | 폭 |
|---|---|
| 워드마크 136.3 + 간격 40 + 메뉴 205.5 | 381.8 |
| 상태 배지 | 190.1 |
| **필요** | **571.9** |
| **가능** (375 − 좌우 여백 64) | **311** |

260px 이 모자란다. flex 는 이럴 때 **모두를 눌러 담는다.** 그래서 한 가지가 아니라
세 가지가 동시에 깨져 있었다 — 다만 눈에 띄는 것은 마지막 하나뿐이었다.

1. **상태 배지가 뷰포트를 4px 넘는다.** `documentElement.scrollWidth` 379 vs `clientWidth` 375.
   배지가 min-content(121.5px)까지 눌렸는데도 그 아래로는 못 줄어서 그대로 밖으로 나갔다.
2. **배지 안 문구가 배지 밖으로 샌다.** `.runtime__where` 가 3줄 51px 이 되는데
   필은 `height: 32px` 고정이라, 문구가 위아래로 필을 뚫고 나왔다 (문구 6~57 vs 필 15.5~47.5).
3. **워드마크가 세로로 쪼개진다.** `.wordmark__ko` 가 min-content 까지 눌려
   "톤먼저" 가 한 글자씩 3줄(w 34.1 · h 72)로 분해됐다.

즉 보고된 4px 넘침은 **원인이 아니라 증상**이다. 원인은 "안 들어가는 것을 한 줄에 넣으려는 것"
하나이고, 넘침·샘·쪼개짐은 그 한 원인이 세 군데로 터져 나온 것이다.
4px 만 없애는 수선(배지 숨기기·간격 줄이기)은 2·3번을 그대로 남긴다.

## 어떤 원리를 쓰는가

flex 에게 **누를 것인지 나눌 것인지**를 정해 준다.

- 누른다(`flex-shrink`, 기본값) → 항목이 min-content 까지 찌그러지고, 그보다 작아질 수 없으면 넘친다.
- 나눈다(`flex-wrap: wrap`) → 안 들어가는 항목이 다음 줄로 내려가고 **아무것도 안 찌그러진다.**

좁은 화면에서 상단바가 원하는 것은 후자다. 다만 그냥 `flex-wrap: wrap` 만 켜면
`.topbar__left` 가 워드마크와 메뉴를 한 덩어리로 묶고 있어 셋이 세 줄(워드마크 / 메뉴 / 배지)로
흩어진다. 그래서 좁은 화면에서만 `display: contents` 로 그 묶음을 풀어,
워드마크·메뉴·배지가 각자 `.topbar` 의 flex 항목이 되게 한 뒤 `order` 로 메뉴만 아랫줄로 보낸다.

```
1줄   톤먼저 ──────────────────────── ( ● BM25  로컬 · Ollama 준비됨 )
2줄   홈   대화 내역   추천 받은 조합
      ‾‾
```

## 그래서 코드가 이렇게 된다

`public/app.css` 에 **상단바 전용 `@media (max-width: 700px)` 블록**을 새로 만들었다.
처음에는 기존 `@media (max-width: 620px)` 블록에 넣었는데, 그러면 621~636px 구간이
고쳐지지 않은 채 남는다 — 왜 620 이 아닌지는 아래 "브레이크포인트를 700 으로 정한 이유"에 있다.

| 규칙 | 왜 |
|---|---|
| `.topbar { height:auto; flex-wrap:wrap; row-gap:12px; padding:12px var(--gutter) }` | 누르지 말고 나눈다. 높이 고정을 풀어야 둘째 줄이 잘리지 않는다 |
| `.topbar__left { display:contents }` | 워드마크와 메뉴 묶음을 풀어 메뉴만 따로 내린다 |
| `.nav { order:1; width:100% }` | 메뉴를 항상 아랫줄 전폭으로 |
| `.wordmark__en { display:none }` | 라틴 워드마크(TONEFIRST, 65.9px)를 두면 1줄이 326px 이 되어 배지가 또 밀린다 |
| `.nav__item[aria-current="page"] { padding-bottom:4px; margin-bottom:0 }` | 아래 참조 |

새 색은 만들지 않았다. 색 선언 자체가 없다 (추가 29줄에 헥스·rgb·hsl·oklch 0건).

### 브레이크포인트를 700 으로 정한 이유

상단바는 **페이지가 아니라 자기 내용 폭**이 임계값을 정한다. 한 줄에 필요한 폭은

```
워드마크 136.3 + 간격 40 + 메뉴 205.5 + 배지 190.1 = 571.9
+ 좌우 여백 64 (--gutter 32 x 2)              = 635.9
```

실측으로 **636px 에서 메뉴 오른쪽 끝과 배지 왼쪽 끝 사이가 0.1px**까지 붙고, 그 아래로는
워드마크가 두 줄로 접힌다. 즉 한 줄 레이아웃의 물리적 하한이 636px 다.
좁은 화면 규칙이 모여 있는 620 에 맞추면 **621~636 구간이 두 규칙 사이에 끼어** 한 줄도
두 줄도 제대로 못 되는 채 남는다. 그래서 상단바만 자기 브레이크포인트를 갖는다.

700 은 하한 636 에 64px 을 얹은 값이다. 이 여유는 넉넉해서가 아니라 **필요해서**다 —
위 수치는 HYSinMyeongJo 가 설치된 기계의 값이고, 폴백 폰트가 잡히면 워드마크 폭이 달라진다.
경계에 딱 맞춘 브레이크포인트는 폰트가 다른 기계에서 조용히 깨진다.
701px 에서 메뉴와 배지 사이가 65.1px 로 벌어지고, 태블릿 세로(768px)는 한 줄로 남는다.

### 현재 페이지 밑줄을 되돌린 이유

`.nav__item[aria-current="page"]` 는 원래 `padding-bottom: 21px; margin-bottom: -22px` 다.
항목을 상단바 바닥까지 늘려 **밑줄이 상단바 아래 테두리 위에 정확히 얹히게** 하는 장치다.
메뉴가 아랫줄로 내려오면 그 테두리가 항목 바로 밑에 없으므로, 늘려 놓은 21px 이
허공에 밑줄을 띄운다. 좁은 화면에서만 평범한 밑줄(4px)로 되돌린다.

**`.wordmark__en` 을 숨긴 것을 되돌리지 않는 이유.** 대안은 `.sr-only` 유틸리티를 새로 만들어
화면에서만 지우는 것인데, 두 번째 a11y 리뷰가 짚었듯 `.sr-only` 는 *"스크린리더에는 남기고
화면에서만 지울 때"* 쓰는 도구다. 여기서 지우려는 것은 **"톤먼저" 의 표음 중복 표기**이고
시각·비시각 사용자 모두에게 똑같이 지우는 것이 의도다. 없는 유틸리티를 장식용 중복 문자열
하나 때문에 새로 들이는 것은 이 저장소의 "범위 밖 추상화 금지" 에 어긋난다.

**`order` 불일치를 고치지 않는 이유.** 두 번째 a11y 리뷰가 명확히 답했다 —
`<nav>` 를 마크업에서 배지 뒤로 옮기고 데스크톱에서 `order` 로 되돌리는 방식은
**불일치를 없애는 것이 아니라 데스크톱으로 옮기는 것**이다. 모바일이 원하는 시각 순서와
데스크톱이 원하는 시각 순서가 다르므로 단일 DOM 순서로 둘 다 만족시킬 수 없다.
Grid `grid-area` 를 써도 같다. 지금은 배지에 포커스 가능한 요소가 0개라 실제 영향이 없다 —
**배지 안에 버튼(새로고침 등)을 넣게 되면 그때 다시 봐야 한다.**

**상태 문구 길이를 지금 막지 않는 이유.** `flex-wrap` 이 이미 안전판이다. 문구가 길어져
1줄에 안 들어가면 배지가 **셋째 줄로 내려갈 뿐 다시 찌그러지지 않는다** — 눌러 담기가
줄 나누기로 바뀐 것이 이번 변경의 요지다. 320px 에서 가장 긴 라벨("로컬 · Ollama 기동 중",
193.5px)로 1줄이 255.8 vs 256 이라 아슬아슬한데, 넘치더라도 결과는 3줄 배치이지 넘침이 아니다.

## 덧붙임 — 621~636px 구간까지 고쳤다 (같은 세션, 리뷰 뒤)

첫 수정은 상단바 규칙을 기존 `@media (max-width: 620px)` 블록에 넣었고, 그 결과
**621~636px 구간이 그대로 남았다**(한 줄 하한 636 과 두 줄 시작 620 사이). 위 "브레이크포인트를
700 으로 정한 이유" 대로 상단바 규칙만 `@media (max-width: 700px)` 로 분리해 그 구간을 닫았다.

- 규칙 자체는 한 줄도 바뀌지 않았다. **어느 블록에 있느냐만 바뀌었다.**
- 실측: 621 · 636 · 700 → 두 줄 113px, `.wordmark__ko` 24px(한 줄), 넘침 0.
  701 → 한 줄 64px 복귀, TONEFIRST 보임, 메뉴↔배지 65.1px.
- 게이트 S2 8/8 재통과.
