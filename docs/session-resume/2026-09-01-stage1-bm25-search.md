## 왜 그렇게 했나

### 한국어를 형태소 분석기 없이 색인하는 법

한글 어절은 조사·어미가 붙어 표면형이 계속 바뀐다("따뜻한 / 따뜻하고 / 따뜻함"). 어절을 통째로만
색인하면 이 셋이 서로 다른 항이 되어 매칭이 끊긴다. 그래서 **어절 전체 + 문자 2-gram** 을 함께 낸다.

**버린 대안:** 형태소 분석기(konlpy·mecab) — 의존성 0 조건에 걸린다. 어절만 색인 — 활용형이 다르면
매칭이 통째로 끊긴다. 2-gram 만 색인 — 정확 매칭에 가중치를 몰아줄 수 없다.

### 2-gram 가중치를 0.3 으로 낮춘 이유 (실측)

2-gram 은 어간뿐 아니라 **어미·조사 조각**(`않게` `인데` `보여`)도 그대로 만든다.
`"대시보드가 탁해 보여요"` 가 **`보여` 하나로** 아이보리×연하늘을 1위(2.50점)로 올렸다.
가중치를 0.3 으로 내리자 같은 질의가 1.12점으로 떨어지고, 정상 질의(6.9~18.9)와 깨끗하게 갈렸다.

부작용: BM25 의 `tf` 가 정수가 아니라 실수 가중합이 된다. BM25 식 자체는 실수 tf 에서도 그대로
성립하므로 문제없다(리뷰에서 확인).

### `wholeMatches` — 단계 승급 트리거

매칭된 항 중 **어절 전체로 겹친 것**이 하나도 없으면 어미 조각만 맞은 것이다. 점수는 나오지만 근거가
없다. 이걸 `wholeMatches === 0` 으로 판정해 "전문 검색이 못 잡았다"고 선언한다.
`docs/com/rag-is-simpler-than-you-think.md` 가 말하는 **2단계(질의 재작성) 승급 조건**이 이것이다.

## 지금 상태

### 검색 기준선 (실측)

| 질의 | 1위 | 점수 |
|---|---|---|
| 따뜻한데 촌스럽지 않은 오래된 목조 부엌 같은 색 | 앰버 × 커피브라운 ✓ | 8.65 |
| 병원 앱인데 차갑지 않게 | 살구 × 파랑 ✓ | 6.93 |
| 느와르 포스터 만들건데 고급스러운 빨강 | 빨강 × 흑록 ✓ | 18.88 |
| 청량한 여름 화장품 브랜드 | 아이보리 × 연하늘 ✓ | 9.94 |
| 신뢰감 주는 금융 앱 색 | 살구 × 파랑 ✓ | 8.81 |
| 대시보드가 탁해 보여요 | **못 잡음** | 1.12 |
| 밤에 혼자 걷는 도시의 쓸쓸함 | 테라코타 × 회분홍 (논쟁 여지) | 7.11 |

게이트 4개 전부 통과. 기대값을 틀리게 바꾸거나 `BIGRAM_WEIGHT` 를 1.0 으로 되돌리면 실제로 FAIL 로
떨어지는 것을 확인했다 — 항상 통과하는 가짜 게이트가 아니다.

### 3단계 탐침 결과 — 질의 재작성이 값을 못 했다

`exaone3.5:7.8b` 를 받아 재작성을 미리 재봤다(구현 아님, 탐침만).

| 원 질의 | 1단계만 | 재작성 후 |
|---|---|---|
| 대시보드가 탁해 보여요 | 못 잡음 (1.12) | 코럴 × 미드나잇블루 4.06 — **고신뢰로 올라감** |
| 밤에 혼자 걷는 도시의 쓸쓸함 | 테라코타 × 회분홍 7.11 | **순위 변화 없음** |

**둘 다 나쁜 결과다.** 두 번째는 재작성이 아무것도 못 했고, 첫 번째는 더 나쁘다 —
"탁해 보인다"는 팔레트를 찾는 질문이 아니라 **진단 질문**이다(color-design 진단표: 명도 단계가
뭉쳐 있음 → 톤축). 코퍼스에 답이 없는데 재작성이 검색어를 그럴듯하게 만들어 **틀린 답을 자신 있게**
내놓게 했다. 저신뢰 판정이 오히려 정직했다.

**3단계 설계에 반영할 것:** 질의를 먼저 **의도로 분기**한다 — 팔레트 탐색 / 진단 / 그 외. 진단
질의를 팔레트 검색으로 라우팅하지 않는다. 문서의 "다중 의도 질의는 부질의로 쪼개 각각 최적 경로로
라우팅한다"가 정확히 이 지점이다.

**측정된 지연:** Ollama 첫 호출 **51초**(모델 메모리 적재), 이후 220~525ms. BM25 는 2.5~3ms.
화면에서 이 격차를 어떻게 보여줄지가 3단계의 실제 UX 문제다.

**프롬프트 문제:** exaone 이 `톤비대칭` 처럼 띄어쓰기를 붙여 내놔서 코퍼스 항 `톤 비대칭` 과 안 맞는다.

## 다음에 할 일

1. **2단계** — HTTP 서버 + 홈 화면. 착수 시 `createSearcher()` 를 모듈 스코프에서 1회만 부른다.
2. **3단계 재설계** — 위 탐침 결과대로 의도 분기를 먼저 넣는다. 재작성 프롬프트에 "코퍼스 항은
   띄어쓰기를 유지한다"를 넣는다. 모델 적재 51초를 어떻게 감출지 결정한다(서버 기동 시 워밍업 등).
3. **미결 질문** — `defaultRatio` 규칙(D형 70:30 / 대등 50:50)을 유지할지, 전부 50:50 에서 시작하고
   사용자가 조정하게 할지. 사용자 답변 대기 중.
