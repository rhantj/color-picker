## 어떻게 도는가

```
질의 → 팔레트 BM25 → 걸리면 끝            (LLM 안 부름)
     → 진단   BM25 → 걸리면 끝            (LLM 안 부름)
     → LLM 한 번   → 의도 분기 ┬ 팔레트 → 재검색
                              ├ 진단   → 진단표
                              └ 기타   → 못 잡음
```

**대부분의 질의가 1단계에서 끝난다** — 문서가 말한 "60% 는 전문 검색 + 재작성에서 종료" 와 같은 방향.
Ollama 가 없거나 죽어 있어도 검색은 그대로 동작한다(자동 기동을 시도하되 기다리지 않는다).

## 이 세션이 배운 것 (되풀이하지 말 것)

1. **필드를 만드는 것과 그 필드를 보는 것은 다르다.** `ratioAdjusted`·`defaultRatio` 를 조정 보존용으로
   만들어 놓고 정작 재저장 경로에서 안 읽어 데이터를 잃었다. 새 필드를 넣을 때는 **그 필드가 없으면
   무엇이 깨지는지**를 게이트로 적는다.
2. **함수가 존재한다 ≠ 불린다.** `warmUp` 이 `import` 만 되고 호출부가 없었는데, 나는 그걸 모른 채
   "워밍업으로 빨라졌다" 고 보고했다. 실제로는 앞선 실행으로 모델이 메모리에 남아 있었을 뿐이다.
3. **요청 하나가 서버를 죽이는 구조를 남기지 않는다.** `format=__proto__` 로 프로세스가 끝났다.
   개별 결함(`Object.hasOwn`)을 고치는 것과 별개로 요청 처리 전체를 try/catch 로 격리했다.
4. **코퍼스가 좋아지면 LLM 경로 게이트가 검사 대상을 잃는다.** 진단표를 늘리자 S3-G7 이 쓰던 질의가
   1단계에서 잡혀 LLM 이 아예 안 돌았다. 이제 그럴 때 명시적으로 실패한다.
5. **정적 게이트는 회귀 스모크지 보안 통제가 아니다.** 정규식으로 "무엇이 실행될지" 판정하는 것은
   원리적으로 불가능하다. 중요한 것은 행위 검사를 함께 둔다.

도구 자체의 함정(파일을 깨뜨린 패치 방식 등)은 `docs/troubleshootings/2026-09-01-tooling-traps.md`
에 따로 있다. **다음 세션은 그것부터 읽는 게 시간을 아낀다.**

## 열려 있는 것

**작은 것**
- 저장 메모 입력 칸. 서버는 이미 `note` 를 받고 내보내기에도 실리는데 화면에 입력이 없다.

**알려진 한계** (의도적으로 두고 감)
- 저신뢰 질의가 동시에 오면 LLM 을 각각 부른다(단일 비행 없음). 로컬 단일 사용자 전제.
- 대화·저장·내보내기가 무인증 GET 이다. 루프백 바인딩이 유일한 방어다.
- `LIMITS.saved`(200)는 중복 저장을 막아 코퍼스 크기(16)가 상한이라 도달 불가.
- 대화 경계가 세션이라 같은 대화를 두 탭에서 열면 각자 이어 쓴다(마지막 쓰기가 이긴다).
- 대화 확인 경합의 좁은 창은 게이트가 못 본다(정적 검사 + 코드 구조로 막음).

**새 방향 후보**
- 진단 결과에서 팔레트로 넘어가는 연결("그럼 어떤 조합?").
- 조합 비교 화면 — 두 조합을 나란히 놓고 면적을 바꿔 보기.
- 검색 3단계(하이브리드)는 **아직 필요 없다.** 문서 기준대로 실측이 요구할 때 올린다.
