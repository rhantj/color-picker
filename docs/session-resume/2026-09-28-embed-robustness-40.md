## 왜 그렇게 했나 (버린 대안)

- **H2 에서 700ms 빠른 길을 아예 없애기** — 버렸다(대표 결정으로 넘김). 26단계의 "확신 검색 1초 안" 약속을 뒤집는 일이다.
  대신 "어절 하나 확신"(28단계가 이미 "증거가 아니다" 로 본 것)만 기다리게 했다. 대가: "아침에 빵 굽는 냄새가 나는 카페" 는
  어절 **둘**("냄새가"·"나는")로 틀리게 확신해서 여전히 700ms 길을 탄다(리뷰 P1이 잡았다 — 처음엔 이 질의를 고친 예로 잘못 적었다).
- **H4 에서 코사인 차이(1위−2위)로 거르기** — 버렸다. 정답 "너무 병원 같아요" 의 차이가 0.002 라 잡담과 안 갈린다 `[실측]`.
- **H4 에서 "흔한 어절 하나면 튀어나옴 검사 면제 안 함"(리뷰 P2-4 제안)** — 버렸다. "색이 탁해요"(0.077)가 확신을 잃는다.
  그 변형 "BM25 증거가 1위 문서를 가리킬 때만 면제" 도 대 봤다: "안녕 좋은 아침"·"시원한 여름 느낌" 을 막지만 정답 "너무 병원
  같아요"(0.112)가 확신을 잃어 23건 21 → 20 `[실측]`. 문턱을 0.11 로 내리면 이 한 건에 맞춘 값이라 안 했다 — **대표 결정**.
- **H5 에서 종족 낱말 혼자면 바로 캐릭터** — 버렸다. "천사 같은 파스텔"·"기계 같은 대시보드" 처럼 비유가 흔하다. 39단계 원칙(겹침은 되묻는다)을 따랐다.
- **H3 원인 찾기** — 멈춘 뒤 넘어갔다. 세 가지 재현 시도(임베딩만 100회, LLM 직후 임베딩, 두 모델 새로 올린 직후 90초)에서
  임베딩 멈춤 0, LLM 한 번 6.2초. 환경(GPU 메모리 7.2/8.1GB · Windows) 문제로 보인다 `[추정]`.
