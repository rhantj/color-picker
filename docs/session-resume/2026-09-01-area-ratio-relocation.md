# 2026-09-01 — 면적 비율을 코퍼스에서 규칙으로

[2단계 문서](2026-09-01-stage2-server-home.md)에서 열려 있던 결정을 닫았다.

## 바뀌기 전에는 무엇이 있었나

`data/palettes.json` 의 조합마다 `defaultRatio: [68, 32]` 같은 값이 박혀 있었다. 두 색을 화면에
칠할 때의 면적 비율이다. 필요한 값이다 — color-design 원칙상 **면적은 색의 일부**이고, 같은 두 헥스도
비율이 바뀌면 다른 색이 된다(`#CC1236 + #0F1A14` 는 22:78 이면 느와르, 78:22 면 경고판).

문제는 **배색사전 원전에 그 값이 없다**는 것이었다. 원전은 헥스와 인상만 적는다. 16개 숫자 쌍은
전부 내가 지어낸 것이고, 규칙(D형 70:30 / 대등 50:50)과 어긋나는 예외가 6개나 붙어 있었다.

## 왜 바꿨나

지어낸 값이 데이터에 흩어져 있으면 **어디까지가 원전이고 어디부터가 우리 판단인지** 구분이 사라진다.
사용자가 세 번째 안을 골랐다 — 비율을 데이터에서 빼고, 규칙을 코드 한 곳에 둔다.

## 어떤 원리를 썼나

유형만으로는 부족하다. D형(서열 조합)은 **어느 쪽이 바탕이고 어느 쪽이 강조인지**를 알아야 70:30 을
어느 방향으로 놓을지 정해진다. 이걸 조합마다 적으면 숫자가 역할로 바뀔 뿐 판단은 여전히 데이터에 남는다.

그래서 헥스에서 계산되는지 실측했다. D형 9쌍에 대해, 초안이 손으로 정한 바탕과 두 규칙을 대조했다.

| 규칙 | 적중 |
|---|---|
| **바탕 = 채도가 낮은 쪽** | **8 / 9** |
| 바탕 = 명도가 높은 쪽 | 5 / 9 |

채도 규칙은 color-design 원칙에서 그대로 온다 —
> 강조색은 채도 대비로 만든다. 강조색을 더 쨍하게 하는 게 아니라, 나머지를 탁하게 눌러야 하나가 산다.

유일한 반례는 앰버 × 커피브라운(초안이 고채도인 앰버를 바탕으로 뒀다). 예외를 만들어 규칙을 더럽히는
대신 규칙 쪽을 따랐다. 원전이 "목조주택 부엌"이라 하니 어두운 나무가 바탕이고 앰버가 빛인 쪽도 읽힌다.

**결과: 조합별 데이터가 0개다.**

## 그래서 코드가 이렇게 된다

| 파일 | 변화 |
|---|---|
| `data/palettes.json` | `defaultRatio` 16개 제거. `_ratioNote` → `_areaNote`(규칙이 어디 있는지 지목) |
| `public/ratio.js` | **신규.** 규칙 두 줄 + 근거 주석 |
| `public/color.js` | `chroma()` 추가 (RGB max-min 근사) |
| `server.js` | API 가 색에 `ratio` 를 붙여 내려보내던 것 중단 — 코퍼스가 아는 것만 보낸다 |
| `public/app.js` | `swatch(palette)` 가 `ratioFor()` 로 계산 |
| `scripts/search.mjs` | CLI 도 같은 규칙 |
| `scripts/check-stage1.mjs` | S1-G1 이 `defaultRatio` **잔재를 금지**하는 쪽으로 반전 |
| `scripts/check-stage2.mjs` | S2-G3 수정, **S2-G7 신설** |

규칙을 바꾸려면 `public/ratio.js` 의 `HIERARCHY = 70` 한 줄만 고친다.

`public/ratio.js` 를 `public/` 에 둔 이유는 브라우저와 Node 양쪽에서 같은 규칙을 쓰기 위해서다.
DOM 을 안 건드리는 순수 함수라 게이트가 브라우저 없이 검사할 수 있다(`color.js` 와 같은 이유).

**발행한 디자인 캔버스(아트보드 3장)는 아직 옛 비율이다.** 사이트가 기준이 됐으므로 캔버스를 맞출지
사용자 판단 대기 중.

## 지금 상태

게이트 **11개 전부 통과** (S1-G1~G4, S2-G1~G7).

| 게이트 | 뮤테이션으로 확인한 것 |
|---|---|
| S2-G7 | 바탕 판정을 고채도 쪽으로 뒤집으면 D형 9건 전부 FAIL |
| S2-G3 | API 에 `areaRatio` 를 최상위로 되돌리면 FAIL |
| S1-G1 | `defaultRatio` 가 남아 있으면 FAIL |

브라우저 실측: 느와르 스와치 **138px : 322px = 30:70**(460px 기준), API 응답에 `ratio` 없음,
콘솔 오류 없음.

**주의:** 브라우저 패널이 접혀 있으면 뷰포트가 `0x0` 이 되어 퍼센트 폭이 전부 0 으로 측정된다.
CSS 버그로 오인하기 쉽다 — 측정 전에 `resize_window` 로 크기를 준다.

## 코드 리뷰 (격리 복사본)

Critical 0 / High 0 / Medium 1 / Low 1 — 둘 다 반영:

| 지적 | 조치 |
|---|---|
| S2-G3 이 색 객체 내부 `ratio` 만 봐서, 비율이 결과 **최상위 필드**로 되돌아오면 못 잡음 | 최상위·색 객체 양쪽에서 `ratio`·`area` 패턴 키를 찾도록 확대. `areaRatio` 를 심어 FAIL 확인 |

단방향 의존으로 순환 없음, `defaultRatio` 잔재 0건, 호출부 시그니처 전부 정합.
