# 2026-09-07 — 저장에 재질 배정을 남긴다 (19단계 · A2-a)

## 무엇이 안 됐나

파생 팔레트를 저장하면 **색과 비율은 남는데 재질이 사라졌다.**

```
화면:  강조 = 발광 · 바탕 = 무광 · 면 = 금속     ← LLM 이 질의를 읽고 정한 것
저장:  { colors: [...], ratio: [60,20,20] }      ← 재질이 없다
```

다시 열면 재질 칸이 비어 있고, 내보내기도 그것을 못 쓴다. **A2(엔진 수치 내보내기)의
선행 조건이 이것이다** — 남기지 않은 것은 내보낼 수 없다.

## 왜 색과 다르게 다뤄야 하나

저장소에는 규칙이 하나 있었다 — **화면이 보낸 색을 믿지 않는다.** 화면이 `#ff0000` 을 보내도
서버가 씨앗 id·구조 id·모드로 색을 **다시 계산한다.** 그래야 저장소가 코퍼스와 어긋나지 않는다.

재질에는 그 방법이 안 통한다.

| | 다시 계산되나 | 왜 |
|---|---|---|
| 색 | **된다** | 씨앗+구조+모드가 정해지면 색이 하나로 정해진다(S11-G3) |
| 비율 | 안 된다 | **사용자의 판단**이다. 코퍼스에 답이 없다 |
| 재질 | **안 된다** | 로컬 LLM 이 정한다. 같은 질의라도 답이 달라진다 |

재계산하면 사용자가 화면에서 본 것과 **다른 재질이 저장된다.** 그래서 재질은 비율과 같은
부류로 다룬다 — **받되 검증한다.**

## 무엇을 만들었나

### `pickFinishes` — 받은 배정을 걸러 낸다

무는 것 셋: 역할이 그 구조에 실제로 있는가 · 값이 문자열인가 · 실재하는 재질인가.

**거부가 아니라 걸러내기다.** 하나 틀렸다고 저장을 통째로 막으면 사용자가 이유도 모른 채
저장을 못 한다. 버린 자리는 기본 배정으로 채운다 — LLM 응답을 다루는 `parseAssignment` 와
같은 선택이다.

프로토타입 없는 객체(`Object.create(null)`)에 모은다. `{ "__proto__": "matte" }` 같은 이름이
평범한 객체에서는 **own 속성이 아니라 프로토타입 대입**이 되어 조용히 새기 때문이다.
17단계에서 같은 것을 겪었다.

### `finishesAdjusted` — 이어받기 조건을 비율과 맞춘다

비율에는 `ratioAdjusted` 가 있다. 앞의 값이 "기본값 그대로" 였으면 이어받지 않고 **지금의
기본값을 다시 쓴다.** 그래야 면적 규칙을 나중에 고쳐도 사용자가 안 건드린 옛 저장이 새 규칙을 따라간다.

배정에는 그 구분이 없어서 **한 번 기본값으로 채워진 자리가 영구히 굳었다**(리뷰 지적).
`DEFAULT_FINISH_BY_ROLE` 을 고쳐도 옛 저장은 새 기본을 못 받는다 — 같은 상황에서 비율은 받는데
배정만 안 받는 비대칭이었다. `finishesAdjusted` 를 두어 규칙을 하나로 만들었다.

"손댔다" 의 정의는 **지금의 기본과 다른가**다. 결과가 기본과 같다면 그것은 판단이 아니라
우연히 같은 값이고, 굳혀 둘 이유가 없다.

### 저장소가 `src/material.js` 를 안 읽는다

`materials` 를 서버가 주입한다 — `ratioFor` 를 넣는 것과 같은 자리다. 저장소는 파일 두 개를
다루는 곳이지 색·재질 규칙을 아는 곳이 아니다.

### 뮤테이션 — 살아남은 것 하나, 구멍이 아니다

`pickFinishes` 의 `wanted.has(role)` 을 지워도 게이트가 안 잡는다. **이중 방어여서다** —

### 정보성 지적 — S19-G1 의 한 케이스는 공회전이었다

`{ __proto__: "matte" }` 는 JS 객체 리터럴이라 `JSON.stringify` 를 거치면 **그 키가 아예
안 나간다.** 즉 서버는 그 공격을 받아 본 적이 없다. 원문 JSON 을 그대로 보내는 `postRaw` 를
만들어 세 가지를 더했다 — 그것이 진짜 공격 형태다.

## 다음에 할 일 — A2-b, 그리고 정할 것 하나

내보내기(`src/export.js`)는 아직 파생을 뺀다. 이제 재질이 저장되므로 `applyFinish` 로
base·metallic·roughness·emission 을 만들 수 있다. **착수 전에 사용자에게 물어야 할 것:**

> **언리얼 표기로 낼까, 유니티 표기로 낼까, 둘 다 낼까?**

내부 표현이 언리얼 기준이다 — `Roughness` 는 **0이 거울**이다. 유니티의 `Smoothness` 는
**1이 거울**로 정반대다. 그대로 붙여 넣으면 **거울로 만들려던 것이 무광이 된다.**
`toUnity`/`toUnreal` 이 이미 있으니 어느 것을 낼지만 정하면 된다.

## 함정 기록

- **`\b` 를 문서에 적을 때 진짜 0x08 이 박힐 수 있다.** 그 사고를 경고하는 문장에서 같은
  사고를 냈다. 문서를 쓴 뒤 제어문자를 원시 바이트로 검사한다.
- **JS 객체 리터럴로 만든 공격 케이스는 공격이 아닐 수 있다.** `{ __proto__: x }` 는
  `JSON.stringify` 에서 사라진다. 프로토타입 공격은 **원문 JSON 으로** 보내야 재현된다.
- **살아남은 뮤테이션을 무조건 구멍으로 읽지 않는다.** 이중 방어에 가려진 것인지 먼저 가른다.
  가려진 것이면 그 사실을 코드에 적어 다음 사람이 같은 조사를 반복하지 않게 한다.
- **경고문은 그 파일을 여는 사람만 읽는다.** 세 번 놓친 뒤에야 규칙을 `CLAUDE.md` 로 옮겼다.
