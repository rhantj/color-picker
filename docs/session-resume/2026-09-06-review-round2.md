# 2026-09-06 — 9·10단계 재리뷰 (미실시 2라운드 메우기)

9단계와 10단계가 각각 **1라운드만** 리뷰되고 넘어갔다. 스킬이 2라운드를 하한으로 정하고
그 근거가 "리뷰 1회는 실제 결함의 3분의 1 정도만 잡는다" 인데, 두 번 다 판단으로 건너뛰었다.
그 빚을 갚은 기록이다.

## 지금 상태

| 항목 | 값 |
|---|---|
| 게이트 | **67개 전부 통과** |
| 새 결함 | **P0 0 · P1 1 · P2 5** |
| 수정 | 여섯 전부 |

## 이건 "같은 SHA 2라운드" 가 아니다

1라운드 지적이 전부 반영된 뒤였으므로, 스킬 기준으로 **고쳐진 코드의 첫 리뷰**다. 그래서
`--prior` 에 지적 18건과 **처리(accept/decline/defer)까지** 실어 보내고, 리뷰어에게
"직전 처리가 옳았는지도 판정하라" 고 요구했다 — 1라운드에서 리뷰어끼리 네 번 갈렸고
그중 셋은 호출자의 실측이 갈랐기 때문이다.

**대상** `3cabc01..HEAD`(9·10단계만, 14파일 1304줄) · **4콜** — Claude 3종 + Codex.
`security-reviewer` 를 켰다: 9단계가 새 쓰기 경로를 열었고 메모가 두 경로로 들어와
CSS·JSON 으로 나가며, `safeComment` 와 `clip` 이 최근 각각 두 번·한 번 바뀌었다.

### 다듬리지 않은 관계값이 연결을 조용히 잃게 했다

`usableRelation` 은 `v.trim() !== ""` 로 검사하는데 `Set` 에 넣는 값은 **원본**이었다.
`" 유사색"`(앞 공백)이 들어오면 필터는 통과하지만 축 문자열에는 공백 없는 형태만 있어
**매치가 조용히 실패한다.** 에러도 경고도 없이 연결이 하나 사라지고 원인을 찾기가 어렵다.

```
수정 전 — 어휘 [" 보색","유사색"] · 축 "보색 + 톤 통일" -> hue: null
수정 후 — 어휘 ["유사색","보색"]  · 축 "보색 + 톤 통일" -> hue: "보색"
```

다듬은 값을 넣도록 고치고 S10-G7 에 "앞뒤 공백이 붙은 값" 케이스를 더했다.

### 정적 검사의 주석 제거가 코드를 먹었다

```
원본 : const url = `http://${h}`; const x = "유사색";
제거 : const url = `http:
```

`//` 를 줄 주석으로 보는 정규식이 URL 스킴도 먹는다. 같은 줄에 관계어가 있으면 하드코딩
탐지가 **거짓 통과**한다. `://` 만 제외하도록 좁혔고(검사기 넷, 4곳), **`"a//b"` 형태는
여전히 먹힌다.** 더 넓히지 않았다 — 정규식으로 코드와 문자열을 가르는 것은 원리적으로
불가능하고, 넓히면 오탐과 미탐이 함께 는다. `GATES.md` 알려진 한계에 적었다.

## 리뷰어가 확인해 준 것 (새 지적 아님)

- **`safeComment` 순서 보장이 유효하다.** `별표 + U+202E + 빗금` 을 실제로 넣어 `* /` 로
  손질되는 것을 확인했다. 불변식은 **도달 불가능한 방어선**이다 — 통과할 조합을 못 찾았다.
- **불변식이 던져도 서버가 안 죽는다.** `handleExport` 가 `dispatch` 의 try/catch 안이고,
  그 catch 는 `format=__proto__` 사고 뒤에 넣은 바로 그 보호막이다.
- **`entry` 직접 변형에 공유 상태가 없다.** `listSaved()` 가 매번 새 객체를 파싱해 돌려준다.
- **`shapeBridgePalette` 는 `shapePalette` 의 부분집합**이다. 초과 노출 없음.
- **9·10단계가 `ui.js` 를 공유하지만 충돌하지 않는다.** `diagnosisCard` 는 `app.js` 만,
  `noteField` 는 `saved.js` 만 쓰고 기존 export 시그니처는 안 바뀌었다.
- 직전 처리 18건(accept·decline·defer)이 **전부 타당**하다고 셋이 각각 재검증했다.
  `무관` defer 는 18개 축 전수 스캔으로 충돌 0건을 확인했다.

## 배운 것

**같은 수를 여러 곳에 손으로 적는 구조가 이 세션에서 네 번 어긋났다.** README/GATES 두 번,
`알려진 한계` 절 본문 한 번, 세션 문서 증분 한 번. 매번 다른 자리라 점검 목록으로는 안 잡힌다.
**수를 한 곳에서만 적고 나머지는 세는 방식이 아니면 계속 어긋난다** — 아직 안 고쳤다.

**건너뛴 2라운드는 실제로 빚이었다.** P0 는 없었지만 P1 하나와 P2 다섯이 나왔고, 그중 둘
(`usableRelation` 트림, 주석 제거)은 1라운드가 전혀 건드리지 않은 축이었다. 다만 **1라운드가
잡은 것들보다 가볍다** — 스킬이 말하는 "1회는 3분의 1" 과 방향이 같다.
