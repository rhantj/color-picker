# 2026-09-07 — 재질을 손으로 바꾼다 (21단계 · A3)

## 무엇이 안 됐나

로컬 LLM 이 **"본문은 광택"** 이라고 정하면 사용자는 **그대로 봐야 했다.**

```
바탕  무광     ← 읽기 전용. 바꿔 볼 수가 없었다
본문  광택
강조  메탈릭
```

배정이 마음에 안 들어도 할 수 있는 것이 없었다. 다시 물어봐도(질문을 바꿔 다시 검색해도)
같은 답이 나올지 알 수 없고, 그러면 **보이는 다섯 배색이 통째로 바뀐다.**

## 무엇을 만들었나

역할마다 고르개가 생겼다.

```
바탕  [무광 (LLM 배정) ▾]
본문  [광택 (LLM 배정) ▾]   ← 여기서 발광으로 바꾸면
강조  [메탈릭 (LLM 배정) ▾]
```

바꾼 것이 **저장에 남고 엔진 수치까지** 간다. 본문을 발광으로 바꾸면 언리얼 파일에
`emissiveColor: #de2143 · emissiveIntensity: 2` 가 나온다(실측).

### 되돌릴 길을 상태 없이 만들었다

이것저것 바꿔 본 뒤 원래로 돌아가려면 **어느 것이 원래였는지** 알아야 한다.
되돌리기 버튼과 그 상태를 따로 두는 대신, **목록 안에 적었다** — LLM 이 고른 항목에만
`(LLM 배정)` 이 붙는다. 상태가 하나도 안 늘어난다.

## 함정 셋을 피해야 했다

이 단계는 새 기능이라기보다 **세 가지 함정을 피하는 일**이었다.

### 1. 고친 재질이 모드 토글에 날아간다

모드 토글은 격자를 **통째로 다시 그린다**(`redraw`). 고르개를 카드 안에 그냥 넣으면
어두운 모드로 바꾸는 순간 **사용자가 고친 것이 전부 사라진다.**

15단계에서 겪은 것과 같은 부류다(그때는 포커스가 사라졌다).

**바꾼 배정을 카드 밖 — 펼침 영역 클로저에 뒀다.** `S21-G4` 가 그 자리를 정적으로 검사한다:
배정 상태가 `redraw` 보다 **위**에 선언돼 있는가.

```
실측:  본문을 발광으로 바꾼다 → 어두운 모드로 토글 → 여전히 발광
```

### 2. 한 카드를 고쳤는데 일곱이 같이 바뀐다

배정 표는 **역할별로 하나**다(`본문 → 광택`). 카드 여덟이 그것을 함께 본다.
그대로 고치면 **안 건드린 카드 일곱이 조용히 달라진다.**

**구조마다 따로 담는다.** 사용자는 하나의 배색을 다듬는 중이고, 저장도 구조 단위다.

```
실측:  첫 카드의 본문을 바꿈 → 나머지 네 카드 그대로
```

### 3. 바꾸려고 서버를 다시 부른다

`/api/expand` 를 다시 부르면 `selectStructures` 가 다시 돌아 **같은 질의인데 보이는 다섯이
바뀐다.** 재질을 하나 고치려다 화면 전체가 갈리는 것이다 — 15단계가 모드 토글에서 피한
것과 정확히 같은 함정이다(`S15-G11`).

담아 두기만 한다. 네트워크 0.

### 4. 다시 그리기만 해도 망가진다 (구현 중에 스스로 찾음)

**함정 셋을 피해 놓고 네 번째에 걸렸다.** 서버는 안 불렀지만 **격자를 다시 그렸고**,
그것이 브라우저 실측으로 두 가지를 망가뜨렸다.

```
① 사용자가 맞춘 면적 비율    55 : 25 : 20  →  34 : 33 : 33   (조용히 초기화)
② 방금 조작한 고르개의 포커스  select       →  body           (사라짐)
```

**①이 더 나쁘다.** 이 사이트는 "면적이 색의 일부다 · 같은 두 헥스도 비율이 바뀌면 다른 색"
이라고 말해 왔다. 비율을 맞추고 재질을 하나 고쳤을 뿐인데 그 작업이 사라지면, 화면이
스스로의 주장을 배신한다.

②는 모드 토글이 **이미 겪고 `focus()` 로 막아 둔** 문제다. 그 주석을 내 코드에서 인용해
놓고 같은 실수를 했다.

**애초에 다시 그릴 필요가 없었다.** 고르개는 사용자가 고른 값을 이미 스스로 보이고 있고,
카드에서 재질에 딸린 것은 그것 하나뿐이다 — 스와치·비율·`(LLM 배정)` 표시는 전부 재질과
무관하다(표시는 **원래** 배정 기준이라 안 바뀐다). 그냥 담아 두기만 하면 된다.

```
고친 뒤:  비율 55:25:20 그대로 · 포커스가 그 고르개에 그대로 · 요소도 DOM 에 살아 있음
모드 토글: 바꾼 재질이 여전히 남음 (합치기는 forStructure 가 그때 한다)
```

`S21-G4` 가 이 회귀를 막는다 — **`onFinish` 안에 `redraw` 가 있으면 운다.**

**교훈: "서버를 안 부른다" 는 "화면을 안 부순다" 와 다른 말이다.** 앞의 함정 셋은 전부
바깥(서버·다른 카드·모드)을 건드리는 것이었고, 이것은 **자기 카드 안**을 부수는 것이라
같은 눈으로는 안 보였다.

> **"비율을 맞춘 뒤 재질을 바꾼다" 는 안 잰다** — 그게 깨지는 바로 그 시나리오다.

맞다. 처음 목록은 **바깥으로 새는 것만** 보고 있었다.

### TS 리뷰가 Block 을 냈다 — 게이트 구멍 둘

**둘 다 "코드가 지금 깨졌다" 가 아니라 "깨져도 아무도 모른다" 였다.**

#### High① — 고른 값으로 열리는지를 아무도 안 봤다

`structureCard` 에서 `editing?.assignments ?? finishes.assignments` 를
`finishes.assignments` 로 바꾸면(=사용자가 고른 것을 무시) **일곱 게이트가 전부 통과했다.**

실제로는 이렇게 된다 — 재질을 고르고 어두운 모드로 토글하면, **저장에는 고른 값이 남는데
화면은 원래 값으로 돌아간다.** 무엇이 저장될지 알 수 없어진다.

원인은 게이트가 `editing.assignments` 를 늘 원래 배정과 **같게** 넘긴 것이다. 둘이 같으면
어느 쪽을 읽든 결과가 같아서 구별할 방법이 없었다. 지금은 **다른 값**을 넘겨 가른다.

#### High② — "서버를 다시 안 부른다" 를 글자로 재고 있었다

이 단계에서 가장 중요한 보장이다. 부르면 `selectStructures` 가 다시 돌아 **보이는 다섯이
바뀐다.** 그런데 `app.js` 소스에서 `api(` 라는 글자를 찾는 방식이었다.

리뷰가 **한 줄로 우회했다:**

```js
const reloadExpansion = () => { api(`/api/expand?seed=...`); };   // ← 검사 창 밖
...
onFinish: (role, id) => { overrides.set(...); reloadExpansion(); }
```

**이건 난독화가 아니라 평범한 리팩터링이다.** 다음 사람이 악의 없이 할 법한 일이고,
그런 것에 뚫리는 검사는 검사가 아니다. (리뷰어가 처음에 헬퍼 이름을 `sneakyRefetch` 로
지었더니 잡혔는데, 그건 `Refetch(` 안에 `fetch(` 가 우연히 들어 있어서였다.
`reloadExpansion` 으로 바꾸니 통째로 안 보였다.)

**정규식을 더 똑똑하게 만드는 길은 없다.** 소스 문자열만 보고 무엇이 실행될지 판정하는 것은
원리적으로 안 된다 — 이 저장소가 `S19-G5` 에서 이미 겪었다.

그래서 판정 로직을 **`finishEditing` 이라는 순수 함수로 뺐다.** 게이트가 직접 부르고:

| 무는 것 | 어떻게 |
|---|---|
| 서버를 안 부른다 | `fetch` 를 감시한다. 한 번이라도 부르면 운다 |
| 화면을 안 부순다 | **DOM 을 아예 안 깔고** 부른다. 건드리면 던지고 그 던짐을 잡는다 |
| 고른 것이 담긴다 | 담고 나서 새로 물어본다(캐시가 아니라 저장을 본다) |

감시가 진짜로 도는지 **양성 대조**도 넣었다 — 아무도 안 부르면 "0번 불렀다" 는 늘 참이라
검사가 공허해진다.

17단계 `structureColors` · 18단계 `savedFields` · 20단계 `engineToggle` 이 같은 이유로
같은 것을 했다. **정규식으로 원리적으로 못 하던 것이 함수를 부르면 그냥 된다.**

### Medium — 흉내 낸 DOM 이 브라우저보다 너그러웠다

`option` 의 `value` 를 이름표로 바꿔치기하는 변형이 `S21-G3` 을 통과했다.
진짜 브라우저에서는 그 변형이 **기능을 통째로 깬다** — `select.value = "gloss"` 가
일치하는 `option` 을 못 찾아 아무것도 안 고른 채로 열리고, 고르면 이름표 문자열이
저장으로 가서 조용히 버려진다.

흉내가 `value` 를 그냥 필드로 뒀기 때문이다. 진짜 `select` 는 **일치하는 `option` 이 없는
값을 안 받는다.** 흉내에 그 규칙을 넣었다.

**흉내는 최소로 두되, 브라우저보다 너그러운 자리는 만들지 않는다.** 너그러우면 게이트가
통과하는데 화면은 깨진다 — 그게 흉내를 쓰는 값을 통째로 없앤다.

### Medium — 주석이 없는 게이트를 있다고 말했다

`ui.js` 의 `FINISH_IDS` 옆에 *"`MATERIAL_FINISHES` 와 같은 목록이고, 어긋나면 `S21-G1` 이
운다"* 라고 적혀 있었는데, **그 게이트는 자기 사본하고만 비교하고 있었다.**
목록이 어긋나면 화면이 고를 수 있는 것과 서버가 받는 것이 달라져, 고른 재질이 저장에서
조용히 기본값으로 바뀐다. 이제 실제로 셋(화면·엔진·게이트)을 대조한다.

### Low — 고치지 않고 넘긴 것 하나

서버가 화면이 모르는 재질을 보내면 그 역할의 재질 줄이 **사라지고**, 저장소는 그 자리를
기본값으로 채운다. 사용자는 줄도 못 보고 저장된 값도 못 본다.

**전제조건을 `S21-G1` 이 이제 막는다** — 두 목록이 어긋나면 게이트가 운다. 어긋남 없이 이
상태에 닿는 길은 손상된 응답뿐이고, 거기에 화면을 더 만드는 것은 안 일어날 일에 대한
설계다. **다시 볼 조건: 재질 목록이 실제로 늘어날 때.**
