# 2026-09-07 — 엔진 수치를 엔진별로 나눠 내보낸다 (20단계 · A2-b)

## 무엇이 안 됐나

화면에 **"강조 = 발광 · 면 = 금속"** 이라고 떠도, 정작 **유니티나 언리얼에 붙여넣을 숫자를
못 얻었다.** 이 사이트가 게임 엔진용이라는 전제를 세워 놓고 마지막 한 걸음이 비어 있었다.

19단계가 재질 배정을 저장에 남겼으니, 이제 `applyFinish` 로 수치를 만들 수 있다.

## 왜 엔진을 나눠야 하나

두 엔진이 **같은 것을 반대로 센다.**

| | 거울 | 완전 무광 |
|---|---|---|
| 언리얼 `Roughness` | **0** | 1 |
| 유니티 `Smoothness` | **1** | 0 |

한쪽 값을 다른 엔진에 그대로 넣으면 **거울로 만들려던 면이 무광이 된다.** 나쁜 것은
에러가 안 난다는 점이다 — 장면만 달라지고, 사람이 눈으로 알아채기 전까지 계속 틀린다.

## 무엇을 만들었나

### 방어 셋을 겹친다

| 방어 | 쉽게 말하면 |
|---|---|
| **엔진마다 파일을 나눈다** | 한 파일에 둘이 있으면 잘못된 쪽을 복사하기 쉽다. 그게 함정 그 자체다 |
| **파일이 자기 엔진을 밝힌다** | 나눠 놨어도 나중에 열었을 때 어느 쪽인지 모르면 똑같이 헷갈린다. `engine` 필드와 반전 경고 한 줄을 넣는다 |
| **필드 이름이 안 겹친다** | 유니티 프로젝트에 `roughness` 를 넣으면 그 칸이 비어 **사람이 알아챈다.** 조용히 반대가 되는 것보다 낫다 |

버린 대안: **한 파일에 둘 다 담기.** 파일이 하나면 편하지만, 막으려는 실수를 오히려 쉽게
만든다 — 같은 색 블록 안에 `roughness` 와 `smoothness` 가 나란히 있으면 눈으로 고르게 된다.

### 형식이 다루는 대상이 갈렸다

| 형식 | 담는 것 | 왜 |
|---|---|---|
| `css` · `json` | 코퍼스 조합만 | 파생은 `paletteId` 도 `type` 도 없고 색이 3~4개다. 그대로 내면 조용히 망가진다(18-B 실측) |
| `unreal` · `unity` | 파생 팔레트만 | 코퍼스에는 재질 배정이 없다 |

**코퍼스를 엔진 형식에서 빼는 이유는 데이터가 없어서다.** LLM 이 코퍼스 조합에 재질을
배정한 적이 없고, 역할 이름도 `바탕`/`강조`/**`대등`** 인데 `대등` 은 재질 엔진의 역할 표에
없다. 기본 재질을 붙여 내보내면 **배색사전이 한 적 없는 주장을 지어내는 것**이다 —
와다 산조의 색 쌍이 빛을 내게 된다.

**양쪽 다 뺐다고 말한다.** 조용히 빼면 사용자는 저장한 것이 다 나왔다고 믿는다.

### 토글

내보내기 패널 안에 버튼 하나. 누르면 지금 보이는 출력이 반대 엔진으로 바뀐다.

```
언리얼 엔진 · 109줄
[⇄ 유니티 표기로 보기]  [복사]  [파일로 저장]  [닫기]
```

**라벨은 지금이 아니라 갈 곳을 말한다.** "언리얼" 이라고만 적혀 있으면 지금이 언리얼인지
누르면 언리얼이 되는지 알 수 없다. 15단계 모드 토글이 "어두운 배경으로 보기" 라고 적는 것과
같은 규칙이다.

어느 엔진을 보여줄지 정하는 부분은 **`engineToggle` 이라는 순수 함수**로 뺐다. **이유는
게이트다** — 화면 코드는 정적 검사밖에 못 하는데 정적 검사는 "눌렀을 때 어디로 가는가" 를
못 본다. 17단계 `structureColors` · 18단계 `savedFields` 와 같은 자리다.

### 손상된 항목이 전체를 못 죽인다

`applyFinish` 는 모르는 재질·역할에 던진다(16단계 계약). 그 계약은 옳지만 여기서 그대로
위로 올리면 **손상된 항목 하나가 내보내기 전체를 500 으로 만든다.** 18-B 에서 `/saved`
화면이 정확히 그 이유로 목록을 통째로 비웠고 리뷰가 High 로 잡았다.

`enginePalette` 가 `null` 을 돌려주고, 못 낸 수를 `skippedBroken` 으로 말한다.
**던지지 않는 것과 조용히 넘어가는 것은 다르다.**

## 기존 게이트 하나가 울었다 — 그게 맞다

**S18-G13 이 실패했다.** 그 게이트는 `FORMATS` 전부를 돌며 "파생을 뺐는가 · 코퍼스가
나오는가" 를 물었는데, 20단계가 **정반대 성질의 형식**을 더하면서 그 물음이 엔진 형식에는
거짓이 됐다.

게이트를 약하게 만들지 않고 **둘로 갈랐다.**

| 무엇을 | 어디에 |
|---|---|
| `undefined` 안 나옴 · 어떤 목록에도 안 던짐 | **모든 형식** (4형식 × 목록 4가지) |
| 파생을 빼고 뺐다고 말함 · 코퍼스는 나옴 | **코퍼스 형식만** (`css`·`json`) |

그리고 **형식 목록을 게이트에 손으로 적고, 실제와 어긋나면 실패시킨다.** 목록만 적어 두면
나중에 형식이 하나 늘었을 때 그것이 검사에서 **아무 신호 없이 빠진다.** 새 형식이 코퍼스용인지
엔진용인지는 사람이 정해야 하는 것이다.

수리한 게이트도 뮤테이션 3개로 확인했다 — 형식 추가 · 안내문 제거 · 빈 목록에서 던지기.

## 함정 두 개

### 1. `\21C4` 가 진짜 0x11 로 들어갔다

토글 버튼에 방향 기호(`⇄`)를 CSS `content` 로 넣으려고 `"\21C4"` 를 썼더니, 파일에
**제어문자 0x11 + `C4`** 가 박혀 버튼에 `◀C4` 가 찍혔다.

**19단계의 `\b` → 0x08 과 정확히 같은 사고다.** 그때 GATES.md 에 "escape 를 안 쓴다" 를
적어 뒀는데도 다시 났다 — 그 항목이 *게이트 정규식* 이야기로만 적혀 있어서 CSS 는 해당이
없다고 읽었다. 항목을 **"파일에 escape 를 안 쓴다. 문자를 직접 넣는다"** 로 넓히고 두 사례를
나란히 적었다.

두 번 다 **눈으로는 안 보였다.** 원시 바이트 검사로만 드러난다.

### 2. 게이트가 통과하고 **나서** 죽었다

`S20-G1`·`G2`·`G4` 가 통과 문구를 찍은 뒤 종료 코드 127 로 실패했다.

```
두 엔진이 반전된 수치를 내고 필드 이름이 안 겹친다
S20_G2_OK
Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c, line 94
```

요청을 여러 번 보내는 게이트에서 **연결이 정리되는 중에 `process.exit()` 로 강제 종료**하면
윈도우 libuv 가 죽는다(3회 중 2회 재현). `process.exitCode` 만 정하고 노드가 스스로 끝나게
바꿨다 — 5회 반복해서 전부 안정.

**"지적 없음" 과 "검사가 깨져 사라짐" 은 다른 것이다.** 하네스의 문제를 코드 결함으로 읽거나
반대로 넘겨 버리면 게이트 전체가 신뢰를 잃는다.

## 격리 리뷰 두 건 — Critical 0 · High 3 · Medium 3 · Low 4

**High 3건은 전부 문서 최신성이었고, 리뷰가 도는 동안 이미 고쳐져 있었다** — 리뷰어는 고정된
SHA(문서 변경 0건)를 봤다. 작업 목록 · 이 문서 · 게이트 수 셋 다 갱신됐다.
(그래도 **네 번째 경고로 센다.** 문서를 코드와 같은 커밋에 넣었다면 리뷰가 볼 것도 없었다.)

### 두 리뷰가 한 지점에서 엇갈렸다

`isEngineFormat` 이라는 함수를 두고 —

| 리뷰 | 판정 |
|---|---|
| 일반 | "아무 데서도 안 쓴다. 죽은 코드니 지워라" (Low) |
| TS | "그게 바로 `toEngine` 이 써야 할 방어인데 안 쓰고 있다" (Medium) |

**TS 쪽이 맞다.** 지울 것이 아니라 **그 자리에 쓸 것**이었다. `toEngine` 의 경계 검사가
참·거짓으로만 보고 있어서, `ENGINE_SPEC["constructor"]` 가 프로토타입에서 `Object` 를 물고
나와 통과했다. 그러고는 `spec.convert` 가 없어 `TypeError` 가 났다 — 그 예외는
`enginePalette` 의 try/catch **밖**이라 위로 튄다.

```
전: toEngine([], "constructor") → TypeError: spec.convert is not a function
후: toEngine([], "constructor") → Error: 모르는 엔진이다: constructor
```

이 저장소가 같은 것을 세 곳에서 이미 `Object.hasOwn` 으로 막아 뒀다(`handleExport` ·
`evForRole` · `applyFinish`). **여기만 빠져 있었다.** 함수 안에서 직접 막고, 중복이 된
`isEngineFormat` 은 없앴다 — 두 지적이 함께 닫힌다.

**지금은 HTTP 로 못 닿는다.** `FORMATS` 의 엔진 항목이 엔진 이름을 리터럴로 묶어 두고, 서버가
`Object.hasOwn(FORMATS, format)` 로 먼저 거른다. 그래도 고친 것은 **공개 함수**이기 때문이다 —
호출부가 하나뿐이라는 사실이 언제까지나 참일 보장은 없다.

### 게이트 구멍 하나 — 색만 보고 팔레트를 안 봤다

`structure` 를 통째로 빼고 `finishesAdjusted` 를 `false` 로 굳혀도 **일곱 게이트가 전부
통과했다**(TS 리뷰가 변형으로 재현). 색마다의 수치는 촘촘히 무는데 **팔레트 단위 정보**는
아무도 안 봤다. 그 값들은 붙여넣는 사람이 실제로 쓴다 — 어느 구조·어느 모드인지, 재질이
사람이 고른 것인지 기본값인지.

고치면서 한 번 더 걸렸다. **`finishesAdjusted` 를 `false` 로 굳히는 변형이 처음 수리에서도
살아남았다** — 게이트가 참·거짓 *타입만* 봤고, 시험 데이터가 마침 둘 다 `false` 라 구별이
안 됐다. 그다음엔 **두 값을 서로 바꾸는** 변형이 살아남았다 — 두 팔레트에서 두 값이 늘 같아서다.

지금은 시험 데이터를 **엇갈리게** 만든다.

| 팔레트 | 재질을 손댔나 | 비율을 손댔나 |
|---|---|---|
| 보색대비 · 밝은 | **참** | 거짓 |
| 명도 스케일 · 어두운 | 거짓 | **참** |

이래야 굳히기(참·거짓 양쪽)와 뒤바꾸기가 전부 잡힌다. **참·거짓을 검사할 때 데이터가 한쪽에
쏠려 있으면 검사가 절반만 산다.**

### 접근성 — 인용한 선례를 절반만 따랐다

토글 라벨이 "갈 곳" 을 말하는 근거로 15단계 모드 토글을 인용해 놓고, 그쪽이 하는 두 가지 중
하나만 했다(일반 리뷰 지적). 모드 토글은 라벨과 함께 **지금 상태**도 알린다.

버튼으로 바로 이동하면 위 제목("언리얼 엔진")을 안 지나므로 "유니티 표기로 보기" 만 들리고
**지금이 어디인지 알 방법이 없다.**

**`aria-pressed` 는 안 썼다.** 모드 토글은 "어두운 모드가 켜졌는가" 라는 이진 상태라 맞지만,
여기는 **둘 사이를 오가는 전환**이라 눌림/안 눌림이 언리얼·유니티에 대응되지 않는다 —
읽어 주면 오히려 틀린 말이 된다. 대신 `aria-label` 로 지금과 갈 곳을 함께 말한다:

```
보이는 글자:  ⇄ 유니티 표기로 보기
읽어 주는 말: 지금 언리얼 표기 · 유니티 표기로 보기
```

**읽어 주는 문장이 보이는 글자를 그대로 담는다.** 음성으로 조작하는 사람은 눈에 보이는 것을
말해서 버튼을 누르므로, 라벨이 보이는 글자를 안 담으면 그 방법이 막힌다.

이것도 게이트 수리가 한 번 필요했다. 처음엔 `saved.js` 에 `aria-label` 이 있는지만 봤는데,
**그 파일은 메모 입력칸에도 그 속성을 쓴다** — 토글이 안 붙여도 통과했다. 지금은 그 속성과
문장이 **같은 구문**에 있는지를 본다.
