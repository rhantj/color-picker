# 2026-09-01 — 5단계: 면적 비율 조정

[캔버스 동기화 문서](2026-09-01-canvas-ratio-sync.md) 다음. 초안이 약속했던 세 기능 중 첫 번째.

## 바뀌기 전에는 무엇이 있었나

사이트가 여러 곳에서 **"같은 두 헥스도 비율이 바뀌면 다른 색"** 이라고 말한다 — 저장 화면 리드문,
캔버스 주석, 코퍼스의 `_areaNote`. 그런데 정작 **바꿔볼 수가 없었다.** `public/ratio.js` 가 계산한
기본값이 유일한 값이었다.

주장을 검증할 수 없는 화면이었던 셈이다.

## 그래서 코드가 이렇게 된다

| 자리 | 무엇 |
|---|---|
| 홈 결과 카드 | 슬라이더를 움직이면 스와치가 즉시 바뀌고, 버튼이 "조합 저장" → "이 비율로 저장" 으로 바뀐다 |
| 저장 카드 | 바꾸면 바로 서버에 저장된다. "기본값" 버튼으로 규칙값 복귀 |

| 파일 | 변화 |
|---|---|
| `public/ui.js` | `swatchView`(폭·라벨을 `set()` 으로 갈아끼움), `ratioControl`(슬라이더), `paletteCard` 에 `onRatio` |
| `public/app.js` | `resultCard` 가 조정한 비율을 들고 있다가 저장에 실어 보냄 |
| `public/saved.js` | 저장된 조합의 비율을 즉시 변경 |
| `src/store.js` | `normalizeRatio`, `updateSavedRatio`, 저장 항목에 `ratioAdjusted`·`defaultRatio` |
| `server.js` | `/api/saved/ratio` |

세부 결정 둘:
- **저장은 `input` 이 아니라 `change`(손을 뗐을 때)에만.** `input` 마다 쓰면 슬라이더 한 번에 수십 번 쓴다.
- **단계는 5%.** 면적 판단이 1% 단위로 의미 있지 않다.

## 규칙 하나를 의도적으로 풀었다

4단계에서 **"서버는 클라이언트가 보낸 색을 믿지 않는다"** 를 못박았는데, 비율만 예외로 뒀다.

> 색은 코퍼스가 아는 **사실**이지만 비율은 사용자의 **판단**이다. 그 결정을 사용자에게서 받는 것이
> 이 도구의 요점이다.

대신 형태는 강제한다 — 정수, **10~90**. 0·100 은 한 색을 없애는 것이라 2색 조합이 아니게 된다.
저장할 때 `defaultRatio` 를 함께 남겨 언제든 되돌릴 수 있다.

## 지금 상태

게이트 **34개 전부 통과** (S1 4 + S2 7 + S3 10 + S4 7 + S5 6).

브라우저 실측: 느와르 조합을 30:70 → 65:35 로 옮기니 스와치 폭이 59.7px → 129.3px 로 따라오고,
`65%/35% adjusted=true 기본=30:70` 으로 저장됐다. 저장 화면에서 "기본값" 을 누르면
`adjusted=false` 로 돌아가고 버튼이 사라진다. 콘솔 오류 없음.

## 코드 리뷰 (격리 복사본)

Critical 0 / **High 1** / Medium 1 / Low 3. 다섯 건 반영:

| 지적 | 조치 |
|---|---|
| **[High] 재저장이 조정한 비율을 조용히 버린다.** 저장 화면에서 70:30 으로 맞춰 둔 조합을, 홈에서 같은 조합을 다시 저장하면 기본값으로 덮어썼다. `ratioAdjusted`·`defaultRatio` 를 만들어 놓고 정작 재저장 경로에서 안 봤다 | 비율을 안 보냈고 이미 조정된 항목이 있으면 **그 값을 이어받는다.** 명시한 비율이 오면 그게 이긴다. **S5-G5 신설** |
| [Medium] 저장 화면 실패 롤백이 "최초 로드 값" 으로 돌아가 서버와 어긋난다 — 50→70 성공 뒤 70→40 실패하면 화면이 50 을 보여주는데 서버는 70 | 성공할 때마다 기준값을 갱신해 **마지막으로 확인된 값**으로 롤백 |
| [Low] `defaultRatio` 가 없던 옛 항목은 `ratioAdjusted` 가 영원히 true | 코퍼스에서 채워 넣는다. **S5-G6 신설** |
| [Low] 죽은 export `swatch`·`swatchForPalette`·`swatchForSaved` | 제거 |
| [Low] S5-G4 가 정적 패턴 매칭이라 우회 가능 | 그대로 둔다 — 이 게이트의 목적("화면 상수를 따로 박아 서버와 어긋나는 것")에는 정확히 맞는 좁은 검사다. 넓히려면 DOM 실행이 필요한데 의존성 0 조건에 걸린다 |

리뷰가 확인해 준 것: `normalizeRatio` 가 `NaN`·`Infinity`·`-0`·부동소수·큰 정수를 모두 거부,
`updateSavedRatio` 도 `serialize` 체인 사용, `/api/saved/ratio` 도 CSRF 가드 적용,
슬라이더 접근성(`label[for]`↔`id`, `aria-valuetext`, 키보드, 44px 히트) 정상,
색만으로 정보를 전달하는 곳 없음(라벨에 헥스·% 병기), XSS 없음.

### 게이트 실효성 (뮤테이션)

| 망가뜨린 것 | 잡은 게이트 |
|---|---|
| 재저장 이어받기 제거 | `S5-G5_FAIL 재저장이 조정한 비율을 버렸다: 30 (기대 60)` |
| 옛 항목 `defaultRatio` 채우기 제거 | `S5-G6_FAIL defaultRatio 를 채워 넣지 않았다` |
| 조정 비율 무시 | `S5-G1_FAIL 조정한 비율이 안 들어갔다: 30` |
| 범위 검증 제거 | `S5-G3_FAIL ratio=0·100·-10·200 이 200` |
| 화면 슬라이더 범위를 서버와 어긋나게 | `S5-G4_FAIL 화면 최소 0 vs 서버 10` |

## 배운 것

**필드를 만드는 것과 그 필드를 보는 것은 다르다.** `ratioAdjusted`·`defaultRatio` 는 조정을 잃지
않으려고 만든 필드인데, 정작 데이터를 잃는 경로(재저장)에서 읽지 않았다. 게이트도 그 경로를
안 밟고 있었다 — 새 필드를 넣을 때는 **그 필드가 없으면 무엇이 깨지는지**를 게이트로 적는다.
