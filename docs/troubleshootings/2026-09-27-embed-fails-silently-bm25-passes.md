# 2026-09-27 — 임베딩이 조용히 실패하고 BM25 의 틀린 확신이 통과했다

"검색 질문이 LLM 없이 끝나는 비율" 을 재다가 드러났다. 질의 55건을 `/api/chat` 에 흘리고 Ollama 로 나간
HTTP 요청을 전부 적었더니, **임베딩(bge-m3) 호출 절반 이상이 실패했는데 화면에는 확신한 답이 나가고 있었다.**
측정 때는 막힌 채로 넘어갔고, **40단계에서 고쳤다**(아래 "해결"). 목록: `docs/com/open-work.md` H1~H6.

측정 스크립트·로그 원본은 저장소 밖(세션 스크래치)에 있었다. 재현 방법은 아래 "재현" 절.

---

## 증상

1. **1차 측정 (서버 기동 직후)** — 임베딩 50건 중 41건 실패. 서버 쪽 오류 원문:

   ```
   [ollama#4] /api/embed    bge-m3            705ms  FAIL The operation was aborted due to timeout
   ```

   같은 시각 Ollama `server.log`:

   ```
   msg="client connection closed before llama-server finished loading, aborting load"
   msg="Load failed" model=...daec91ff... error="timed out waiting for llama-server to start: context canceled"
   [GIN] 2026/09/27 - 23:50:29 | 499 |    825.4312ms |       127.0.0.1 | POST     "/api/embed"
   ```

   `aborting load` 이 30번, 23:50:29 ~ 23:51:26 약 1분 이어졌다. 23:51:33 에 `loaded runners count=2` 로 끝났다.

2. **2차 측정 (두 모델이 이미 GPU 에 있을 때)** — 50건 중 15건 실패. 몰려서 난다(#1–4, #19–24, #30–34).
   Ollama 는 작업을 받고(`processing task`) 안 끝낸 채 있다가 클라이언트가 끊자 이렇게 적었다:

   ```
   [GIN] 2026/09/27 - 23:52:51 | 400 |    695.9113ms |       127.0.0.1 | POST     "/api/embed"
   srv          stop: cancel task, id_task = 37
   ```

3. **실패가 답을 바꿨다** — 임베딩이 없으면 파이프라인은 "BM25 가 확신했으니 믿는다" 로 간다(`src/pipeline.js:177`).

   | 질의 | 임베딩 실패 때 | 임베딩 정상 때 | 쉽게 말하면 |
   |---|---|---|---|
   | 아침에 빵 굽는 냄새가 나는 카페 | 1단계 pair-10 (오답) | 3단계 pair-09 (정답) | 흔한 낱말 둘("냄새가"·"나는")로 BM25 가 우긴 것을 임베딩이 막아야 하는데 못 막았다. 어절 둘이라 40단계 뒤에도 700ms 길이다 — GPU 가 멈추면 같다(open-work H2) |
   | 색이 탁해요 | 1단계 pair-15 | 3단계 dx-muddy | 진단으로 가야 할 질문이 팔레트로 갔다 |

   트레이스(`var/traces.jsonl`)의 `search` 자식은 `stage:1, confident:true` 로만 남는다. **실패가 기록에 안 보인다.**
   1차 기록만 봤다면 "BM25 가 40턴 중 32턴을 정했다" 로 읽었을 것이다 — 정상일 때는 21턴이다.

## 원인

- **1차 — 확인함 `[실측]`.** bge-m3 가 GPU 에 없으면 로딩에 700ms 넘게 걸린다(3차에선 콜드 첫 호출 2.7초).
  검색은 BM25 가 확신하면 임베딩을 700ms 예산(`FAST_BUDGET_MS`)으로 부른다. 서버가 700ms 에 끊으면 Ollama 가
  로딩까지 취소하고, 다음 질의가 로딩을 처음부터 다시 시작한다 — 계속 제자리를 돈다. 8초 예산(저신뢰 질의)으로도
  몇 번 실패했다(로딩이 8초를 넘긴 때가 있다, 서버 로그의 GPU discovery watchdog timeout 과 겹침).
  모델이 안 올라간 채 시작하는 이유: 코퍼스 벡터가 `var/embeddings.json` 캐시에 있으면 기동 때 Ollama 를 안 부른다
  (`src/embed.js` 머리 주석). 기동 워밍업(`rewrite.warmUp`)은 LLM 만 덥힌다.
- **2차 — GPU 가 가끔 몇 초 멈춘다 `[실측]`, 왜 멈추는지는 모른다.** 로그를 다시 읽으니 "멈춘" 작업은 결국 끝났다 —
  14토큰 임베딩 하나(task 37)가 **약 3.5초** 걸렸고, 그동안 뒤 요청들이 줄을 섰다가(슬롯 1개, `-np 1`) 700ms 에 끊겼다.
  2026-09-28 재현 시도:
  - 서버 없이 임베딩만 100번 → 최대 48ms, 멈춤 0
  - LLM 호출 직후 임베딩 5번씩 × 6 → 최대 33ms, 멈춤 0 ("LLM 이 GPU 를 쥐어서" 가설 기각)
  - 두 모델을 내렸다 다시 올린 직후 90초 동안 임베딩 494번 + LLM 33번 → 임베딩 멈춤 0 · **LLM 호출 하나가 6.2초**
  → 어느 모델이든 가끔 몇 초 멈춘다. GPU 메모리 7.2/8.1GB (exaone 5.18GB + bge-m3 0.66GB) 와 Windows 의 GPU 메모리 관리가
  관계있을 수 있다 `[추정]`. 코드로 없앨 대상이 아니라 **견딜 대상**으로 보고 40단계에서 견디게 고쳤다(아래).

## 해결 / 우회

측정 당시(2026-09-27)에는 코드를 안 고치고 두 모델이 올라간 것을 확인한 뒤 다시 쟀다(3차, 임베딩 50/50 성공).
3차 측정용 하네스의 재시도는 **한 번도 발동하지 않았다** — 3차는 있는 그대로의 값이다.

**40단계에서 고쳤다** (`GATES.md` 40단계 · `scripts/check-stage40.mjs`):

| 무엇을 | 쉽게 말하면 | 어디 |
|---|---|---|
| 기동 워밍업 | 코퍼스 준비가 끝나면 임베딩 모델을 먼저 올리고, LLM 워밍업은 그 **뒤에** 건다 | `server.js` `prepareCorpusEmbeddings` · `embed.warmUp` |
| 끊지 않는 예산 | 700ms 가 지나면 **기다림만** 멈추고 요청은 8초까지 살려 둔다 — 적재가 끝까지 가서 다음 질의부터 빠르다 | `embed.embedQuery` |
| 어절 하나 확신은 기다림 | BM25 가 어절 하나로 확신했으면 700ms 가 아니라 8초까지 임베딩을 기다린다. 어절 둘 이상은 그대로 700ms | `pipeline.resolve` 의 `budgetMs` |
| 기록 | 트레이스에 `embed` 자식 런(예산 · 걸린 시간 · 성공 여부 · 사유), LangSmith 에는 `run_type: "embedding"` | `chat.js` · `trace.js` |

임베딩이 **끝내** 없으면(Ollama 가 죽음) 지금처럼 BM25 답을 낸다(S26-G3) — 대신 이제 기록에 남는다.

## 재현 (40단계 **이전** 코드에서)

40단계 뒤에는 워밍업이 모델을 먼저 올리고 700ms 예산이 요청을 안 끊어서 `aborting load` 가 되풀이되지 않는다.

1. Ollama 에서 bge-m3 를 내린다: `ollama stop bge-m3`
2. `node server.js` 를 띄우고 `var/embeddings.json` 이 있는 상태에서 BM25 가 확신하는 질의(예: "청량한 여름 화장품 브랜드")를 연달아 보낸다.
3. Ollama `server.log` 에 `aborting load` 가 반복되고, `/api/chat` 응답의 `payload.hybridError` 에 "제때 답하지 않았다" 가 찍힌다.

## 재발 방지책

- 게이트 `S40-G1`~`G4` 가 워밍업 순서 · 요청이 안 끊기는 것 · 어절 하나 확신의 기다림 · 기록을 가짜 Ollama 로 지킨다.
- **남는 것:** 어절 둘 이상 확신 질의는 여전히 700ms 뒤 BM25 답을 낸다. 대부분 믿을 만하지만 "아침에 빵 굽는 냄새가 나는 카페"
  처럼 어절 둘("냄새가"·"나는")로 틀리게 확신하는 질의가 있다 — GPU 가 멈추면 오답이 나간다(open-work H2 — 대표 결정 2026-09-28: 지금대로, 알려진 한계).
- **남는 것:** 예산을 넘긴 요청이 이제 끊기지 않고 8초까지 산다. GPU 가 멈춘 동안에는 그런 요청이 Ollama 의 슬롯 하나(`-np 1`)에
  줄을 서, 뒤에 온 긴 예산 질의가 그만큼 더 기다릴 수 있다 `[판단]`. 쌓이는 양은 "질의 속도 × 8초" 로 한정된다.
  GPU 멈춤이 8초를 넘으면 어절 하나 확신도 BM25 답을 낸다 — 그때는 트레이스의 `embed` 런이 `ok:false` 로 알려 준다.
- 측정할 때는 `ollama ps` 로 bge-m3 가 올라가 있는지 먼저 본다.
