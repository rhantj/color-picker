# Voyage 임베딩이 분당 3회 안팎에서 429 로 막혔다

## 증상

41단계에서 임베딩을 Voyage(`voyage-4`)로 옮긴 뒤, 기준값을 다시 재려고 질의 60여 건을 하나씩 임베딩하자 429 가 연달아 났다.

```
  429 — 21초 기다림 (해가 넘어간 직후 하늘의 잔광)
  429 — 21초 기다림 (해가 넘어간 직후 하늘의 잔광)
  429 — 21초 기다림 (물 위에 떠 있는 것처럼 가볍고 서늘한)
```

그 전에 서버에서 한 건씩 부를 때(코퍼스 34건 한 요청 + 질의 몇 건)는 문제가 없었다 `[실측 2026-09-30]`.

## 원인 (추정)

Voyage 는 결제 수단을 등록하지 않은 계정에 아주 낮은 한도(분당 3회 안팎)를 건다 `[판단]` — 21초 간격으로는 통과하고 연달아
부르면 막힌 모양이 그와 맞는다. 문서로 확인하지는 않았다.

측정 스크립트 쪽 결함도 하나 있었다: 판정을 대조하려고 서버 경로(`pipeline.resolve`)를 한 번 더 돌리면서 **같은 질의를 두 번**
임베딩했다. 그 두 번째 호출이 429 를 맞고 임베딩 없이 1단계로 떨어져 "따라 쓴 판정이 어긋났다" 로 멈췄다.

## 해결 / 우회

- 측정은 여러 건을 한 요청에 묶고, 대조는 받은 벡터를 그대로 돌려주는 가짜 Voyage 로 하도록 고쳤다 — 그러나 돌리기 전에
  대표님이 방향을 바꿨다.
- **대표 결정(2026-09-30): 임베딩을 로컬 Ollama bge-m3 로 되돌렸다.** LLM 만 Claude API 로 남긴다. 측정 스크립트는 지웠다.
  설계 부록: `docs/superpowers/specs/2026-09-29-claude-voyage-api-design.md`

## 재발 방지책

외부 API 를 들일 때는 **요금제별 호출 한도**를 먼저 확인한다 — 사이트는 검색 한 번마다 임베딩을 한 번 부르므로, 분당 한도가 곧
분당 검색 수다. Claude 쪽도 같은 문제가 날 수 있다(계정 등급별 분당 한도). `src/quota.js` 는 우리 쪽 한도일 뿐이라 이걸 막지 못한다.
