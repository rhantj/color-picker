# OKLCH 왕복에서 파랑이 바뀐다 (#0000FF → #0031E5)

42단계 OKLCH 엔진(`src/oklch.js`)을 처음 쓰고 sRGB 왕복을 쟀을 때.

## 증상

```
#0000FF 0.452 0.313 264.1 #0031E5
roundtrip mismatch 8 / 4096        (#000099 → #00158D, #0000AA → #001A9B …)
```

파랑 계열만 헥스 → OKLCH → 헥스 왕복에서 다른 색이 나왔다.

## 원인

둘이 겹쳤다.

1. **화면 안 판정 여유가 너무 좁았다(1e-4).** 행렬 계산의 반올림으로 파랑의 R 채널이 −1.2e-5(선형)쯤 음수가 되고, 감마 곡선이
   0 근처에서 12.92배로 키워 −1.6e-4 → "화면 밖" 으로 판정됐다. 이 크기는 8비트 반올림에서 사라지는 크기다.
2. **같은 색상각 선이 sRGB 경계를 한 번 나갔다 다시 들어온다.** #0000AA 쪽 색상각에서 C 0.27 은 밖(R −2.3e-4)인데 C 0.313(원래 색)은
   안이다 `[실측]`. 그래서 `maxChroma`(이진 탐색 — 첫 출구를 찾는다)로 원래 안이던 색까지 잘랐다.

## 해결

- 여유를 **8비트 반 단계(0.5/255)** 로 — 반올림 결과가 같은 넘침은 안으로 본다.
- `clampToGamut` 이 **이미 안인 색은 그대로** 돌려준다. 자르는 것은 정말 밖인 색뿐.

결과: 140,608색(5 간격 격자) 왕복 오차 0 `[실측]`.

## 재발 방지

`S42-G8` 이 4096색 격자 왕복을 잰다. 위 둘 중 하나를 되돌리면(변형 검사) 8색이 바뀌어 실패한다.
